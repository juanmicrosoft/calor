## Objections

1. **[BLOCKING] The artifact inventory omits evidence that gates publication** — `artifact-inventory.json:225–241` inventories ratchet **baselines**, but no entry inventories the coverage, mutation, performance, or flake results consumed by `publish-nuget.yml:274–311` and retained at lines 324–335. The packaged SDK consumer also gates publication (`publish-nuget.yml:181–224,339`) without an inventoried evidence output. Furthermore, `release-test-suites` lists six project paths (`artifact-inventory.json:56`), whereas `eng/test-manifest.json` declares thirteen release-critical projects. Consequently, #1424’s “every authoritative artifact” closure requirement cannot cover the actual release gate evidence. — **Fix:** inventory every release-critical producer’s inputs, results and attempts, with classification, ownership, regeneration and durable retention; reconcile the suite paths with the manifest.

2. **[BLOCKING] Benchmark registration can follow decision-bearing inspection** — §5 freezes general equivalence rules and comparability-field **names**, but not the initial denominator, task specifications, input sets, oracle, metric implementations or aggregation method (`v0.24-evidence-contract.md:163–188`; `contract.json:171–182`). #1276’s closure requirement asks for the resulting manifest without requiring its registration before repairs or decision-bearing checks (`contract.json:295`). Unlike #1419’s explicit ordering requirement, this lets #1276 choose its first oracle or exclusions after seeing results and describe that choice as initial registration rather than an amendment. — **Fix:** require a committed benchmark registration before inspection or repair, pinning the complete initial denominator, task/input/failure specifications, oracle and statistical method; retain every subsequently changed or excluded row.

3. **[BLOCKING] Terminal success contradicts the recorded independence limitation** — `contract.json:237` permits failure or a self-adjudicated **non-release record** when independent adjudication is unavailable, while line 254 anticipates `MILESTONE-SUCCEEDED` under reduced independence. The Markdown explicitly admits that the epic’s success requirement is unmet (`v0.24-evidence-contract.md:308–310`). Neither artifact supplies a complete terminal-success predicate resolving this conflict or requiring zero release-critical blockers. This leaves #1408 to decide what “successful” means at adjudication. — **Fix:** retain the chosen maintainer and `BOUNDED` cap, but explicitly define which terminal record is permitted. Under the current epic, retain failure/non-release status until its unmet requirement is satisfied or explicitly amended. Freeze the remaining success predicates, including zero blockers, zero unresolved false proofs and matching adjudication consumption by every public surface.

4. **[MAJOR] N1 is registered but omitted from the registration deliverable** — N1 is explicitly an investigated baseline (`contract.json:54–60`; Markdown §2), yet #1419’s closure evidence still requires a manifest for “baseline B1” only (`contract.json:287`; `v0.24-evidence-contract.md:380`). #1311 then promises execution of every **registered** row, allowing an N1 omission to propagate through closure. — **Fix:** require separate complete B1 and N1 registrations, attempts and dispositions, and state explicitly whether the shared capacity ceilings apply to their combined work.

5. **[MAJOR] Merge acceptance has no machine-readable transition** — The documents say merging accepts capacity and freezes R0, but the committed packet remains `PROPOSED`/`NOT-MET` (`contract.json:7–9,260–262`). `CommittedContractIsNotMarkedMetWhileCapacityIsProposed` permanently asserts those draft values (`EvidenceContractTests.cs:38–44`), while C008 rejects marking R0 met without changing them (`EvidenceContractValidator.cs:123–128`). No acceptance/write-back mechanism is specified. — **Fix:** define the post-merge acceptance record and its durable merge identity, update the packet and hashes, and make the test validate the recorded lifecycle state rather than require perpetual proposal status.

6. **[MAJOR] “Established” proof validation ignores required establishment conditions** — §4 requires a registered producer, independent oracle agreement, matching translator semantics and resolved false-proof findings. `ValidateEvidenceRows` checks none of these (`EvidenceContractValidator.cs:374–401`). Its positive fixture contains only labels, vacuity, commit, timestamp and adjudication (`EvidenceContractTests.cs:553–563`), and cites an artifact with an explicitly open determinism defect (`artifact-inventory.json:32`). `nonVacuityChecked=true` likewise passes without any registered check or retained result (`EvidenceContractTests.cs:175–183`). — **Fix:** require resolvable registration, oracle, semantics-version and disposition evidence; require the non-vacuity check’s identity and result. Add independent negative controls for each missing or failing prerequisite.

7. **[MAJOR] Incomplete benchmark rows pass the advertised fail-closed validator** — `ValidateBenchmark` accepts absent or empty `pairs`, checks inclusion only when `included` exists, and skips comparability validation when `comparedTo` is absent (`EvidenceContractValidator.cs:417–429`). Thus an `UNCLASSIFIED` pair with no `included` field produces no E009. It never checks the frozen `pairRowRequiredFields`; the positive fixture lacks paths, source hashes, task/input/output/failure specifications, equivalence evidence and reviewer (`EvidenceContractTests.cs:577–589`). — **Fix:** enforce the complete pair schema, explicit inclusion, denominator coverage and verified manifest identities. Require complete comparability metadata independently of whether an earlier result exists. Add missing-field and empty-denominator controls.

8. **[MAJOR] C010 does not enforce a version bump, and its negative control conflates failures** — `ValidateAmendments` merely requires `contractVersion` to equal the last log entry (`EvidenceContractValidator.cs:197–224`). A well-formed amendment with version `1.0.0` passes without any bump; repeated or decreasing versions also pass. The inspection flag need only be a `JsonValue`, so a string passes. Meanwhile, the negative control introduces three faults and asserts only a count of three identical C010 codes (`EvidenceContractTests.cs:514–528`), contrary to §12’s promise of one changed fact per control. — **Fix:** enforce strictly increasing versions and a Boolean inspection flag; compare amended scope against the previous frozen revision. Test each rejection separately, including removal of a failing row and a non-incrementing amendment.

9. **[MINOR] The enum control does not prove the claimed unique classification** — §4 and the test comment claim every emitted status is classified exactly once. The test checks only substring presence (`EvidenceContractTests.cs:49–64`). `ContractVerificationStatus.Unproven`, `ObligationStatus.Timeout` and `ImplicationStatus.Unknown` appear under both `Assumed` and `TimeoutOrUnavailable`. Both vacuity variants satisfy the `ProofStatus.Proven` presence check. — **Fix:** describe legacy mappings as lossy and test actual classification predicates using `ProofOutcome`, including assumptions and vacuity, rather than claiming uniqueness from text membership.

10. **[MINOR] The K-induction production-consumer claim is false** — `contract.json:84` says K-induction has no production consumer outside `Verification/Z3/KInduction`. Production compilation invokes `VerificationAnalysisPass` (`src/Calor.Compiler/Program.cs:1044–1051`), whose enabled K-induction path calls `LoopAnalysisRunner` (`Analysis/VerificationAnalysisPass.cs:505–516`). Proven results become synthesized-invariant diagnostics through `LoopInvariantSynthesizer.cs:67–71,386–393`. — **Fix:** document this optional production path and distinguish diagnostic consumption from runtime guard elision.

11. **[MINOR] Hash enforcement does not require the three contracted files** — `PacketHashesMatchSha256Manifest` checks only `files.Count >= 3` and hashes whatever entries the manifest supplies (`EvidenceContractTests.cs:72–81`). Replacing a required packet entry with another correctly hashed file passes. The current hashes match, but the asserted coverage guarantee is unenforced. — **Fix:** require the three named packet paths explicitly and add a negative control that substitutes an unrelated correctly hashed file.
