## 2. Decisions

1. **Syntax is frozen.** `§A{ref|out|in}` on named-target calls, with `§A{out}[name]` for named
   arguments, is the only spelling. No new declaration syntax. A different spelling needs a versioned
   amendment (RO-SYN-1).
2. **Writability is parity with `§ASSIGN`.** A ref/out operand is accepted where a direct assignment to
   it is, and where C# accepts a variable. Operands C# cannot pass by reference get a Calor diagnostic,
   not a leaked C# error (RO-LV-1, RO-LV-2).
3. **No copy may pass as a reference.** No temporary, hoist, write-back or value-type receiver copy,
   ever. Where no native form exists, preserve or refuse (RO-COPY-1…4). This decides F1-REFOUT-08.
4. **C# evaluation order and exception behavior hold exactly** (RO-ORD-1, RO-ORD-2, RO-EXC-1).
5. **`out var` is lowered, not added to the language.** A bounded lowering to a pre-declared mutable
   binding in the same block, never for loop headers or expression-bodied members, and never when the
   name could rebind; everything else is preserved (RO-DECL-1). `out _` is a discard only when no
   symbol named `_` is in scope, because C# would bind to it (RO-DECL-2). This decides F1-REFOUT-02.
6. **Representation stays native.** No Option, tuple or wrapper for out parameters (RO-REP-1).
7. **Nullability consumes 0.22 and adds nothing.** By-reference transfers are not receiving
   boundaries; narrowing is invalidated, including for aliased by-reference parameters; flow
   attributes are inert; generic-type payload transfers are unchecked and the operand keeps its
   declared type; method-generic by-reference parameters are preserved or refused (RO-NULL-1…5).
   This decides F1-REFOUT-07.
8. **Effects charge the caller like an assignment** (RO-EFF-1…4): row A2.
9. **Analysis follows R-OBL's stale-fact rule as implemented**, not a stricter one: entry facts die
   for the whole body, guard facts die when their governed body writes the name, fresh guards after
   the call are usable (RO-ANA-1…6): row A1.
10. **`in` stays a compatibility control**, not a start on ref-readonly or ref returns (RO-LV-3, RO-UNS-1).

## 3. Rules

### syntax

- **RO-SYN-1.** The only call-site spelling is `§A{ref}`, `§A{out}` or `§A{in}` on a named-target call (`§C{target}`), optionally combined with a named argument as `§A{out}[name] operand`. The brace must touch the marker. Any other spelling, including a new declaration form, requires a versioned amendment of this contract and a migration decision.
- **RO-SYN-2.** Any other modifier text, and any modifier on an expression-target call, constructor (`§NEW`) or collection argument list, is refused with Calor0107. A modifier is never dropped silently.
- **RO-SYN-3.** Parameter declarations keep the existing `(T:name:ref|out|in)` form. The C# emitter writes the modifier on the same argument, and C# to Calor to C# round trips keep each argument's modifier and name.

### call-shape

- **RO-CALL-1.** Statement calls and expression calls, static and instance calls, follow the same rules. An instance receiver is evaluated before the arguments.
- **RO-CALL-2.** Named and reordered arguments are evaluated in source order. The emitted call keeps source order and C# argument names; it is never reordered into parameter order.
- **RO-CALL-3.** Modifiers take part in overload selection, as in C#. A call with an explicit modifier selects only a parameter of the same kind (ref with ref, out with out, in with in) and never falls back to a by-value overload; with no matching candidate it is refused (Calor0208 at the measured commit). A call without a modifier selects a by-value overload when one applies, and is refused when the only applicable parameter is by-reference.
- **RO-CALL-4.** The return value of a by-reference call can be used wherever an expression can. The callee's writes are visible to every read that C# evaluates after the call, including later operands of the same expression.

### lvalue

- **RO-LV-1.** A ref or out operand is accepted exactly where a direct `§ASSIGN` to the same operand is accepted, and C# also accepts it as a variable: a mutable or immutable local binding, a by-value, ref or out parameter, an instance or static field that is not readonly (bare, `this.`, qualified or through a reference-type receiver), a readonly field of the class being constructed inside its own constructor, an array element of any rank, and a field path of value-type fields rooted at one of these. Parity with `§ASSIGN` also covers immutable bindings and loop variables, which `§ASSIGN` accepts at the measured commit; if the language later rejects those assignments, by-reference operands follow.
- **RO-LV-2.** Calor refuses, before C# generation, every operand C# cannot pass by reference: a literal, a computed expression, a call result, a property, an indexer (any `§IDX` whose receiver is not an array), a readonly field outside a constructor, an `in` parameter, and `this`. The refusal is a Calor semantic diagnostic (symbol InvalidByReferenceOperand, allocated by #943); a generated-C# failure (Calor1002) does not count as a refusal.
- **RO-LV-3.** `§A{in}` takes the same operands as `ref`, plus `in` parameters and readonly fields. An `in` parameter needs `§A{in}` at the call site; a call without it is refused (Calor0208 today). C# calls that pass an rvalue to an `in` parameter, or omit `in`, are preserved or refused, not converted natively.

### copy

- **RO-COPY-1.** A by-reference argument denotes the caller's storage. The generated C# passes that same storage location. No temporary, hoist or copy of the operand, or of any value-type step of its path, is allowed (F1-REFOUT-08).
- **RO-COPY-2.** A receiver may be hoisted into a local only when its static type is a reference type (class, interface, array, delegate, string) and the hoist evaluates it exactly once, in the original order. A value type, Nullable<T>, a type parameter not constrained to `class`, or an unknown type is never hoisted.
- **RO-COPY-3.** Copy-in/copy-out emulation (pass a temporary, write it back after the call) is forbidden. It differs from C# under aliasing and exceptions.
- **RO-COPY-4.** When no native operand form exists, the converter preserves the enclosing member or statement as C# interop, or refuses. Such cases count as preserved or rejected in every report, never as native.

### aliasing

- **RO-ALIAS-1.** The same storage passed in two by-reference positions is one location; the callee's write order decides the result. Storage the callee can also reach directly (a static field) aliases the by-reference parameter.
- **RO-ALIAS-2.** A by-value argument that names the same storage is read at its own argument position, before the call.

### evaluation-order

- **RO-ORD-1.** Receiver first, then arguments left to right in source order. For an element operand, the array reference and indices are evaluated, and null and bounds checks happen, at the operand's position: before later arguments and before the callee runs. A `ref` or `out` element of an array of reference type also performs the array-covariance check there (ArrayTypeMismatchException); an `in` element takes a read-only reference and performs no covariance check, so it must not be emitted or emulated as `ref`.
- **RO-ORD-2.** A by-reference call in a conditional position stays conditional and is evaluated as often as in C#. It is never hoisted out of `&&`, `||`, `?:`, `??`, or a loop condition.

### definite-assignment

- **RO-DA-1.** A ref operand must be initialized before the call. An out operand need not be. After normal completion the out operand holds the callee's value.

### exception

- **RO-EXC-1.** Writes the callee makes before throwing stay in the caller's storage, for both ref and out. After an exceptional exit the caller may assume neither the old value nor that the out operand was assigned.

### declaration

- **RO-DECL-1.** Native Calor gets no inline out declaration. The converter may lower C# `out var x` or `out T x` to a mutable binding of the declared type, placed immediately before the innermost enclosing statement in the same block, and pass `§A{out} x`, only when all of these hold: the enclosing statement is an expression statement, local declaration, return or `if` statement directly in a block (never a `while`, `do`, `for` or `foreach` header, a `using` or `lock` header, a `when` filter, a field, property or constructor initializer, a query, a lambda or an expression-bodied member); the type is known and expressible; and the name collides with no name visible at the placement point or anywhere in the C# variable's scope, including fields, properties, members, parameters, outer locals and converter-generated names. In every other case the statement or member is preserved as C#. FeatureSupport's `out-var` entry must match this rule.
- **RO-DECL-2.** `§A{out} _` is a discard and emits `out _`, in module functions and class methods alike. Because C# binds `_` to any variable of that name in scope, `§A{out} _` is refused (InvalidByReferenceOperand) when a parameter, local, field or other symbol named `_` is in scope. The converter never emits `§A{out} _` for a C# `_` that binds to a declared variable. `§A{ref} _` and `§A{in} _` are refused.

### representation

- **RO-REP-1.** By-reference operands keep their native types. No Option, Result, tuple, multi-return, StrongBox or wrapper-class representation is introduced, and no out parameter is turned into a return value.

### nullability

- **RO-NULL-1.** This contract consumes docs/plans/v0.22-nullability-enforcement-scoping.md at d0dc0f8bf3ea400b1d7d16780a98d9ff3341abc7: `?str` is a nullable reference, not Option<T>; new ref/out syntax and flow-dependent interop attributes are outside 0.22. By-reference transfers are not 0.22 receiving boundaries, and this contract activates no Calor0272/0273/0274 diagnostic for them.
- **RO-NULL-2.** After a ref or out call, every flow narrowing of the operand is invalidated. Aliasing reaches narrowing too: in a callable whose by-reference (ref, out or in) parameters may alias each other or heap storage, which is the same condition as RO-ANA-1's alias exception (two or more such parameters with one written, directly or through a ref/out argument; or one or more with any call or heap write in the body), a narrowing of any by-reference parameter does not survive that write, call or heap write. The operand keeps its declared type; no fact is derived from the call's return value.
- **RO-NULL-3.** Flow-dependent attributes (NotNullWhen, MaybeNullWhen, NotNullIfNotNull, MaybeNull, NotNull, AllowNull, DisallowNull, MemberNotNull, MemberNotNullWhen, DoesNotReturn, DoesNotReturnIf) are inert metadata and are never interpreted. Code that type-checks only through such an attribute is preserved or refused, not converted natively. The converter never inserts `!`, defaults or throws.
- **RO-NULL-4.** A by-reference parameter typed by a type parameter of a generic type, substituted from the receiver (Dictionary<TKey,TValue>.TryGetValue), may be called natively. 0.22 excludes arbitrary generic payloads, so the transfer is not checked: no receiving-boundary diagnostic is activated, the operand keeps its declared type (a declared `str` stays `str`), and nothing claims it is non-null; a miss writes null into it at run time (D1-CS-16, D1-NULL-08). A by-reference parameter typed by a method type parameter (TryCast<T>(object, out T)) is preserved or refused (F1-REFOUT-07).
- **RO-NULL-5.** For natively declared parameters, a ref or out operand's declared type must equal the parameter type, including the scalar nullable annotation. A mismatch in either direction is refused (Calor0208 at the measured commit).

### effects

- **RO-EFF-1.** A ref or out argument charges the caller the effect that a direct `§ASSIGN` to the same operand charges: `mut` for an array element, a field through a receiver, or a dotted path; nothing for a local or parameter. `in` charges no write. Sub-expressions of the operand charge their read effects.
- **RO-EFF-2.** Assigning a by-reference parameter inside the callee charges nothing extra there; RO-EFF-1 charges the caller, who chose the storage.
- **RO-EFF-3.** The write charge depends on the call-site modifier and operand, not on callee resolution. An unresolved or BCL callee keeps the existing unknown-call handling (Calor0410 or Calor0419) and is never treated as pure because it takes by-reference arguments.
- **RO-EFF-4.** A bare-name field operand (`§A{ref} n`) charges what `§ASSIGN n` charges at the measured commit, which is nothing. Changing bare-field charging is outside this contract and must change both forms together.

### analysis

- **RO-ANA-1.** Consistent with R-OBL (#1496, ba2e31cb), whose rule this freezes rather than tightens: a name passed as ref or out anywhere in a body is a written name, so every entry fact (precondition or parameter refinement) that reads it is stale for the whole body. A guard fact is stale when the body the guard governs writes a name it reads (including through a ref/out argument); a guard evaluated after the call is otherwise fresh and may be used. Exception: in a callable whose by-reference parameters may alias (two or more of them with one written, or one or more with any call or heap write in the body), every by-reference parameter is alias-written and no entry or guard fact that reads one is usable anywhere in the body, fresh or not. A fact that reads an element, field or dotted path is stale once the body contains any call. This holds for unresolved callees.
- **RO-ANA-2.** An `in` argument does not make its operand a written name. Aliasing does: when a callable has two or more by-reference parameters and writes one, or has a by-reference parameter and may change the heap, all of them are written names.
- **RO-ANA-3.** An obligation that reads a stale name is reported Unsupported (Calor1124) with its runtime check kept, or discharged only from facts that are not stale. It is never reported as a failed proof (Calor1121/Calor1140) from that state. Guards are elided only for discharged obligations.
- **RO-ANA-4.** Caches must distinguish modifiers: a result recorded for a body passing `§A y` is never reused for the same body passing `§A{ref} y` or `§A{out} y`. At the measured commit the obligation solver has no cache; the witness shares one verification cache directory across both compilations so that any cache added later is covered.
- **RO-ANA-5.** Bug-pattern checks (division by zero, null dereference, index bounds, overflow) must not use the pre-call value or range of a ref or out operand after the call. If a check cannot model the call, it reports nothing as safe because of it.
- **RO-ANA-6.** A body containing preserved C# (`§CS`, `§CSHARP`, raw blocks) has no facts (R-OBL opacity). By-reference calls inside preserved C# are covered by that rule, not modelled.

### unsupported

- **RO-UNS-1.** Outside this slice, preserved as counted C# interop or refused, never native: ref locals and ref returns, conditional ref operands (`ref (c ? ref a : ref b)`), ref readonly parameters and returns, `scoped`, ref structs and their indexers (Span<T>), ref fields, `this ref` and `this in` extension methods (an implicit receiver never becomes an explicit native by-reference argument), by-reference arguments to constructors, constructor initializers and indexers (`obj[in key]`), delegates and function pointers with by-reference parameters, by-reference arguments through `dynamic`, pointers and unsafe code, and method-generic by-reference parameters. A value conditional (`§?`) is not a conditional ref and cannot stand for one.

### migration

- **RO-MIG-1.** Preserved shapes are counted and reported as interop. FeatureSupport's `out-var` (claims Full) and `ref-parameter`/`out-parameter` (recommend tuples) entries must be corrected by #943 to describe this contract.
- **RO-MIG-2.** Regression controls F1-REFOUT-01, 03, 05 and 06 stay native-match on all four R0 surfaces. Calls without modifiers are unchanged.

|---|---|---|---|
| Local binding, mutable or immutable | accept (parity) | accept | D1-SYN-01, D1-LV-06, D1-LV-07 |
| Loop variable | accept (parity) | accept | D1-LV-08 |
| By-value, ref or out parameter | accept | accept | D1-ANA-01, D1-ANA-04 |
| `in` parameter | refuse: InvalidByReferenceOperand | accept | D1-LV-04 |
| Field, bare / `this.` / static / qualified | accept (parity) | accept | D1-LV-09, D1-CS-06 |
| Field through a reference-type receiver | accept; receiver evaluated once | accept | D1-LV-12, D1-CS-04 |
| Readonly field outside a constructor | refuse | accept | D1-LV-05 |
| Readonly field in its own class's constructor | accept (parity) | accept | D1-LV-13 |
| Array element, any rank or jagged | accept; `ref`/`out` check covariance at the operand | accept; no covariance check | D1-LV-10, D1-LV-11, D1-CS-01, D1-CS-09, D1-CS-27 |
| Value-type field path (`o.In.X`, `pts[0].X`, `grid[1,1].X`) | accept as one path; never via a copy | accept | D1-CS-01, D1-CS-02, D1-CS-03, D1-R0-08 |
| Property, indexer, `§IDX` on a non-array | refuse | refuse | D1-LV-03, D1-CS-19 |

Parity has a cost: the measured compiler accepts `§ASSIGN` to an immutable `§B{v}` binding and to a
`§L` loop variable, so by-reference writes to them are accepted too. Immutability enforcement is
outside this contract; if the language starts rejecting those assignments, by-reference operands
follow without an amendment.

## 5. Success and refusal examples

These use the `fn` prelude in `contract.json` (`Bump (i32:x:ref)`, `SetOut (i32:x:out)`,
`Twice (i32:x:in)`).

```
§B{~v:i32} 1
§C{Bump} §A{ref} v §/C          // accepted: Bump(ref v)           D1-SYN-01
§C{SetOut} §A{out}[x] v §/C     // accepted: SetOut(x: out v)      D1-SYN-02
§R §C{Twice} §A{in} v §/C       // accepted: Twice(in v)           D1-SYN-03
§C{Bump} §A v §/C               // refused: Calor0208              D1-CALL-02
§C{Bump} §A{byref} v §/C        // refused: Calor0107              D1-SYN-04
§C{Bump} §A{ref} (+ v 1) §/C    // must be refused before codegen  D1-LV-02
```

C# witnesses (§11) run `Probe.Run()` on the original and on mutants. For example, D1-CS-05 prints
`1|15`: an `out` written before a throw stays written. Its copy-in/copy-out mutant prints `5|15`.
D1-CS-10 prints `False|0`; hoisting `TryGetValue` out of `&&` throws `ArgumentNullException`.

## 6. Nullability (consumes #1379)

By-reference arguments are outside the three 0.22 Stage A receiving boundaries (binding initializers,
native returns, resolved method inputs), and the #1383 plan lists by-reference exclusions.
This contract activates no Calor0272/0273/0274 for them. What it does fix:

- After the call, narrowing of the operand is gone. D1-NULL-05 holds today: the binder's
  `InvalidateMutatingCallArguments` makes `§B{str:u} s` report Calor0272 after `Set(ref s)`, while
  D1-NULL-06 (no call) is accepted.
- Aliasing reaches narrowing too. In `Two(?str:a:ref, ?str:b:ref)`, `Two(ref s, ref s)` makes `a`
  and `b` one location, so writing `b` (directly or through `Clear(ref b)`) must invalidate a
  narrowing of `a`. At the measured commit it does not (D1-NULL-07, D1-NULL-09 violate). A single
  by-reference parameter can alias heap storage: `Check(ref K.slot)` followed by a call that nulls
  `slot` must invalidate a narrowing of the parameter (D1-NULL-10 violates). The condition is the same
  as RO-ANA-1's alias exception.
- Natively declared annotations must match exactly for ref and out (D1-NULL-01…04 hold today, through
  Calor0208).
- BCL generic-type payloads (`TryGetValue(…, out TValue)`) convert natively. 0.22 excludes arbitrary
  generic payloads, so the transfer is unchecked: the operand keeps its declared type, no diagnostic
  is activated, and nothing claims it is non-null. A miss writes null into a declared `str`
  (D1-NULL-08 accepts this; D1-CS-16 shows the null at run time). This is 0.22's stated limit that
  null can inhabit `str`, not a guarantee. `[MaybeNullWhen(false)]` is not read.
- `NotNullWhen` and the other flow attributes carry no meaning. Code that needs them to type-check is
  preserved or refused (D1-CS-17, D1-R0-07). The converter never inserts `!`, defaults or throws.

## 7. Effects (row A2)

The caller pays for the write, exactly as for `§ASSIGN` to the same operand. At the measured commit
this fails: `§C{Bp} §A{ref} §IDX{arr} 1 §/C` and its `out` form compile under `§E{alloc}`
(D1-EFF-01, D1-EFF-02), while `§ASSIGN §IDX{arr} 1 7` reports Calor0410 (D1-EFF-03). A heap write
through a by-reference argument is therefore *laundered* (performed without being charged). Locals
charge nothing (D1-EFF-04). A bare-name field charges nothing in either form today (D1-LV-09,
D1-EFF-05); RO-EFF-4 freezes that parity instead of changing it here. Unresolved callees keep their
existing unknown-call handling (RO-EFF-3).

## 8. Analysis boundaries (row A1)

R-OBL already implements the stale-fact rule: `FactCollector.AddByReferenceArguments` adds every
`ref`/`out` argument name to the body's assigned names, any call makes heap facts stale, and two or
more by-reference parameters alias when one is written. This contract freezes that behavior for the
by-reference surface and registers witnesses:

| Case | Shape | Observed at the measured commit |
|---|---|---|
| D1-ANA-01 | `§Q (> x 0)`, `Bump(ref x)`, `§PROOF (> x 0)` | Unsupported; guard kept |
| D1-ANA-02 | same with `SetNeg(out x)` (writes −5) | Unsupported; a discharge would be a false proof |
| D1-ANA-03 | `Twice(in x)` | Discharged: `in` does not kill the fact (RO-ANA-2) |
| D1-ANA-04 | `(a:ref, b:ref)`, writes `b` | Unsupported: aliasing |
| D1-ANA-05 | warm the cache with `Set(§A y)` (by value, discharged), then `Set(§A{out} y)` in the same cache directory | Unsupported |
| D1-ANA-08 | `Bump(ref x)`, then a fresh guard `(> x 0)` around `§PROOF (> x 0)` | Discharged: a guard after the call is fresh |
| D1-ANA-09 | the same with `x` a `ref` parameter | Unsupported: R-OBL's alias exception makes even a fresh guard unusable |
| D1-ANA-06 | division by zero after a zeroing `ref` call | spec only: the checker reports nothing with or without the call, so no witness discriminates yet |
| D1-ANA-07 | by-reference call inside preserved `§CS{}` | spec only: covered by R-OBL opacity |

The case tests also require Calor1124 and the retained runtime guard for every Unsupported proof.
The obligation solver has no cache at the measured commit, so D1-ANA-05 cannot observe a cache hit;
it shares one verification cache directory across both compilations so that a cache added later is
covered. #943 must add an executable witness for D1-ANA-06 before READY. An analysis that cannot model a by-reference call must refuse or demote; it never
establishes safety by omitting the call.

## 9. Unsupported shapes

RO-UNS-1 lists them. Each registered one (D1-CS-18…22, D1-R0-07, D1-SYN-05) expects
`preserved-or-rejected`; the C# witness pins the original output so a preservation can be checked
for behavior. None may be counted as native, and rescue cannot satisfy a native row (R0 §8).

## 13. Findings at the measured commit

- **Calor1002 leakage (5 cases).** Literal, computed, property, `in`-parameter and readonly-field
  operands are refused only by the generated C# compile (D1-LV-01…05).
- **Module functions differ from class methods.** An array-element operand compiles in a class method
  (D1-LV-10) but is Calor0208 in a module function (D1-LV-11). `§A{out} _` compiles in a class method
  (D1-DECL-01) but `_` is undefined in a module function (D1-DECL-02). A receiver field `k.n` is
  Calor0208 by reference but assignable directly (D1-LV-12).
- **Effect laundering (A2).** D1-EFF-01 and D1-EFF-02.
- **Discard collision.** `§A{out} _` with a parameter named `_` compiles to `out _`, which C# binds to
  the parameter (D1-DECL-04).
- **Alias-blind narrowing.** D1-NULL-07, D1-NULL-09 and D1-NULL-10.
- **FeatureSupport overclaims.** `out-var` says `Full` with pre-declaration, but F1-REFOUT-02 keeps
  `out var` as inline `§CS{}`; `ref-parameter`/`out-parameter` recommend tuples or `Result`, which
  RO-REP-1 rules out.
- **Already holding (controls).** Syntax and modifier mismatches (D1-SYN-*, D1-CALL-*), annotation
  identity (D1-NULL-01…04), narrowing invalidation (D1-NULL-05), and every A1 proof case.
