`create-release` does not proceed to the tag until `ppe1-analysis.json` exists and the verdict
is in the release notes (A-1.11, "Who runs it, and when"). An epoch directory that already
holds results is refused — a re-run is a new epoch id. `--null-agent` forces the epoch id to
`e1-rows-parity-001-null` (a plumbing check never lands in the registered directory), and the
check (or any epoch id other than `e1-rows-parity-001`) is analysed with `--dry-run`, labelled,
and cannot be recorded as leg B; `ppe1-analyze.py` additionally refuses, as an invalid harness
with the reason named, any non-dry-run epoch whose `pins.mode` is not `live` or that holds a
