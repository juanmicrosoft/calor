## What is recomputed vs what is recorded (so the pin is not overread)

**Recomputed, every CI run, by the test:**

- Leg A, all ten cells: each frozen diff is re-applied textually to a temp copy of the frozen
  fixture (every anchor asserted to occur exactly once, as A-1.11 registered; `L5-A2` is the
  committed `after/A2-broadening.calr`, blob `f975f282`, used as-is), compiled with the pinned
  invocation, and the codes/declarations compared to the ledger. Detection = the registered
  code at the registered declaration; `L6-MAP`/`L6-MATCH` must name `'cw'`; `L6-MID` must name
  the instantiation (the message's `Effect row:` continuation line — `RunTwice's row
  instantiates to e at a call site in 'Handle'` — is captured, which is why the probe parses
  continuation lines); `L7` requires `Calor0425` specifically, rising above the unmutated
  fixture's count at that line. Drift is bounded to {`Calor0424`, `Calor0425`, `Calor0404`,
  `Calor0405`} and published by name; `Calor0418`/`0419`/`0411` are never detection.
- The negative control, per fixture, against A-1.11.1's **post-E4** multisets — A2 = 1×
  `Calor0410` (23,9) + 2× `Calor0411` (26,24)(28,19), exit 1; the four A3 fixtures exit 0 with
  zero diagnostics — with severity and exit code in the pin, the bar on any further
  effect-family diagnostic, the barred set, and the one pre-allowed migration
  (`Calor0410`-'unknown'/`Calor0411` → `Calor0425`/`Calor0419` at the same declaration) as the
  only tolerated substitution.
- Route (a): any control or mutant compile drawing a lexer/parser/semantic-class code
  (`Calor0001`–`Calor0299`, i.e. not reaching the effect pass).
- Route (b): `dA.total + dB.aggregate.total` from `higher-order-demand-ledger.json` against the
  frozen floor of 25 (reads **2 + 3121 = 3123** at this commit; A-1.11 quoted 3 + 3121 at
  registration — the D-A leg moved by one when E4 retired a `Calor0418`; still two orders of
  magnitude above the floor, and the floor is asserted to be 25).
- The ramp denominator: 10 (rank-1 was NOT cut; the spike's ramp verdict is VALIDATED).
- Mechanical evidence beside route (d): `Calor0424` present in `src/Calor.Compiler`, the L7
  cells observing `Calor0425` (E4's code), the L5 cells observing `Calor0421` with row text.

**Recorded, read from files, never re-run by a test:**

- Leg B: `epochs/e1-rows-parity-001/ppe1-analysis.json` when it exists (its `epoch` must be
  `e1-rows-parity-001` and it must not be a dry run); otherwise status `not-run` with every
  figure `null`. Numbers are never invented by the test.
- Route (d)'s `fires` and the own-goal flag (both `false`; a human judgement the row assigns
  to the adjudicator, recorded beside the mechanical evidence above).

**Derived, not written:** the four-valued verdict, from the frozen map in its precedence
NOT-ADJUDICATED > MISS > UNDERPOWERED > HIT. While leg B is `not-run` the verdict MUST be
`NOT-ADJUDICATED` with reason `leg B epoch e1-rows-parity-001 not yet run; adjudication at the
0.15.0 release commit`; once leg B is recorded the verdict is exactly what the rules compute
(routes → not-adjudicated, or MISS under the own-goal flag; leg A < 10/10, control not clean or
leg B fails → MISS; point > 1.35 with the bound not firing or CV > 0.66 → UNDERPOWERED; else
HIT). `PpE1Ledger_VerdictFollowsLegBState` re-derives it from the file alone.

## How the 0.15.0 release PR's author runs leg B (the exact commands)

```bash
# 1. Two PRODUCT checkouts, never the harness checkout, each built Release:
git worktree add /tmp/ppe1-control v0.14.3
git worktree add /tmp/ppe1-treatment <the 0.15.0 release commit>
for r in /tmp/ppe1-control /tmp/ppe1-treatment; do
  dotnet build $r/src/Calor.Compiler -c Release
  dotnet build $r/src/Calor.Tasks    -c Release
  dotnet build $r/src/Calor.Runtime  -c Release
done

# 2. Zero-spend plumbing check (no confirmation needed):
CLAUDE_MODEL=<pinned model> bench/phase0-agent-native/run-ppe1-epoch.sh \
  --arm-a-repo-root /tmp/ppe1-control --arm-b-repo-root /tmp/ppe1-treatment \
  --epoch e1-rows-parity-001-null --null-agent

# 3. The paid 40-run epoch (prints the plan, refuses without the flag):
CLAUDE_MODEL=<pinned model> bench/phase0-agent-native/run-ppe1-epoch.sh \
  --arm-a-repo-root /tmp/ppe1-control --arm-b-repo-root /tmp/ppe1-treatment \
  --confirm-paid-epoch
#    -> epochs/e1-rows-parity-001/{pins.json (both roots + both Calor.Tasks hashes, ppE1 block),
#       N1-*/<arm>/run-N/{result.json,agent.json,...}, ppe1-analysis.json}

# 4. Record leg B and derive the verdict (the ledger's measuredCommit becomes the release commit):
CALOR_REGENERATE_PPE1_LEDGER=1 dotnet test tests/Calor.Compiler.Tests --filter EffectRowsProbeLedger
dotnet test tests/Calor.Compiler.Tests --filter EffectRowsProbeLedger    # must be green as committed
# 5. Publish `verdict` + `reason` from effect-rows-probe-ledger.json in the release notes, whatever they say.
```

`create-release` does not proceed to the tag until `ppe1-analysis.json` exists and the verdict
is in the release notes (A-1.11, "Who runs it, and when"). An epoch directory that already
holds results is refused — a re-run is a new epoch id.
