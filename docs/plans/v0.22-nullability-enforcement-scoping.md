# v0.22 nullability enforcement: N0 scope and production baseline

**Date:** 2026-09-11. **Checkpoint:** #1379 under #1082.
**Status:** measured scoping checkpoint, not enforcement activation or release
approval. Acceptance, independent reviews and delegated adjudication belong in
the linked #1379 PR. No behavioral repair is part of this change.

## 1. Governing contract

Supported `?str`, `?string` and `?Foo` denote **nullable references, not runtime
`Option<T>`**. `Some`/`None` do not implicitly initialize a nullable reference.
The current implementation does not consistently implement that distinction;
#1397 owns the parser/TypeChecker/binder/emitter and diagnostic-ownership repair.

Existing explicit coalescing with a non-null fallback, coalescing with `throw`,
and typed-pattern consumption are bounded migration choices. #1398 repairs
their static transfers. It does not add an unwrap operation or general flow
narrowing. `default(string)` is null, not a safe fallback. C# conversion must
preserve behavior: it must not insert defaults, throws or mass nullable
annotations to make a candidate pass.

**Stage A is scalar STRING receiving shapes only**, at explicit binding
initialization, native returns and resolved method input arguments. It is not
restricted to BCL-return expressions. #1385 must route by the receiving shape
and boundary, not simply allowlist `Calor0272`/`0273`/`0274`: those codes also
cover nominal, array-element and generic-payload cases.

**Stage B is conditional.** #1400 must first measure and adjudicate nominal
`Oblivious` policy. Conservative treatment of unknown references is a candidate,
not an adopted default. #1402 can activate the remaining bounded shapes only
after that decision and its dependencies. Non-null literal and `new` expression
guarantees survive nullable-disabled C#. A Stage A-only release or Stage B
deferral requires an explicit scope decision; this checkpoint makes neither.

General assignment/rebinding, member writes, constructor **inputs**, arbitrary
generic payloads, flow-dependent interop attributes, new `ref`/`out` syntax,
whole-program guarantees and proof-demotion lifts are excluded. Constructor
**results** remain known non-null.

## 4. Runtime controls and retained soundness boundary

Generated C# was compiled with the existing `GeneratedCSharpCompiler`
references and executed, rather than treating emission as runtime evidence:

| Case | Null input | Present input |
|---|---|---|
| Explicit `"fallback"` coalesce | returns `"fallback"` | returns `"present"` |
| Coalesce with `ArgumentNullException` throw | throws that exact exception | returns `"present"` |
| Converted `is string text` pattern | returns `"fallback"` | returns `"present"` |
| Converted `default(string)` coalesce | returns **null** | returns `"present"` |

The typed-pattern conversion is native `is` plus guarded cast/binding, not an
opaque C# body. Its guard explains runtime safety; it does not justify marking
all casts non-null. The default conversion emits a `null` reference and also
has a raw undefined-variable0200; it is deliberately **not** an isolated
nullability witness or safe migration.

Nullable-disabled C# literal and `new Item()` controls convert and execute to
non-null values. This does not classify every nullable-disabled method result
as safe. The direct constructor node is NotAnnotated even when local transfer
later loses that annotation.

The following actual source compiles without parser, TypeChecker, binder, API
or LSP diagnostics and returns **null** when the key is absent:

```calor
§M{m1:N0}
  §F{f1:Probe:pub} () -> str
    §E{env}
    §B{~x:str} "safe"
    §ASSIGN x §C{System.Environment.GetEnvironmentVariable} §A "CALOR_N0_UNSET" §/C
    §R x
```

The statement tag is `§ASSIGN`; `§SET` is an accessor tag. General mutation is
outside this milestone's receiving boundaries. Therefore even completed
Stage A/B must not claim "null can never inhabit str."

D3/D12/D14 demotions and runtime guards in `Verification/Z3/Z3Verifier.cs`
remain load-bearing and unchanged. The existing
`W1Slice1SoundnessTests`, `ArrayLengthSoundnessTests` and
`MethodElisionCursorTests` passed **92/92**. These include string/reference/array
demotion and numeric positive controls; they do not authorize a demotion lift.
#875 remains separate and open.

## 5. Every BoundType kind has a disposition

The complete inventory is the six concrete kinds in
`Binding/BoundTypes/BoundType.cs`. A kind name alone is not a safety
classification. In particular, zero `UnresolvedBoundType` nodes does not mean
zero unknown references: the measured unqualified call is nominal OBJECT.

| Kind | Current checker treatment | Staged disposition |
|---|---|---|
| `PrimitiveBoundType` | No target case; source annotation helper falls through to NotAnnotated | Value primitives are not nullable-reference coverage; unexpected primitive reference encoding must remain visible, not safe by default |
| `NominalBoundType` | STRING checks Annotated/Oblivious; user-reference branch uses short-name matching and only Annotated. Known value names are excluded heuristically | A: scalar STRING only. B: correctly resolved nominal references after identity/annotation repairs and #1400 decision. Value/enum/struct or unresolved nominal identities require explicit classification |
| `ArrayBoundType` | Checks matching STRING **element** annotation, not container nullability | B only; container, rank and element identity must be explicit. Other elements/containers are not silently covered |
| `GenericInstantiationBoundType` | Checks matching definition and position0 STRING payload; Binder supplies whitelist | B only: current whitelist is Option, List, IList, IEnumerable, IReadOnlyList, ICollection, IReadOnlyCollection. Not arbitrary/nested payloads or container non-nullness |
| `FunctionBoundType` | No target case; source helper falls through to NotAnnotated | Unsupported function-reference receiving shape; do not count as safe reference coverage or infer flow-sensitive delegate guarantees |
| `UnresolvedBoundType` | No target case; source helper falls through to NotAnnotated | Unresolved, not safe; record reason and resolution gap, with explicit later disposition |

The current helper's NotAnnotated fallback for kinds without an annotation
property is a **baseline defect/limitation, not the proposed unknown policy**.
Nominal types carry declaration/Roslyn identity only when actually available;
`VariableSymbol` currently has `TypeName`, not a structured `Type` property.
The nullable-element source probes demonstrate representation gaps; S6/S7
directly constructed predicate tests remain useful unit coverage but are not
substitutes for end-to-end parser/binder/API cases.

## 9. Review, adjudication and acceptance protocol

Two **separately initiated** reviewer contexts must independently read the
governing issues, final diff and evidence: one compiler-integration lens and
one adversarial-compatibility lens. Neither is the implementation context.
Exact prompts, requested/actual available model identity, agent IDs, reviewed
head SHA, evidence links, findings and dispositions are recorded in the PR.
Material fixes require re-review; no author self-approval substitutes for either
review. Final-head CI must pass without bypassing gates.

These are AI reviews sharing repository evidence and potentially correlated
training/tool failure modes. Different contexts or models do not establish
statistical independence or human review. Parent-delegated checkpoint
adjudication must be recorded explicitly, with its scope and remaining
limitations; this document does not fabricate a maintainer's approval.

The checkpoint can record pre-existing/infrastructure failures; it cannot
turn them into safe coverage. Stage A/B acceptance later requires explained
candidate deltas, executable migrations, no rejected supported safe controls,
and the appropriate additional decision/capacity gates. N0 merges no
nullability policy changes, proof-elision changes, version bump, release,
paid model collection or PP-W restart.
