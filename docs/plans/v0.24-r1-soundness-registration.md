## 0. What this is and is not

This registers the search for **false-established proofs** in the released verifier: a claimed
property that is false on a concrete input while the verifier reports it unconditionally
established (contract §4: `Proven` non-vacuous, or `Discharged` with a passed non-vacuity check).
It freezes the denominator, oracle, case set, budget, and rules **before** any decision-bearing
result exists. It does not run the sweep, change the verifier, or authorize a release. Zero findings
will mean *no counterexample found within this matrix and budget*, not whole-compiler soundness.

## 3. Channels and observation

Each case runs in-process against the baseline's own `calor.dll` in a collectible
`AssemblyLoadContext` (`Program.Compile` bound by name). There is **no fallback channel**: the CLI
envelope does not carry every outcome and both emissions, so a baseline that cannot be loaded
in-process has an invalid run.

- **CH-CONTRACT** — `VerifyContracts = true`, `EnableTypeChecking = true` with `CALOR_NO_TYPE_CHECK`
  unset (recorded; a change invalidates the run), cache off, solver timeout 5,000 ms, compiled with
  elision on (the default user path) and off. Outcomes from `ContractVerificationResult.EffectiveOutcome`.
- **CH-OBLIGATION** — additionally `VerifyRefinements = true`; outcomes from `options.ObligationResults`,
  matched by the template's `obligationKind` (the path behind `calor_refine` and the public API).
- **CH-IMPLICATION** — the always-on inheritance checker. Each IMPL template carries contracts in one
  direction only; `Calor0815` text identifies the direction (`Proven`), LSP-violation errors are
  `Failed`, `Calor0816` is `TimeoutOrUnavailable`, and no diagnostic (heuristic fallback) is
  `Unsupported`. Inherited-guard cases produce no token and are judged on the guard alone.
- **CH-CACHE** — prime, warm compile, and cold compile in fresh directories. The semantics-version row
  tampers a primed `Failed` entry to `proven` (variant A, a tamper-reachability control that must
  be `Proven` and is never a finding) and to `proven` plus a stale version (variant B, adjudicated:
  it must equal the cold result). The literal-width row primes `LONG:1` and finalizes `INT:1`.
- **CH-CLI-CROSSCHECK** — on control cases, the CLI (`--verify --verbose --format json`) must not
  contradict the in-process status; a contradiction invalidates the run.

Every claim-bearing outcome the compiler produced is adjudicated even if compilation then fails
(Calor1002 and Calor0326 arise after verification); a rejection counts as a refusal only when no
claim-bearing outcome exists. Every claim-bearing raw status maps to exactly one contract §4 token from `ProofOutcome`, never from
a legacy enum; an unmapped status is a harness error. Each case has exactly one claim (`claimSite`,
plus `obligationKind` for obligations). Guards are observed in both emissions: absent with elision
only for `Proven` (non-vacuous) or `Discharged` with a guard-free policy action; always present with
elision off.

## 4. Independent oracle (R1-O1) and corroboration (R1-O2)

The C# oracle text for every case is written by the registrant in `templates.json` and rendered per
case by `SweepCaseGenerator`. It compiles with Roslyn against **BCL assemblies only** — no Calor
assembly is referenced or loaded — and runs over the case's input domain under `en-US` and the
module's overflow mode. It never calls the verifier's translator, simplifier, emitter, solver, or cache.

- **forall claims** (postconditions, obligations, implications): wherever the hypothesis holds and
  the body returns normally, the property must evaluate to `true` without throwing; false or
  throwing is a violation. Inputs where the hypothesis or body throws are excluded and counted
  (normal-return semantics, D5). A witness found before the 60 s budget runs out stays conclusive.
- **exists claims** (precondition satisfiability; B1/N1 record no model, and nothing is
  instrumented): `Proven` with an O1 witness is validated; with an exhaustive no-witness domain it is
  a false proof; with a sampled no-witness domain it is `unconfirmed-claim` (blocks clean). `Failed`
  with an O1 witness is a spurious refutation. The witness is the non-vacuity check.
- **Domains:** exhaustive when every parameter is `bool` or an 8/16-bit integer and the product is at
  most 65,536 inputs (81 of 710 cases); otherwise the per-type boundary table, 6 seeded values, and
  every numeric constant drawn into the case with its neighbours (v-1, v, v+1), capped at 4,096
  tuples with every constant-only tuple kept. A sampled domain can show a violation but never
  establishes truth.
- Where C# defines no semantics (u64 versus signed; unary minus on `ulong`; `**`), the oracle uses
  exact integers and the row is a refusal or hypothesis row.

**R1-O2** runs the baseline's forced-guard emitted C# on every O1 witness and on the first 16 reached
inputs, and records whether the claim site's own guard fired (ContractViolationException,
InvalidOperationException, ArgumentOutOfRangeException, or IndexOutOfRangeException by site; other
exceptions are recorded but are not divergence). It does not apply to implication or precondition
claims. It executes post-simplification code (`ContractSimplificationPass` rewrites contracts before
emission), so it shares the simplifier's assumptions and is never the sole oracle. An O1/O2
disagreement in either direction adds a `semantic-divergence` record; it never changes the O1 verdict.

## 5. Case generation and freeze

Deterministic template expansion. Case ids are `R1-<row>-<nnn>`. Each case seeds SplitMix64 with
master seed `1419002401` XOR the first 8 bytes of SHA-256(case id); `cycle` holes take option
(instance mod n). `cases-index.json` holds the SHA-256 of every rendered text, and a test regenerates
the cases and fails on any byte difference. Only control templates carry `expectedOutcome` (checked).

## 7. Execution rules

- **Order:** solver-availability controls (CTRL-POSITIVE, CTRL-NEGATIVE) first on each baseline, then
  the other controls, then round-robin by case index across rows with B1 and N1 alternating, so a
  timebox stop leaves coverage spread, not chosen.
- **Timeouts:** solver 5,000 ms per query (production default); 120 s per case; 60 s per oracle run.
- **Retry:** a `TimeoutOrUnavailable` claim or a crashed/over-time case is retried once with identical
  inputs, charged to the reserve; both attempts are kept; disagreement is `flaky`; any
  `Proven`/`Discharged` attempt with an O1 violation is a finding regardless. No run-until-green.
- **Environment:** exact `dotnet --version`, OS, and architecture recorded and fixed per baseline;
  `en-US`; no Z3 seed injection (determinism itself is #1421/#1135); sequential execution.
- **Invalid runs:** a pin mismatch, an SDK change, a solver-availability control mismatch, an oracle
  control with the wrong verdict on the executing machine, a CLI contradiction, failure to load the
  baseline in-process, or harness crashes above 10% invalidate a run. Invalid runs are archived and
  never used for row status, but a false-proof candidate seen in one is kept as `candidate-unconfirmed`
  and re-executed first. A fourth invalid run makes the baseline's unexecuted release-critical rows
  `BLOCKED`.

## 8. Results, row status, and findings

Finding classes: `false-unconditional-proof`, `false-proof-unconfirmed-vacuity`,
`required-demotion-absent`, `guard-elided-without-proof`, `vacuity-mislabel`, `spurious-refutation`,
`spurious-model`, `stale-cache-proof` (warm token differs from cold), `semantic-divergence`,
`control-mismatch`, `candidate-unconfirmed`. Other classes: `validated-proof`, `refusal-validated`,
`no-claim`, `unconfirmed-claim`, `flaky`, `harness-invalid`. The registered non-vacuity check for a
counted `Discharged` (contract §4 condition 5) is `R1-O1-reached`: at least one input where the
hypothesis held and the body returned.

A frozen `classificationTable` assigns exactly one class to every (row classification, token, O1
verdict) combination; an unmatched combination is a harness error, not a judgment call. Row status
per baseline, mechanically: `FALSE-PROOF` if any false-unconditional-proof; else `FINDING`
if any other finding; else `INCOMPLETE` if **any** allocated case is unexecuted, harness-invalid,
flaky, crashed, unconfirmed, or still timed out after its retry (no tolerance); else
`CLEAN-WITHIN-BUDGET`, reported with its counts (a modeled row with zero validated proofs supports no
claim that relies on `Proven`/`Discharged`).

Each finding is a JSON record (`findingRecord`) with case hashes, raw and mapped outcome, guard
observations, witness, O1/O2 results, non-vacuity check, a minimized Calor case with a standalone C#
reproduction, binary and environment hashes, every attempt, the other baseline's result, the affected
guarantee, and an empty disposition for #1413.

## 9. Controls and hypothesis

- **Oracle controls (13, executed in R1):** wrap-around, checked-overflow throws, mixed-sign
  promotion, shift masking, null strings, culture, body-excluded overflow, exists witnesses, an empty
  domain, and positive identities.
- **Verifier controls (32 per baseline, executed by #1311), each with an exact `expectedOutcome`:**
  8 positive and 6 negative (the solver-availability check: a mismatch invalidates the run), 2
  mutation pairs (oracle verdicts must match; a changed verifier outcome alone is not a finding), 6
  #845 cases, and 8 post-fix vectors (D3, D4, D8, D11, D14, D15, #807, G1-C1). A retrospective
  mismatch is a `control-mismatch` finding, and the rows the control `guards` cannot be dispositioned
  `VALIDATED` before it is resolved.
- **#845 / PR #961 (retrospective, discriminating):** pre-#961, unsigned literals above
  `int.MaxValue` were refused and every other integer literal was translated as signed 32-bit (source
  reading, not executed). The two ULONG-near-max cases are the shape #845 names; P845 is expected to
  refuse them, so they document rather than discriminate. Four width cases discriminate: under
  `overflow=unchecked`, `x + LONG:1` and `x + UINT:1` at `int.MaxValue` wrap in the pre-fix solver but
  widen in C#. The control discriminates only if P845 produces exactly its registered pre-fix outcome
  while B1 (and separately N1) produces exactly its expected outcome on the same case. If it does not
  discriminate on a baseline, the guarded rows are `INCOMPLETE` there until an amendment registers a
  replacement control that passes.
- **Hypothesis H1 (from R0, not tested):** "`ExpressionSimplifier` folds unary `Negate` and
  `BitwiseNot` over `IntLiteralNode` without checking `IsUnsigned`/`IsLong`." Source reading at B1
  shows an early return that gates folding to non-long, signed literals, and that `BitwiseNot` is
  folded although it is not in `ModeledForms.UnaryOperators`. `SIMP-H1-UNARY-FOLD` renders every
  registered literal form against sign-consistent operands, plus pinned cases (`§Q (== x INT:-1)`,
  `§S (== x (~ UINT:0))`) where a wrong fold would turn a false property into a proof; forms with no C#
  typing sit in the refusal row `SIMP-H1-INVALID-TYPING`. Nothing was executed.

## 10. Stopping, amendments, owners, and handoff

- **Stop** at the first of: 10 days after merge, 20 agent-hours, 1,500 case executions, 600 CI
  minutes, 10 local machine-hours. Unreached cases are `not-investigated`; a release-critical row with
  an unreached case is `INCOMPLETE` and therefore `BLOCKED`, unless a reviewed #1407 amendment raising
  the ceiling merges first. Contract §8 stopping conditions apply unchanged.
- A **finding does not stop** the sweep: minimize it from the reserve, file it, continue in order.
- **Amendments** carry a version, UTC time, justification, reviewed PR, and an
  after-decision-bearing-inspection flag. They cannot remove a row or case. Cases added after the
  freeze are `post-registration`: they can add findings, never clean status.
- **Owners:** implementation by a Claude Code agent under #1311 (at most 2 PRs; agents never merge);
  review, merge, decision, and amendment authority @juanmicrosoft under the contract's recorded
  independence deviation. The #1311 executor does not edit templates, the generator, or the oracle.
- **Handoff to #1413:** each row on each baseline and each finding gets exactly one of `VALIDATED`,
  `FIX-IN-0.24`, `DEMOTE-IN-0.24`, `NOT-INVESTIGATED`, `MILESTONE-FAILED`. `VALIDATED` only for
  `CLEAN-WITHIN-BUDGET`; `NOT-INVESTIGATED` only for the four excluded rows; a false unconditional
  proof needs a fix or visible demotion within the s2-repairs ceilings, or the milestone fails. A
  retained guard does not cure it. B1 and N1 are immutable releases, so their findings stay recorded
  against them with the candidate-side disposition.
