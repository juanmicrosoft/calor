### Two permutation statistics, both stated

Labels are permuted **within each pair** in both; both are one-sided, P[permuted ≥ observed].

**Pooled mean difference** (the reviewers' statistic) is computed **exactly**, not sampled. The
statistic is strictly increasing in the total treatment sum, so the distribution of that sum over
all C(10,5)⁴ = **4 032 758 016** relabellings is obtained by convolving the four per-pair sum
distributions and thresholded with a bisect — seconds of work, no seed, no noise:

| | turns | tokens | wall-clock |
|---|---|---|---|
| exact p | **0.013289** | **0.083758** | **0.439102** |
| as a fraction | 53590270/4032758016 | 337777535/4032758016 | 1770790660/4032758016 |

The reviewers' 0.012 / 0.08 / 0.44 were a 20 000-draw Monte-Carlo estimate of exactly these.

**Median over pairs of the paired mean delta** (the notes' statistic) has no such monotone
reduction, so it stays Monte Carlo: a fresh `random.Random(4537)` per metric, the label vector
`[1]*nT + [0]*nC` rebuilt and shuffled per pair per draw, **100 000 draws**, with the binomial
standard error emitted beside every p:

| | turns | tokens | wall-clock |
|---|---|---|---|
| committed MC p | **0.0041** ± 0.0002 | **0.0251** ± 0.0005 | **0.4385** ± 0.0016 |
| exact relabelling value | 0.004132 | 0.026204 | 0.439069 |

The test pins the MC value **within three standard errors of the exact value**, not to its fourth
decimal — the fourth decimal of a Monte-Carlo p is noise, and pinning it would make the suite
fail on any draw-order change without any statistical meaning.

Observed statistics: pooled Δturns 4.35; median-over-pairs Δturns 5.5 (four pairs → the mean of
the two middle deltas).

**On the published triples.** Roadmap §0.2 quotes 0.0037 / 0.0249 / 0.4375 for the
median-over-pairs statistic; the notes quote 0.004 / 0.025 / 0.449. Both are 20 000-draw
Monte-Carlo estimates of the same quantity, and the roadmap's is reproduced *exactly* by this
script's scheme at 20 000 draws (`test_roadmap_triple_is_this_scheme_at_20k`) — so nothing was
irreproducible; the earlier draft of this note wrongly said so. At 20 000 draws the wall-clock
standard error is ≈ 0.0035, which is the whole distance between 0.4375, 0.4385 and 0.449. All
three readings support one conclusion: **the turn gap is real, the token gap is marginal,
wall-clock is not distinguishable.**

**Sensitivity** (point = median over pairs of mean T / mean C output tokens): all-naive
**1.3490**; correcting only N1-003/run-5 (naive 12 547 → 13 585) **1.3390**; correcting only
N1-001/run-3 (4 522 → 12 821) 1.1934; both corrected (registered) **1.1835**. Draft v2 of the
measurement notes attributed the 1.3390 to N1-001/run-3; it is N1-003/run-5. Corrected in that
note and in the roadmap line.

## W4's per-turn table — built now, populated later

`ppe1-turn-attribution.py --transcripts DIR...` tabulates, for every run directory (any directory
holding `result.json` or `transcript.jsonl`), the Claude Code `--output-format stream-json`
transcript:

- **`turns.assistantMessages` = distinct TOP-LEVEL assistant `message.id`** — events with
  `parent_tool_use_id` null. This is the A-1.12 field, and keeping it top-level-only makes it
  independent of whether the epoch ran with `--forward-subagent-text`: turning that flag on adds
  subagent events to the stream and would otherwise silently inflate the turn count.
  `turns.subagentMessages` reports the forwarded ones separately; `turns.resultNumTurns` carries
  the `result` event's own figure for cross-check.
- Tool calls by class **Read / Grep (Grep, Glob) / Bash-build / Bash-other / Edit (Edit, Write,
  MultiEdit, NotebookEdit) / other**, de-duplicated on `tool_use.id` (blocks with no id are
  de-duplicated per message + position + input).
- **Bash-build** = a `dotnet build|test|run`, a `dotnet …calor.dll`, or a `calor` invocation **in
  command position** — at the start of the command or of a pipeline/list segment (after `;`, `&`,
  `|`, `(` or a newline). So `cd x && dotnet  test`, `dotnet run --project src/Calor.Compiler`,
  `dotnet ./calor.dll …` and a bare `calor` are builds, while `dotnet build-server shutdown`,
  `grep calor foo`, `echo 'dotnet test' > notes`, `escalor foo` and `which calor` are not.
  `which calor` is deliberately Bash-other: it locates a binary, it does not compile. All twelve
  cases are pinned in `test_bash_build_pattern_has_word_boundaries`.
- **MCP compiles (`mcp__calor__*`) land in `other`**, with the raw tool name preserved in
  `toolNames` so the E7 MCP leg can be counted later without a schema change
  (`test_mcp_compiles_land_in_other_with_the_raw_name_kept`).

Output is JSON plus a markdown rendering. Runs with no transcript are listed as `noTranscript` —
never dropped. The same table is embedded per epoch in `ppe1-turn-attribution.json` (`perTurn`),
where today every archived run reads `noTranscript` (`run-pair.sh:853/867` ran `claude --print
--output-format json`).
