## Discrepancies against the published figures (reported, not fitted)

1. Roadmap §0.2 quotes the median-over-pairs p as 0.0037 / 0.0249 / 0.4375. The pinned draw order
   gives 0.0043 / 0.0249 / 0.4494 — the notes' own 0.004 / 0.025 / 0.449 at their precision. No
   stdlib draw order tried (fresh RNG per metric, `random.sample`, label-vector shuffle, per-pair
   draw loops, `>` instead of `≥`) reproduces 0.0037 and 0.4375 together. 0.0037 is within the
   Monte-Carlo noise of 20 000 draws (one s.e. ≈ 0.0005 at p ≈ 0.004); 0.4375 is about three
   s.e. (≈ 0.0035) below 0.4494, so it came from a different draw scheme or input rounding that
   the throwaway script did not record. The roadmap line should read 0.0043 / 0.0249 / 0.4494,
   citing this script; the conclusion (turn gap real, token gap marginal, wall-clock
   indistinguishable) is unchanged under every variant tried.
2. The reviewers' pooled statistic reads 0.012 / 0.08 / 0.44; the pinned implementation gives
   0.0124 / 0.0851 / 0.4451. Tokens rounds to 0.09, not 0.08; their draw order is not recorded.
   Same conclusion on every reading.
3. Notes §S1.2 says "correcting only N1-001/run-3 gives 1.3390". The arithmetic puts 1.3390 on
   correcting only N1-003/run-5; correcting only N1-001/run-3 gives 1.1934. The roadmap's unnamed
   "one-run-corrected 1.3390" is therefore the N1-003/run-5 figure. The all-naive 1.3490 and
   registered 1.1835 are reproduced exactly.

## W4's per-turn table — built now, populated later

`ppe1-turn-attribution.py --transcripts DIR...` tabulates, for every run directory (any directory
holding `result.json` or `transcript.jsonl`), the Claude Code `--output-format stream-json`
transcript: **`turns.assistantMessages` = distinct assistant `message.id`** (the A-1.12 field;
`stream-json` emits one event per content block, so multi-block messages count once), subagent
messages (`parent_tool_use_id` set), the `result` event's `num_turns` for cross-check, and tool
calls by class **Read / Grep (Grep, Glob) / Bash-build (Bash whose command matches
`dotnet build|dotnet test|calor `) / Bash-other / Edit (Edit, Write, MultiEdit, NotebookEdit) /
other**, de-duplicated on `tool_use.id`. Output is JSON plus a markdown rendering. Runs with no
transcript are listed as `noTranscript` — never dropped. The same table is embedded per epoch in
`ppe1-turn-attribution.json` (`perTurn`), where today every archived run reads `noTranscript`
(`run-pair.sh:853/867` ran `claude --print --output-format json`).
