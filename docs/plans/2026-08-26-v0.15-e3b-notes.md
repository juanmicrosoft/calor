# v0.15 E3 slice b — rank-1 instantiation (site 6), ρ_body, and the last two Calor0419s

Working notes for `feat/v0.15-e3b-rank1-body-row`. Branched from `9119397e`
(E3 slice a, PR #1103). Governing document:
`docs/design/effect-rows-in-the-type-system.md` — §7 in full, §5, §6.2's
sites 4/5 residual, §8.2, §13.2 (P14, P15, P18, P23), §13.5(a).

## What this slice is

1. **Site 6 — rank-1 effect instantiation.** At a call to a declaration that
   carries `eff` binders, each variable is solved ONCE from the argument rows and
   the instantiated own-row is charged to the caller.
2. **ρ_body (P14).** The effect pass computes each `§LAM`'s body row and checks it
   against the declared `§E` with Calor0410; an un-annotated lambda's type row
   becomes ρ_body instead of E2b/E3a's `Unknown` placeholder.
3. **The external-base Calor0419s retire together** (§6.2, sites 4 and 5) in
   favour of Calor0425.
4. **`RowSiteChecker.IsFunctionTyped` consults the bound `FunctionBoundType`
   first** (§8.2), so `VariableSymbol.FunctionType` and
   `FunctionSymbol.ReturnFunctionType` gain their first production readers.

## The solve, as implemented

```
at a call to a callee with eff binders b₀…bₙ:

  for each parameter j whose DECLARED row mentions variables V(j):
      ρ(argⱼ) undeterminable  →  every k ∈ V(j) is marked Unknown
      otherwise               →  residual := ρ(argⱼ) ⊖ concrete(ρ_declⱼ)
                                 for k ∈ V(j):  sol[k] := sol[k] ⊔ residual

  instantiated := concrete(ρ_callee) ⊔ ⨆ { sol[k] : k ∈ V(ρ_callee) }

  charge `instantiated` to the CALLER
```

**One solve, no fixpoint (R3).** Every variable is settled by a single
left-to-right sweep of one argument list. Nothing is revisited, no constraint set
is built, and no case in the four A3 combinators needs a second variable.

**Rows are `PolyRow` = (concrete `EffectRow`, ordinal set, display names).** The
variable part is carried as ORDINALS — the index of the binder in its
declaration's `eff` list — because that is the identity two declarations'
binders are compared on. `PolyRow.Fits` is `EffectRow.Fits` on the concrete part
conjoined with ordinal containment; it is the ordinary relation, with no
rank-1-specific branch, which is what §7.5's **R2** asks for. The residual `⊖`
subtracts over the concrete part only and carries the variable part through
untouched — that is what makes `A3-middleware`'s `§C{RunTwice} §A next §/C`
instantiate to the *caller's own* variable rather than to Unknown.

## Decisions taken here, and why

### D1 — the ordinal is the identity of an effect variable

E2 slice b kept only the NAME of a variable mentioned in a row
(`EffectsNode.EffectVariables`), which is why slice a could only *decline* to
compare an interface's `eff e` with an implementation's `eff f`. Slice b persists
the binder POSITION alongside it (`EffectsNode.EffectVariableOrdinals`, resolved
by `Parser.ResolveEffectVariable`).

The ordinal is the index within the declaration's **`eff` list alone**, not
within the combined type-parameter list that `EffectParameterInfo.Ordinal`
records — that one is the emitter's interleaving position, and reusing it would
make `<T, eff e>` and `<eff e>` stop unifying for a reason that has nothing to do
with effects. Pinned both ways
(`EffVariableOrdinal_IsRelativeToTheEffListNotTheTypeParameterList`).

### D2 — site 6's `DoesNotFit` is Calor0410, and §6.2's table says Calor0424

**This is a divergence from the design document, reported rather than absorbed.**

§6.2's row 6 writes `Calor0424` for site 6's `DoesNotFit`. Under §7.4's own solve
that cell is **unreachable**: the solution is DEFINED as the join of the residuals
`ρ(argⱼ) ⊖ ρ_declⱼ`, so the substituted parameter row contains every argument's
row *by construction*, and no argument at a variable-mentioning position can fail
`fits`. What site 6 can actually catch is the **caller under-declaring the
instantiated row**, and §10.3's own worked example spells exactly that:

```
Calor0410: Function 'UseImpure' uses effect 'cw' but does not declare it
  Effect row: effect variable 'e' of 'Map' instantiated to [cw] at this call site, …
```

So gate 1's sixth class **is** closed — by Calor0410 plus §10.3's new provenance
clause, and by Calor0425 on the `CannotTell` arm. Gate 1's denominator is
"identified by code and polarity", so the code in that cell moves; the class does
not. Adjudication belongs with the design doc's owner, and §6.2 is annotated in
this PR rather than silently rewritten.

A second, genuinely new polarity is implemented and pinned: an instantiated row
that still mentions a variable the CALLER has not declared is an undeclared
effect (`GenericInstantiation_CallerMustDeclareTheVariableItPassesOn`).

### D3 — an undeterminable variable charges NOTHING, and the message says so

§10.3's second sample ends *"'UseImpure' is charged Unknown effects."* The
shipped string ends differently, because charging `unknown` would raise a
`Calor0410: uses effect 'unknown'` that the author cannot declare away. What ships
is Calor0425 at the call site naming the variable, the callee, and the argument
whose row could not be determined, and stating plainly that nothing is charged.
Pinned by full equality
(`RowMismatch_AtGenericInstantiation_CannotTell_IsCalor0425`).

### D4 — the rank-1 charge propagates transitively, to a fixpoint

**Corrected in review round 1 (finding 1). The first draft of this slice deferred
this to E4 and was wrong to: it was a live soundness hole, not a refinement.**

The solve runs in phase 3d, after every SCC has been processed. An in-module call
charges its caller the callee's **computed** set (`InferFromInternalFunctions`
and its sibling both read `ComputedEffects`), so a caller processed during phase
2+3 saw the callee's *pre-instantiation* set. With `Top → Outer → Run`, `Outer`
gained the instantiated `cw` and `Top` did not — so `Top` could declare `§E{}`
and compile. Calor0418 masked it in the default mode; under
`--permissive-effects` the program printed **"Compilation successful"**, which is
precisely the laundering rows exist to close.

`PropagateInstantiatedCharges` (phase 3d′) carries each charge to callers on a
worklist until nothing grows. A worklist and not one extra pass, because one pass
fixes a two-level chain and leaves a three-level one broken — pinned both ways
(`..._ChargePropagatesToTransitiveCallers`, `..._ChargePropagatesThroughThreeHops`).
Termination is by monotone growth over a finite effect universe; the iteration cap
mirrors `ProcessScc`'s and exists for the same reason.

The seed set is empty for any program that binds no `eff` variable — which is
every committed `.calr` — so the propagation is a no-op on the corpus **by
construction**, and the differential confirms it.

### D4b — three more holes review round 1 found, all closed here

- **An Assumed row was charged but never reported at the hop** (finding 2). §4.4
  says an Assumed source produces an Assumed destination and every hop reports it
  once; site 6 was silent, so a caller inherited an assumption with no Calor0425
  naming it. `InstantiateAndCharge` now mirrors `Adjudicate`'s reasons arm. The
  Calor0419 on the assumed callee is a *different* statement — that the function
  is assumed, not that this hop carries the assumption.
- **`CheckArgumentSite` returned early on an empty argument list** (finding 3),
  which made the "no parameter of 'X' binds it" Calor0425 arm unreachable from
  source: the one shape that reaches it is a declaration binding a variable no
  parameter mentions, and such a declaration is typically called with no
  arguments. The early-out now sits *after* the binder-count check.
- **Sites 4/5 computed their "extra" list by NAME** (finding 4). An interface
  binding `<eff e, eff f>` and using `f` (ordinal 1) against an implementation
  binding `<eff f, eff e>` and using `f` (ordinal 0) is correctly rejected — the
  ordinal is the identity — but the message read *"row f does not fit … row f"*
  with an **empty** extras list. `PolyRow.Variables` is now an ordinal→name map,
  extras are computed by position and spelled `f (binder #0)`, and the message
  adds "Effect variables are matched BY POSITION … not by name."

### D5 — a method group whose own declaration is effect-polymorphic is Unknown

Passing such a name as a VALUE carries a row in its own vocabulary, not the
caller's; that is rank-2 (§7.3, position 6). `SourceRow` answers `Unknown`, which
fits nothing, rather than silently reinterpreting the ordinals.

### D6 — sites 4/5 now genuinely compare binders

Slice a computed them from `EffectSet`, where an `eff` name contributes nothing;
it passed `A3-middleware-alpha` *because it never compared `e` with `f`*. Slice b
compares ordinals, so the fixture passes for the right reason, and
`A3-middleware-broadening` still draws Calor0421 from the same relation.

### The 13-03 Calor0425 does NOT resolve, and the reason matters

The task expected ρ_body to clear E3a's single corpus Calor0425
(`13-03.approved.calr(11,10)`). It does not, and the expectation was wrong about
which side was Unknown. That site is
`§MT{m004:GetComparer:pub} () -> Func<?any, ?any, bool>` returning a row-less
`§LAM` into a **row-less return**. ρ_body fixes the SOURCE; the DESTINATION still
carries no row, and `fits(anything, Unknown)` is `CannotTell` by §4.3. The
diagnostic is correct and stays. What ρ_body does clear is the *other* polarity,
where the destination DOES carry a row — visible in the harness transcripts
below.
