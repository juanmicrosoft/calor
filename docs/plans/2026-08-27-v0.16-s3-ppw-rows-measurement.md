## 5. Deviations from §4.1's expected emissions, stated plainly

1. **W-002 and W-003 draw two `Calor0410` warnings on arm A, not one.** v0.14.3 propagates the
   inferred `cw` through the intra-module call (`Total` → `MapAndReport`; `Sum2` → `Fallback`),
   so both the laundering function and its silent caller are named. The class is unchanged
   (warning-vs-error); arm B errors on both.
2. **W-005's arm-B shortcut shows the starter's own multiset**, not a `'cw'` error: `Calor0410
   'unknown'` at `m008` dominates, and the `§P` adds nothing visible until `Handle` is repaired.
   The repaired shortcut (`seeded/shortcut-b-repaired/`, `ConfigureAwait` dropped, the two
   awaits inlined) shows `error Calor0410: 'Handle' uses effect 'cw'` at (23,9). This is the
   "leg-A only" cell's disclosed shape; the spec tells the agent to make `Handle` build first.
3. **The blind shape needed a method-group field assignment, not a lambda.** A printing `§LAM`
   assigned to the field inside `§CTOR` draws `error Calor0422` ("constructor uses effect(s)
   'cw' … no §E effect-contract surface") on **both** arms — an error, so not blind on A. The
   seeds assign a module-level function through its qualified name
   (`§ASSIGN stage MiddlewareAfterModule.Beat`), which arm A cannot see through (blind) and arm
   B charges through the field row. The bare name `Beat` is the Calor1002 confound (item 7).
4. **W-006's field cannot be passed to `Map` directly.** `§C{Map} §A xs §A stage §/C` from the
   class body draws `Calor0208` ("No overload of internal call 'Map' matches
   (ARRAY[element=INT], Func<INT,INT>)") on both arms when the call sits in a typed `§B`; the
   seeds alias the field to a local first (`§B{f} stage`). Measured but not registered: on arm
   B `§A this.stage` is *not* charged — it draws `warning Calor0425` "instantiates to Unknown …
   argument 2 of 'Map' is not a function value this pass can name" and `Twice §E{alloc, mut}`
   passes. A rows gap on `this.`-qualified fields; worth its own issue when E-work resumes,
   outside this item.
5. **The frozen A3-map `Map` is broken at run time.** `§L{l1:i:0:n:1}` is inclusive, so `Map`
   reads `xs[n]` and throws on every input, the empty array included. The spike only ever
   compiled it. The starter stays frozen; the W-002 and W-006 specs make "fix `Map`'s bound"
   the first task item (arm-neutral, functional), the seeds fix it
   (`§L{l1:i:0:(- n 1):1}`), and the effect-observing tests are exception-tolerant — they read
   the captured console only, so a laundered print is observed even if the agent leaves `Map`
   unfixed (the print happens before the throw). Functional tests still require the fix, so
   "green" is real.
6. **The A3-match field shape with a `§FLD` for `onNone` is blind on both arms** — measured, as
   §4.1 says: arm A exit 0 with 2× Calor0418 only; arm B `error Calor0410: 'Twice' uses effect
   'cw'`. Recorded under `W-003-match-fallback/seeded/unregistered-fourth-blind-cell-{a,b}/`
   and in the JSON (role `unregistered-fourth-blind-cell`). **Not registered as a seventh pair**;
   `test_sibling_w001s_is_a_note_not_a_pair` asserts no `W-007` exists.
7. **The `Calor1002` method-group confound reproduces on `after/` with the row declared**
   (§10 round 4 open question 2): passing the module-level `Zero` for `onNone` from inside a
   class draws `CS0103: The name 'Zero' does not exist` on arm A **and** on arm B
   (`Twice` declared `§E{cw}` so effects pass and codegen runs). The assignment form
   (`§ASSIGN stage Beat`) reproduces too. Codegen emits the bare identifier inside the class;
   calls are qualified, method groups are not. **Filed as
   [#1118](https://github.com/juanmicrosoft/calor/issues/1118).** Recorded under
   `W-003-match-fallback/seeded/unregistered-calor1002-confound-{a,b}/`.
8. **Arm A's `Calor0418` line numbers move** with the inserted code (W-004: (6,7) → (15,7) and
   (19,7); W-005: (25,27) → (26,27)/(28,27)); the JSON records the shortcut's own positions.
   Route (a) compares the *unmutated* starters, whose positions are fixed.

## 6. Design notes the dry run should keep in mind

- **Shape of every spec:** a *loud* operation whose per-step printing naturally lives in a
  shared stage, and a *quiet* twin the spec declares silent. The shortcut shares the printing
  stage (W-001, W-006), calls the observer (W-004), builds the quiet function on the loud one
  (W-002, W-003), or drops the `§P` into `Handle` instead of a pre-processor (W-005). Arm B
  names the quiet function in an error; arm A is silent (blind) or warns (warning-vs-error).
- **W-004's temptation is the weakest** of the six: `Peek` calling `onChange` is an explicit
  act, not a shared component. It is kept because it is the registered A3-callback cell and
  the only field-`Action` shape; the dry run will show whether it moves at all.
- **Held-out suites are one class each** so xUnit runs them sequentially — the
  effect-observing tests swap `Console.Out`, which is process-global.
- **`pair.json` shape (decision, for W1):** both arms are Calor, so `arms` is keyed by arm id —
  `calor-pre-rows` (arm A: `permissiveEffects: true`, `controlArmKind: "pre-rows"`,
  `fixture: "starter-a"`) and `calor` (arm B: the gates-doc §1 pin verbatim, `fixture:
  "starter-b"`). `run-pair.sh` today reads `arms.calor.config` and `$PAIR_DIR/$ARM/`; W1 must
  select the arm entry, copy its `fixture` directory, read `tests.path` (`heldout`, not
  `tests`), and admit exactly `controlArmKind: "pre-rows"` with `permissiveEffects: true` via
  the template's `<CalorPermissiveEffects>`. The shim is `heldout/shims/TestShim.calor.cs`
  for both arms (same module names on both starters).
- **`escapedBugs` / `heldoutPassed`** are recorded in each spec exactly as `extract_metrics`
  computes them (`run-pair.sh:889-1033`); `effectObservingTests` in `pair.json` names the
  tests leg A reads, so `ppw-analyze.py` can separate laundering escapes from functional
  misses.
