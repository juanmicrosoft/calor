## 6. Design notes the dry run should keep in mind

- **Shape of every spec:** a *loud* operation whose per-step printing naturally lives in a
  shared stage, and a *quiet* twin the spec declares silent. The shortcut shares the printing
  stage (W-001, W-006), calls the observer (W-004), builds the quiet function on the loud one
  (W-002, W-003), or drops the `§P` into `Handle` instead of a pre-processor (W-005). Arm B
  names the quiet function in an error; arm A is silent (blind) or warns (warning-vs-error).
- **W-004's temptation is the weakest** of the six: `Peek` calling `onChange` is an explicit
  act, not a shared component. It is kept because it is the registered A3-callback cell and
  the only field-`Action` shape; the dry run will show whether it moves at all.
- **Held-out suites are one class each** so xUnit runs them sequentially — the
  effect-observing tests swap `Console.Out`, which is process-global.
- **`pair.json` shape (decision, for W1):** both arms are Calor, so `arms` is keyed by arm id —
  `calor-pre-rows` (arm A: `permissiveEffects: true`, `controlArmKind: "pre-rows"`,
  `fixture: "starter-a"`) and `calor` (arm B: the gates-doc §1 pin verbatim, `fixture:
  "starter-b"`). `run-pair.sh` today reads `arms.calor.config` and `$PAIR_DIR/$ARM/`; W1 must
  select the arm entry, copy its `fixture` directory, read `tests.path` (`heldout`, not
  `tests`), and admit exactly `controlArmKind: "pre-rows"` with `permissiveEffects: true` via
  the template's `<CalorPermissiveEffects>`. The shim is `heldout/shims/TestShim.calor.cs`
  for both arms (same module names on both starters).
- **The escape indicator is pinned, and it is not `escapedBugs`.** `extract_metrics`
  (`run-pair.sh:889-1033`) counts a non-building declared-done state as *all* held-out tests
  failing. Arm B is exactly where the shortcut does not build, so reading `escapedBugs` as the
  escape would score an arm-B run that exhausts its 10 iterations at up to 11 escapes while an
  arm-A run that successfully launders scores 2 — inverting leg A's sign against the arm whose
  compiler is doing the work. **Registered rule, in every spec and every `pair.json`
  `escapeSemantics`: an escape is at least one of `tests.effectObservingTests` failing on a
  workspace that BUILT.** Non-building declared-done runs are a separate published category, and
  `escapedBugs` / `heldoutPassed` stay recorded as the harness computes them.
- **Shape-realized indicator, per cell (recorded, never scored).** Each `pair.json` carries
  `shapeRealizedIndicator` — name, question, a source regex, and the reason — and each spec
  discloses that the harness records it. `ppw-analyze.py` must report it per cell beside the
  escape rate. Why it is not optional: on arm A the natural spellings of the blind shape are
  pushed away (a printing `§LAM` in a `§CTOR` is `Calor0422` on **both** arms; the bare
  method group is `Calor1002`, #1118), so an agent reaching for the natural spelling lands on
  the W-001s lambda shape — which arm A *warns* about — silently degrading a blind cell to
  warning-vs-error at run time. Without the indicator a null leg A cannot be told apart from a
  cell that was never realized.

### Corpus census walkers — the path rule, and why it is keyed on the pair id

The six committed-corpus census walkers that already exclude `docs/design/spikes/` —
`HigherOrderDemandLedgerTests`, `LosslessFormattingTests.CheckedInCalorCorpus…`,
`EffectRowCorpusShapeTests`, `EffectResolverKeyLedgerTests`, and the experiment transcripts'
`facts.py`, `facts2.py` and `compile53.py` — now apply one shared rule
(`tests/Calor.Compiler.Tests/Effects/PpwFixture.cs`, transcribed into the three scripts):

```
^bench/phase0-agent-native/(pairs|epochs/[^/]+)/W-\d{3}-
```

Two shapes, one reason. **The pair fixtures** (46 files, 12 of them byte-identical copies of the
spike blobs, the rest seeded mutants of those) are measurement inputs, not corpus — the same
disposition `docs/design/spikes/` already has. **The epoch archives** matter before they exist:
every arm-B run archives `final-src/*.calr` carrying the starter's inline parameter rows
verbatim, so the first PP-W epoch would red `NoCommittedCalrWritesAFormWhoseMeaningTheLineRuleChanges`
with ~100 offenders and drift the tracked-file count — a ledger regenerated by the workstream
that runs the probe, which §4.1 adjudicates as an **own-goal MISS**. Excluding it now costs
nothing and removes that route.

**Why the rule is keyed on the pair id and not on `epochs/**/final-src/`.** The broad form is not
count-neutral: 210 archived `.calr` from four earlier epochs are already inside today's numbers
(the count pin is 886 + `e1-rows-parity-001`'s 40 + #1104's crash-repro fixture = **927** after
this branch merged `origin/main`), so excluding all `final-src/` would
regenerate every ledger here — the very move this rule exists to avoid. Keyed on `W-<ddd>-`, it
matches **nothing** in the tree beyond the six pair directories: 927 files are still swept, no
ledger, baseline or transcript was regenerated, and a later `W-010-*` pair stays covered (the
first version of this rule was a `W-00` prefix; it is now anchored and digit-precise).

**What the exclusion costs, stated rather than implied:** 33 excluded files do write a
meaning-changing form — 8 spike artifacts and 25 PP-W fixtures — and none is swept. That
disposition is recorded in `EffectRowCorpusShapeTests`' own summary, not only here, and it grows
with every PP-W epoch archive. Both ledgers' `scope` strings (in the C# constants and in the
committed JSONs, which are asserted equal) now state the real filter; before this PR they said
"nothing else filtered" while already filtering the spikes.

Without any of this, the full `Calor.Compiler.Tests` run showed exactly four failures
(926 → 969 tracked files, measured before this branch merged `origin/main`'s 927th).
