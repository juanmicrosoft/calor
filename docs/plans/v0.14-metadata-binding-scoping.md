## 2. Design decisions

**D1 — Introduce `BoundType`, keep `TypeName` as a string shim, delete the shim at S7.** A new
abstract class `BoundType` (in `Binding/BoundTypes/`) is the ground truth for bound-tree types.
`BoundExpression.TypeName` remains a `string` property implemented as `Type.DisplayString`.
Distinct name from the sealed `Binding/Scope.cs:740` `TypeSymbol`. `BoundExpression.TypeName` is
**deleted at S7 as a v0.14 release exit criterion** (F-5). A completeness pin (F-3) forbids new
`TypeName ==` sites and drives the count monotonically down until S7 completes.

**D2 — `BoundType` hierarchy: exactly six concrete kinds.**

| # | Kind | Purpose |
|---|---|---|
| 1 | `PrimitiveBoundType` | INT / LONG / UINT / ULONG / FLOAT (with `Bits`, `Signed`) / BOOL / STRING / CHAR / DECIMAL / VOID |
| 2 | `NominalBoundType` | Resolved user-defined or .NET type; carries `NullableAnnotation` + a `TypeSymbol` back-ref (Calor) or `INamedTypeSymbol` back-ref (Roslyn) |
| 3 | `GenericInstantiationBoundType` | `Definition : NominalBoundType`, `TypeArguments : IReadOnlyList<BoundType>` — nullable annotation on type arguments propagates (Shape 14) |
| 4 | `ArrayBoundType` | Element `BoundType` + rank |
| 5 | `FunctionBoundType` | Parameter `BoundType`s + return `BoundType`. Effect rows attach here in 0.15 (§4.2) |
| 6 | `UnresolvedBoundType` | Explicit exit ramp (D6). Carries `Reason` string |

Count exhaustively 6. No inference variables. All types ground.

**D3 — Retarget existing `GeneratedCSharpCompiler.References` as the metadata source.** The spike
does **not** build a parallel reference set. `Binding/Metadata/MetadataContext` accepts a
reference list at construction and reuses `GeneratedCSharpCompiler.References` (TPA-derived,
process-lifetime `Lazy<T>`) by default. This closes the round-2 C1 defect (avoids
"binding-time BCL diverges from codegen-time BCL"). Reused surface:

- `TryResolveType(fullyQualifiedName) → NominalBoundType?`
- `TryResolveMethodGroup(receiverType, methodName) → IReadOnlyList<IMethodSymbol>`
- `TryResolveOverload(receiverType, methodName, argumentTypes) → IMethodSymbol?` (see D4)

**Reference-vs-runtime-assembly caveat.** TPA is *runtime* assemblies, not the SDK reference pack
(`Microsoft.NETCore.App.Ref`). Nullable annotations may differ between them (implementation
assemblies sometimes have more Oblivious surface than ref-pack). **Mitigation:** when a
`NominalBoundType` resolves to a `NullableAnnotation.Oblivious` symbol, `Calor0271` (see F-4) is
emitted regardless of *why* it's Oblivious. Any drift is surfaced honestly; it does not silently
become `NotAnnotated`. A future multi-TFM story (needing ref-pack for a non-host TFM) is out of
scope here and deferred to 0.14.x per §6.

**Cache lifecycle:** `GeneratedCSharpCompiler.References` is process-lifetime (matches the
existing pattern; no new lifecycle to reason about). `CSharpCompilation` objects constructed by
`MetadataContext` are per-Calor-compilation and disposed with the `Calor.Sdk.Compilation`. **A
new `MetadataContextLifecycleTests` suite (S1) asserts:** (i) 100 sequential
`Compilation`+`MetadataContext` construct/dispose cycles leave the process working-set within
20% of baseline (guards the M3 unbounded-growth concern), (ii) two concurrent constructions do
not race on `_references.Value`. **`MetadataContext` is `internal` in `Calor.Compiler`**; the
SDK does not expose it as public surface (round 2 m1) — external callers cannot inject arbitrary
`MetadataReference`s.

**Determinism.** The reference set is a manifest at
`bench/phase0-agent-native/metadata-references-manifest.json` (F-2, rule frozen here, content
frozen at S1's merge). Manifest content is a curated *subset* of TPA (the API-surface assemblies
Calor programs may reference — `System.Runtime`, `System.Console`, `System.Collections`, etc.);
extra assemblies present under TPA (like `Z3`, `Microsoft.CodeAnalysis` itself) are excluded
from what `MetadataContext` exposes for resolution, preventing "Calor code binds to the
compiler's own internals". Manifest carries SHA-256 per assembly; drift between manifest and TPA
at load time is a hard failure with a specific message (never silent `null`).

**Rollforward robustness (round 2 M4).** The manifest names its valid SDK version range:
`sdkVersionRange: "10.0.100 – 10.0.999"`. `MetadataContext` construction reads the SDK version
from `RuntimeInformation.FrameworkDescription`; if the observed version is inside the range but
SHA-256 drifts, CI emits an Info-level "manifest regeneration recommended" diagnostic and
auto-regenerates the manifest under a bot-signed commit for review. If the observed SDK is
outside the range, hard failure. This lets `global.json`'s `rollForward: latestMinor` continue to
work without every SDK patch breaking CI.

**D4 — Overload resolution via synthetic invocation syntax + `SemanticModel.GetSymbolInfo`.**
Roslyn's `OverloadResolution` type is `internal`; the standard supported workaround is:
1. Reuse a per-compilation `CSharpCompilation` (D3).
2. For each Calor call site, synthesise a `SyntaxTree` fragment:
   `#nullable enable\n_ = ((TReceiver)default!).<Method>(((TArg1)default!), ((TArg2)default!));`
   The `default!` suppresses nullable-flow warnings on the placeholders (round 2 first reviewer's
   m3 note). `#nullable enable` guarantees Roslyn's overload resolution sees consistent nullable
   context — otherwise the compiler's own build environment would leak in.
3. Add the tree to the compilation; ask `SemanticModel.GetSymbolInfo(invocation)` for the
   resolved `IMethodSymbol`. Roslyn's own algorithm resolves — generic inference, `params`
   collapse, extension priority, nullable tie-breaks.
4. On `SymbolInfo.Symbol == null` with `CandidateSymbols` populated, emit `Calor0270
   SignatureUnresolved` and produce `UnresolvedBoundType`.

**Smoke probe in S1's exit criteria** — resolve `Console.WriteLine(int)` vs
`Console.WriteLine(string)` via this mechanism **before F-1 freezes shape fixtures** (was S4 in
v1 — moved earlier to eat the API-shape risk before design lock-in, per TIER1A V4 discipline).

**D5 — Effect resolver becomes symbol-resolved on receivers.** `Effects/ExternalCallCollector.cs`
reads `BoundExpression.Type` (a `BoundType`) instead of `_variableTypeMap`. The **deletion** of
`_variableTypeMap` is S6's discriminating exit criterion. This closes roadmap §2.2's caveat that
excluded the effects facet from `calor query` v1. **Scope note:** the `calor query` effects
*facet* turns on for resolved receivers only; `UnresolvedBoundType` receivers stay `Assumed`
honestly. Effect *rows* on function types remain 0.15 (§4.2, §6 non-goal 2).

**D6 — Exit ramp is a type, not a policy: `UnresolvedBoundType`.** Failed metadata lookup or
overload resolution → `UnresolvedBoundType(reason)` + `Calor0270 SignatureUnresolved` (in the
0200 semantic band; 0270 verified free — highest currently allocated: `Calor0262
InheritanceCycle`). Downstream analyses treat `Unresolved` as "do not claim".
`NominalBoundType.NullableAnnotation` is `Annotated | NotAnnotated | Oblivious`. `Oblivious` is
first-class; never silently upgraded to `NotAnnotated`. **`Calor0271
SignatureResolvedNullableOblivious`** (Info) is emitted whenever resolution succeeds against an
`Oblivious` symbol, feeding §3.2's "explicit boundary adapter" rule.

**D7 — Flag lifecycle changed after S6 landing constraint (round 2 M1 fix).**
`--enable-metadata-binding` / `CALOR_METADATA_BINDING=1` gates the new binder path through S5.
**At S6's merge the flag flips default-on and the flag surface is removed** — S6 deletes
`_variableTypeMap`, so a flag-off path would silently break effect resolution. The two changes
are coupled in a single PR: "S6 metadata binding becomes trunk, `_variableTypeMap` deleted, flag
retired." Rationale: the flag exists to let 0.13.x preview releases carry the spike safely; S6 is
the point where metadata binding is the trunk mechanism, not a preview. **Any 0.13.x preview
release containing S6 is therefore not shippable with the flag off** — a release-note in the
preview must state this.

### F-7 — `SemanticsVersion.Major` coordination with S7 (round 2 C2 fix)

**Rule:** if the same release cycle (0.14.x) contains both S7 (shim removal, F-5) and a
`SemanticsVersion.Major` bump to 2, they land in that order or in the same PR. **A 0.13.x
preview release containing S7 without the semantics bump is permitted** provided the release
notes disclose that 1.x-declared files continue to compile without 2.0.0-style enforcement in
that preview (S7's changes are string-representation only; they do not by themselves change what
programs are accepted). The release cycle that bumps `Major = 2` is responsible for the

## 5. Risks and their exit ramps

**R1 — Reference-assembly loading is flaky.** TPA is process-local; F-2 falls back to filesystem
probe and the Z3-style bootstrap script if needed.

**R2 — Overload resolution edge cases exceed spike budget.** Postmortem V4's lesson. Ramp:
14+1 = 15 shapes are the budget; S1 smoke probe validates D4 mechanism **before F-1's fixtures
are authored**. If <ceil(0.65 × N) resolve at S4, spike ships with a negative-result section;
§3.5.2's bar is measured, not defined.

**R3 — Shim becomes permanent.** F-3 ratchets; **F-5 is a hard release exit criterion** — the
release does not tag with the shim in place.

**R4 — `SemanticModel` requires syntax; Calor has AST.** D4's synthetic C# fragment. S1 proves
it works before F-1 freezes.

**R5 — `_variableTypeMap` deletion breaks migration paths.** S6 tests must remain green;
deletion is the exit criterion, not a hoped-for consequence.

**R6 — Self-postmortem theatre.** Naming risks is not mitigating them. Structural mitigations:
S1 smoke probe eats the API-shape risk early; F-1 fixture-authoring order removes retro-tuning;
F-5 hard delete removes "cleanup later"; F-7 blocks accidental cross-release-cycle timing bugs;
`MetadataContextLifecycleTests` (round 2 M3) eats the memory-growth risk in S1, not "in
production."

**R7 — Verification cache silently invalidated.** S2's cache-invalidation gate: assert
byte-identical `Type.DisplayString` on pinned corpus OR bump
`VerificationCache.CurrentCompilerSemanticsVersion` and disclose in CHANGELOG. Round 2 C3's
resolution.

**R8 — TPA-based reference set differs from SDK reference pack (nullable annotations).** D3's
`Oblivious`-diagnostic-regardless-of-cause mitigation. Never silently upgraded. Multi-TFM story
(needing ref-pack for a non-host TFM) deferred to 0.14.x with `MetadataContext` accepting a
constructor-injected reference list already in place.

**R9 — Schedule collapse for 2.0.0 self-migration (round 2 M2).** Migrator work partitioned:
authoring starts after S5 (typed receivers available); dogfood-utility migration gate is after
S7; full corpus migration and 217-program re-baseline is a separate downstream PR series that
does not block S1–S7. Confirmed in the cross-workstream table (§3 preamble).
