**Method.** `python3 docs/plans/evidence/v0.25-r0-1426/reproduce/reproduce.py` runs each C# fixture
through four public surfaces:

- `calor convert` with no flags (`cli-default`);
- `calor convert --passthrough` (`cli-passthrough`);
- MCP `calor_convert` with default arguments (`mcp-default`);
- MCP `calor_convert` with `passthroughOnError: true` (`mcp-passthroughOnError`).

It compiles each produced `.calr` with `calor` (default options). If that fails only on effect
diagnostics (`Calor04xx`), it also compiles with `--permissive-effects`, the mode the CLI help names
for converted code. Both results are kept. `ProbeRunner.cs` then compiles the original and each
generated C# file in memory and compares `Probe.Run()` results and exceptions. Two runs produced
byte-identical results.

**Limits.** This is a baseline, not a T1 oracle.

- Each behavior has one input. Culture is checked once (F2-INTERP-07).
- `calor migrate`, MCP `calor_migrate`/`calor_batch`, SDK, MSBuild, and LSP were not exercised.
  They are registered as `not-measured` rows.
- The historical corpus modules of #1139 need project references and were not re-run.
- `@permissive-effects` comparisons show behavior, not that the default compile succeeds.

### Baseline vocabulary

A surface outcome is `native-match`, `native-mismatch`, `preserved-match` (some C# kept as
`§CSHARP` or inline `§CS{}`), or `compile-error:<codes>`. The suffix `@permissive-effects` means the
behavior was compared only after the `--permissive-effects` compile. A case status is
`reproduces`, `partially-reproduces`, `no-longer-reproduces`, `control-passes`, or `not-measured`.

## 4. Discovered defect outside the six families

not in the denominator and not a ref/out defect. It is listed so it is not lost. Recommendation:
file a separate issue and decide whether it blocks a #1430 candidate. The epic says no known
semantic regression in the candidate may be ignored.

## 10. Readiness records and the denominator rule

Each family in `scope.json` has `readiness.status` set to `NOT_STARTED`, `IN_PROGRESS`, `READY`,
or `BLOCKED`. All six start at `NOT_STARTED`. #1428 (T1) and #1429 (W1) update these records. They
do not close per family.

- **IN_PROGRESS** names a `pr` or `branch`.
- **BLOCKED** names a `reason` and `blockedBy`.
- **READY** must contain all of the following (`S007`):
  - `candidate.commit`: a full 40-hex SHA;
  - `cases`: a `passed` result for every registered case of the family;
  - `tests`: each with `project`, `total` > 0, and `failed` = 0;
  - `websiteExamples`: at least one checked page or anchor;
  - `reviews`: each with `reviewer` and retained `record`;
  - `approver`: `login` and `approvalUrl`;
  - `independence`: `"reduced"`;
  - `blockersResolved`: a `reference` for every family blocker, including #1423.

**Denominator rule.** `denominatorV1` freezes the 35 registered cases across the six families, with
expected outcomes and fixture hashes. Its SHA-256 is pinned in the test. Later changes are
amendments with a version, UTC date, PR, justification, and `afterInspection`.

- A removed case or family stays listed in `removedCases`/`removedFamilies` with its last status.
- A changed expected outcome needs `reclassifiedCases`. A changed fixture needs `rehashedCases`.
- Failure alone is not a reason to move a case out of scope.
- Adding cases is allowed. Deleting from `denominatorV1` fails the pinned seal.
