## Mechanism

An invocation of a function-typed VALUE — `§C{f}` / `§C f §A x §/C` where `f` is a
parameter, a `§B`, a field, or `§C §C{GetF} §/C §/C` (the result of a call) — is no longer
Calor0418 `DelegateInvocation`. The value's effect row is read from the declaration that put
it in scope and charged to the invoking function **inside inference**
(`EffectInferrer.ChargeInvokedRow`, called from `InferFromBareNameTarget` and the
returned-value arm of `InferFromExpressionCall`), where every other call is charged — so it
flows through the SCC fixpoint, into a `§LAM`'s ρ_body when the invocation sits inside a
lambda, and into Calor0410 with no extra propagation step. Diagnostics (as opposed to
charges) go through `EffectEnforcementPass.InvocationSink`, which de-duplicates by
(function, span, message) so an SCC iteration or an on-demand re-inference cannot emit twice.

| Row at the invocation | Charged | Reported |
|---|---|---|
| `Concrete(S)` | `S`, with §10.1's provenance clause for Calor0410 | nothing |
| `Assumed(S, R)` | `S` | one Calor0425 carrying `R` (§4.4) |
| `Unknown` | `EffectSet.Unknown` — fail-closed, as an unknown external call; **nothing** under `--permissive-effects` | Calor0425 at the invocation (suppressed under the flag) |
| provably not a function (`i32`, `str`, `[T]`) | nothing | **Calor0418, retained for this residual only** — an error under every policy |

**Where the row comes from.** The declaration's own `§E{…}` node (`PolyRow.From`): a
parameter's suffix row; a `§B`'s own row, else its initializer's — a `§LAM`'s declared row or
ρ_body (§3.5/§5), an in-module callee's declared return row, one alias hop, a monomorphic
method group's declared `§E`; a field's row. Function-typedness is asked of the bound
`FunctionBoundType` first (`CallGraphAnalysis.DeclaredFunctionTypes` / `DeclaredFieldFunctionType`)
and the type string second — the same order `RowSiteChecker.IsParameterFunctionTyped` uses,
so A2's `§CSHARP`-declared `RequestHandlerDelegate<TResponse>` is a function value here
exactly when it is a site there. The row is read as the node rather than as
`FunctionBoundType.Row` because `Binder.BindRow` collapses a variable-mentioning row to Unknown
(E2b's decision) and `f §E{e}` invoked inside a rank-1 `Map` must charge `e`, not Unknown. A
variable the row mentions must be one of the invoking declaration's own binders (a totality
guard: the parser's Calor0404 already keeps a parameter row inside its declaration's `eff` list).

**Why fail-closed for Unknown, against the task text's "charging nothing".** The orchestrating
task described Unknown as "Calor0425 … charging nothing"; the design doc says otherwise at
three places — §13.1's first row ("Calor0425 at the parameter + Calor0410 at `§E{}`"), §6.4's
P22-pinned second sample ("Invoking a value whose row is Unknown charges Unknown to 'Run'"),
and §3.5's reason for Unknown existing at all ("defaulting to pure re-opens the hole PR #968
closed"). Charging nothing would have turned every row-less invocation from an error into a
warning in the default mode — a program printing under `§E{}` everywhere with only warnings —
which is the hole, re-opened at the one place it was closed. The design was followed; E3b's
"nothing is charged" for an undetermined site-6 variable stands as its own disclosed
deviation. The switch is one line (`ChargeInvokedRow`, the `IsUnknown` arm) if review decides
otherwise.

**Calor0424 is never reported at an invocation.** §6.2's site table has no invocation row
because there is no destination row to fit into; the under-declared caller is the ordinary
Calor0410. Pinned by `MessageTexts_Calor0410_InvocationProvenance_IsTheDesignDocSample`
(asserts 0410 with provenance and the absence of 0424).

## Calor0418 — the code decision

**Retained, for exactly one residual: invoking a value whose type is provably not a function
type** (`TypeIdentity.IsProvablyNonFunctionType`). Measured before deciding: the binder does
NOT reject `§C{x}` on an `i32` parameter (probe compiled clean through binding and reached
the effect pass), so this code is the only guard; and an external nominal type the binder does
not know (`MyExternalDelegate:cb`) is not provable either way, so it is Unknown → Calor0425,
never the residual. The code's doc comment says all of this; pinned by
`DiagnosticCodeTests.Calor0418_IsRetainedForTheProvablyNonFunctionResidual` (reads the
catalogue: the constant exists, equals `Calor0418`, and its doc comment names the residual)
and by `StrictnessBatchTests.Invocation_ProvablyNonFunctionValue_IsTheResidualCalor0418_NeverWaived`
(error under default AND permissive) / `Invocation_NotProvablyFunctionTyped_IsUnknown_NotTheResidual`.
Removing the code entirely was rejected because that would leave `§C{x}` on an `i32` silently
pure under enforcement. The old message ("function-typed values carry no effect contract") is
gone; Calor0411's advice text no longer says "delegate invocation is disallowed (Calor0418)".

## Residuals (named, not fixed)

1. **A row-less `§B` assigned from another value after a fitting hop.** `RowSiteChecker`
   tracks §4.4's `Assumed`-after-`Fits` in its `_scope`; the inferrer reads the binding's
   DECLARED row at the invocation. When the binding declares a row, the two agree by
   construction (the declaration is the contract; the hop reported the assumption once — the
   §4.5 answer). When the binding declares no row and its initializer is an alias of an
   `Assumed` parameter/field, the inferrer reads the alias's declared row, so an assumption
   carried only in `_scope` would not be re-reported at the invocation. No source-level shape
   produces an `Assumed` parameter or field row today (only ρ_body and method groups are
   `Assumed`, and a method group is rejected as a `§B` initializer), so this is a description
   of a seam, not an observed miss.
2. **A `§LAM` inside a rank-1 function that invokes the polymorphic parameter** (`f §E{e}`
   inside a lambda inside `Map`): ρ_body is an `EffectSet` and cannot carry `e`, so the
   lambda's row under-approximates if the lambda escapes. Not reachable from the fixtures;
   §7.3 territory.
3. **`PolyRow.Fits` on an Unknown destination with a variable-mentioning source** answers
   `DoesNotFit` (Calor0424) rather than `CannotTell`, because the ordinal containment test
   runs before the lattice's Unknown check. Observed on the L7-MID mutant at (16,26) —
   `§C{RunTwice} §A next` with `next §E{e}` into a now row-less `g`. E3b's relation, not
   changed here; the L7 cell detects on its registered Calor0425 regardless.
4. **The 619 vs 1 Calor0418 count** E3b's notes left open: this harness reads 1 on both sides,
   agreeing with E3b. The two instruments differ only in the CLI's binder gate; stated as the
   plausible cause, not measured.
5. **Calor0410 is still demoted to a warning under `--permissive-effects`** (pre-existing
   `CheckEffects` behaviour); E4 charges rows under the flag and the demotion applies to the
   resulting 0410 exactly as to every other.
6. The Calor0419 "passes function-typed value … which may invoke it with unverifiable
   effects" assumption at BCL argument sites is untouched (§10.2 forecasts its 0425 future;
   out of E4's scope).
