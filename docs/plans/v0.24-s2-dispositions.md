- **FIX** means the verifier now gives the outcome the oracle supports: a true claim proved, or a
  violated claim refuted with an input that reaches it. **DEMOTE** means the form visibly becomes
  `Assumed` or `Unsupported` (or refused), the guard is kept, and no claim is made. A demotion
  withdraws a claim; it does not prove the property.
- **VALIDATED** is used only for the 79 `CLEAN-WITHIN-BUDGET` rows, including the 5 control rows. It
  means "no counterexample within this matrix and budget". Each row records `validatedProofCases`.
  Rows with 0 support no claim that relies on `Proven`/`Discharged`: on B1 and N1, 44 of the 79
  clean rows have no validated-proof case, including all assumed and refused rows.
- **NOT-INVESTIGATED** is used only for the 7 `XCL-*` rows that the frozen scope excluded.
- A row with findings takes the most conservative disposition among them.

## Spurious refutations

These are not soundness defects. The frozen vocabulary has no "known incompleteness" value, so each
one is fixed or demoted like any other finding. FIX applies where the model now reaches the
obligation or the claim is proved: else facts, named-refinement facts, UTF-16 literals, and the
Substring range. DEMOTE applies where the result is `Unsupported` or `Assumed` instead of a `Failed`
compile error with an unreachable counterexample.

## R-NUM: decision required (5 findings per baseline)

`NUM-NARROW-ARITH` and `NUM-LITERAL-OVERSIZE` are registered `unsupported-refused`; the frozen
modeled-forms doc lists them as divergences D1 and D2, "refused". `NUM-OVERFLOW-CHECKED` is
registered `assumed`.

The verifier deliberately does something else:

- it models C# narrow promotion (W1 Slice 1);
- it types `INT:` literals the way C# does (#774);
- it proves checked-arithmetic contracts whose preconditions rule out overflow. The row title says
  "unless entailed", but the frozen classification table counts any `Proven` on an `assumed` row.

Every one of these `Proven` results agrees with the oracle; none is a false proof. Under the frozen
table each is still a finding, and `VALIDATED` is not allowed.

A draft that implements the registered refusals is `docs/plans/evidence/s2-1413/r-num-draft.patch`,
written against `0142438f` (77 added and 4 removed non-test lines). It breaks 19 existing tests that
pin the deliberate semantics; the record names each one. It also changes the committed #1135
differential oracle reports. Options:

1. Accept the demotion as R-NUM, using the reserved sixth slot.
2. Make an amendment, after decision-bearing inspection, to the contract and to the frozen #1419
   registration classifications for the three rows, keeping the S1 findings on record.
3. Record `MILESTONE-FAILED` (terminal predicate 5 then fails).

## Discovery finding outside the registered sweep

**#1493:** on Windows, non-ASCII identifiers can collapse into one Z3 symbol through ANSI marshaling.
This could produce a false proof. It was found by code reading during #1135, was not executed by S1,
and is not part of the registered sweep. Disposition: `FIX-IN-0.24` by R-TEXT (an injective ASCII
symbol encoding). Its end-to-end witness runs on Windows in the z3-consumer-matrix job. The record
lists #1493 under `requiredDiscoveries`, so it cannot be dropped silently.

## Review-found discoveries (MILESTONE-FAILED pending decision Q7)

Two spurious-refutation residuals of the obligation solver were found or confirmed in R-OBL's
review. Neither is a false proof, because facts use the global heap rule, so no false `Discharged`
can result. Neither was executed or observed. Under the frozen rule every finding is fixed, visibly
demoted, excluded by scope, or fails the milestone. R-OBL is past its review ceiling, and the
six-PR capacity is allocated. Both are therefore recorded as `MILESTONE-FAILED` until a decision.

- **D-OBL-PROOF-GETTER.** In a `§PROOF` counterexample, reads inside the proof condition count as
  its evaluation. Two cases can make the model unreachable and produce a spurious `Failed` compile
  error: a getter there that writes state the same condition reads later, and a property hiding an
  inherited field (which the translator models as the field).
- **D-OBL-THROWING-PREDECESSOR.** An earlier statement that throws implicitly is not tracked, so a
  model that statement would stop can be reported. This is pre-existing on B1/N1.

The options (Q7) are:

1. Amend the contract to add a recorded known-limitation path.
2. Spend the reserved sixth slot on a demotion instead of R-NUM.
3. Accept `MILESTONE-FAILED`.

Under the current record, closure would therefore be `MILESTONE-FAILED`.
