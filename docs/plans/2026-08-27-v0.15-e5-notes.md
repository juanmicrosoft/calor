## Mechanism — one producer, two consumers (design §8.5)

The **producer** is the compilation's own effect pass. `EffectEnforcementPass` gains a
phase 5, `ProjectDeclarationFacts`, which projects what phases 2–4 left behind into
`DeclarationFacts`: per declaration (keyed by the pass's structural function id — `f001`,
`Cls.m001` — never by name) the declared row (concrete part + `eff` binders by ordinal),
the inferred row (`_computedEffects` as a row: Concrete, Assumed with the D-W2.3 reasons, or
Unknown), the verdict, the diagnostic code phase 4 reports, and the undeclared surface
codes. The verdict is the pass's own: `DoesNotFit` exactly when `CheckEffects` reports a
forbidden effect, `CannotTell` when the computed set is Unknown (phase 4 still reports
Calor0410 `'unknown'` there — §3.5's fail-closed answer — which is why the code travels
beside the verdict instead of being derived from it), `Fits` otherwise (Calor0419 as the
code when the fit rests on assumptions). Nothing re-implements inference.

The **two consumers**:

1. `EffectSummary` (build cache, cross-module pass) — unchanged in what it carries, changed
   in how it is keyed (P26 below). It is built from the AST + `ExternalCallCollector` as
   before; the index never feeds it (P25).
2. `ProjectIndex.EffectRows` — `ProjectIndexBuilder.RecordEffectRows` runs the per-module
   pass over each bound document (Strict policy, the project directory's manifests, the
   driver's own `BuildCrossModuleFunctionMap` so a call into another file is not
   "unknown"), maps each fact to the bound `FunctionSymbol` whose `DefinitionSpan` starts
   where the fact's declaration does (event accessors share their event's span; the
   collision is settled by name), and records one `IndexedEffectRow` per declaration.
   Cross-module callees are folded in through the cross-module pass's OWN resolution:
   `CrossModuleEffectEnforcementPass.ResolveCrossModuleEffects` (a projection of
   `CheckCaller`, which now shares `ResolveCallerCallees` with it) yields the declared
   effects of each caller's cross-module callees keyed by `CallerId`; the index joins them
   into the inferred row and applies `EffectRow.Fits` (the same relation `VerifyEffects`
   uses — P16) for the verdict. So `calor query effects Run` says what `calor build` says.

A file the binder reports errors for gets no rows and a `Residual.EffectRowsUnavailable`
entry (`IndexedDocument.BindHadErrors` is new): the CLI skips the effect pass on such a
file, and rows the CLI never computed would be an answer with no producer. A pass that
throws is recorded the same way.

### The facet's shape (`ProjectIndex.cs`, nested types)

`IndexedEffectRow { SymbolId, OwnerSymbolId, Name, Kind, Declared, DeclaredRow,
InferredRow?, Verdict, DiagnosticCode?, Forbidden[], BoundRow?, File, Line }` with
`IndexedRow { Display, State (concrete|assumed|unknown), Effects[], Variables[{Ordinal,Name}],
Reasons[] }`. Kinds: `function`, `method`, `constructor`, `accessor` (declaration-level:
inferred row + verdict), and `parameter`, `return` (position-level: declared row only,
verdict `declared-only`, plus `BoundRow`). A parallel list rather than fields on
`IndexedDeclaration`: positions have their own symbol ids but a `return` position has none
(it is recorded under its owner's id with `OwnerSymbolId` set), and a declaration can own
several rows — a per-declaration field cannot carry that.

## `calor query effects <name>` and `calor query impact --effects`

Same envelope as the other facets — indented lines, then a `query:` summary, then the
residual when the answer is partial (partial = an unresolved call inside the subject, or
the subject's file has no rows). `--json` wraps the index's own rows in the schema-v1.1
envelope (`EnvelopeWriter`, command `query`), so text and JSON cannot disagree.

```
  app.calr:11:11 function Leaky
    declared: [pure]
    inferred: cw
    verdict:  does not fit — Calor0410 fires (undeclared: cw)
query: effect row of app.calr:11:11 function Leaky — declared [pure], inferred cw, does not fit — Calor0410 fires (undeclared: cw)
```

`calor query impact <name> --effects [--row cw,fs:w]`: `FindImpactOfDeclarations`'s closure,
**unchanged**, joined with the verdict of fitting the hypothetical row (default: the
subject's current declared row; `--row ""` is pure) into each affected caller's DECLARED
row. `ProjectIndex.FindEffectImpact` is the join; a caller with no recorded row is
`CannotTell`.

```
  app.calr:17:11 function Fan — declares cw: does-not-fit
  app.calr:11:11 function Leaky — declares [pure]: does-not-fit
  app.calr:14:11 function Relay — declares cw: does-not-fit
impact: 3 of 3 affected declaration(s) would stop fitting a row of fs:w on app.calr:8:11 function Log
```

**A pre-existing index gap, fixed because gate 7 observes it.** `ProjectSymbolIndex`
recorded call edges for `BoundCallExpression` only. A call STATEMENT — `§C{Log} §A x §/C`
on its own line, the common shape of an effectful call — produced no edge and no residual
entry, so `callers Log` answered "no callers" and the blast radius was empty exactly where
it matters. The edge loop now takes `BoundCallStatement` too (same Target /
ResolvedSymbols / CalleeSpan). Occurrences are NOT touched (rename's corpus oracle decides
what rename edits). No existing golden changes: the gate-3 fixture had no statement calls.

## P26 — `NoNameKeyedEffectStoreRemains`

`EffectSummaryBuilder.cs:68,:75` — `AppendCallerSummary(…, function.Name, …)` and
`$"{cls.Name}.{method.Name}"` as the grouping key — are gone. `RawCall` carries `CallerId`
(the structural id `ExternalCallCollector` assigns exactly as `CallGraphAnalysis.ToFunctionNode`
does); the builder groups by it; `EffectCallerSummary` has `CallerId` + `DisplayName` and no
`CallerName`. The cross-module diagnostics print `DisplayName`, so their text is
byte-identical. Three legs in the pin: reflection (no `CallerName` property), a source
regex over the builder (groups by `call.CallerId`, never passes `.Name` as `callerId:`),
and the behavioural discriminator — two overloads `Box.Run(i32)` / `Box.Run(str)` are TWO
caller entries (`Box.m001`, `Box.m002`) with one display name; under a name key they were one.

What "symbol-keyed" means here, precisely: the structural declaration id (`f001`,
`Cls.m001`), which is the key E1–E4 built the pass on and the `ast:` component the binder's
`SymbolId` embeds — not the full `calor://…` `SymbolId`, which needs a bound module the
summary builder (an AST projection consumed by the build cache) does not hold. The
`CrossModuleEffectRegistry`'s lookup by call-target text is a RESOLUTION index (text →
declaration), not a store keyed by name; P26 targets the caller store, as its text says.

## Residuals (named, not fixed)

1. **A declaration the builder cannot map to a bound symbol is silently absent** from
   `EffectRows` (the fact exists in the pass; the span match failed). Measured on the
   QueryCorpus fixture and the E5 unit fixtures: none unmapped. Event accessors share their
   event's span and are settled by name; an unnamed collision would drop a row without a
   residual entry.
2. **The index runs the pass on files with binder WARNINGS** (only errors skip it), which is
   the CLI's behaviour too.
3. **`impact --effects` compares against the caller's DECLARED row only.** A caller whose
   declared row is `[unknown]` (a constructor or accessor: no `§E` surface — the index records
   their intrinsic contract as the declared row) answers on that contract. A caller with no
   recorded row (its file's rows are unavailable) is `cannot-tell`.
4. **Manifests:** the index builder initializes the resolver with the PROJECT directory's
   manifests, as `calor build` does per file with `ProjectDirectory`; solution-level
   manifests are not consulted (the index has no solution notion).
5. **Cost:** the index build now runs the effect pass per file (what `calor build` runs). Not
   measured against gate 8's 30-second envelope on a large project in this PR; the
   QueryCorpus builds in well under a second.
6. **`--json` on the other facets** is not added; only `effects` carries data the text
   cannot round-trip.
7. **Hover** (SHOULD) not done — see "Deferred".
