## Findings (verbatim)

1. **MAJOR — Checkout pinning accepts stale compiler builds.** `scripts/checkout_compiler.py:84–101` checks timestamps only for tracked files with four suffixes. It ignores embedded effect manifests, `Directory.Packages.props`, root targets, untracked C# additions, and deleted sources. Changing `src/Calor.Compiler/Manifests/*.calor-effects.json` can therefore leave the old effect rules running while provenance records the current HEAD. These manifests are embedded by `src/Calor.Compiler/Calor.Compiler.csproj:151`. **Fix:** validate a build-produced content fingerprint covering the complete compiler/runtime input set and dependencies, including additions and deletions; bind it to the output hashes. Add controls for resource changes and removed sources.

2. **MAJOR — Negatives pass with diagnostics from the wrong cause.** `scripts/fixture_compile_check.py:91–102` reduces diagnostics to unique codes, discarding file, declaration, span, message, and multiplicity. The ES-04 negative explicitly expects a cross-module error on the **caller** (`eng/tier2-fixture-expectations.json:1280–1290`), but an unrelated `Calor0410` on the callee satisfies it. I confirmed in memory that both a wrong-file error and an additional same-code failure return `expected-negative`. Newly broken members can silently pass inside negative workspaces. **Fix:** register and compare diagnostic identities and multiplicities, using normalized paths, declaration IDs, and relevant message/span constraints. Add wrong-file and extra-same-code controls.

3. **MAJOR — Compiler failure evidence is discarded.** `scripts/fixture_compile_check.py:181–182` returns an empty detail for normal compiler failures; `run_unit` captures stdout/stderr and returns only the signature (`:209–223`). Report rows retain only that signature (`:289–304`), and the temporary generated outputs disappear. Consequently, a newly broken positive leaves CI artifacts containing codes without the diagnostic messages or locations needed to investigate it. **Fix:** preserve structured diagnostics, exit code, stdout/stderr, and available generated C# for failing units in the uploaded evidence.

4. **MAJOR — Negative controls never exercise the migrator’s byte-preservation guards.** `scripts/test_tier2_verification.py:262–276` uses a fake migrator that rewrites nothing. Every available-migrator case exits at the control-file check, before the tracked-file comparisons in `scripts/migrator_corpus_dryrun.py:127–133` or `scripts/migrator_revert_roundtrip.py:119–132`. Removing those comparisons leaves these tests passing. Likewise, `test_unavailable_is_never_ok` (`:278–281`) tests formatting, never either driver’s exit aggregation. **Fix:** implement successful fake forward/revert behavior, then inject dry-run writes and post-revert corruption. Invoke both drivers with failing/unavailable child exits and assert nonzero final exits.

5. **MINOR — The dry-run’s tracked-only claim is false.** `scripts/migrator_corpus_dryrun.py:110–115` passes the original repository directory to `calor fix`. Its enumeration (`src/Calor.Compiler/Commands/FixCommand.cs:593–597`) excludes `bin`/`obj`, but includes other untracked `.calr` files. Only tracked files are subsequently checked for modification. This contradicts the script’s selection claim at `scripts/migrator_corpus_dryrun.py:9–11` and makes its execution scope differ from its reported scope. **Fix:** run against a scratch copy containing exactly the tracked selection, as the revert checker already does.

Verdict: **REQUEST CHANGES — stale-build acceptance, wrong-cause negative acceptance, and failure-evidence loss remain.**

## Response

1. **Fixed.** `checkout_compiler.resolve` now treats every non-ignored file (any type, tracked or untracked) under `src/Calor.Compiler` and `src/Calor.Runtime`, plus `Directory.Build.props`, `Directory.Build.targets`, `Directory.Packages.props`, `global.json`, and `NuGet.config`, as a build input; any input newer than the DLL, or any deleted tracked input, refuses the build. New controls: an added resource and a deleted source both refuse. Not done: a content fingerprint of the inputs bound to the DLL. Freshness stays mtime-based, and the README states this limitation.
2. **Fixed.** A signature is now one `file|code` entry per error, sorted, with duplicates kept. All 60 negative and known-failure entries were re-registered from a fresh run, and a script checked that each entry's code set is unchanged. ES-04 step 1 now expects `caller.calr|Calor0410`. New controls: an error from the other file of a workspace fails, and one extra error of the same code fails. Declaration IDs and spans are not compared; file and multiplicity were judged enough to bind the cause, and adding more would make the signatures platform-fragile.
3. **Fixed.** Non-success rows carry `errorDiagnostics` (file, line, code, and message truncated to 300 characters) in the uploaded report. A crashed row's detail keeps the stderr tail. Generated C# is not retained.
4. **Fixed.** The fake `fix` now rewrites and reverts. New controls: a passing run returns 0; a dry run that writes fails ("changed despite --dry-run"); a revert that corrupts a file fails ("byte-mismatch post-revert"); and the checkout is asserted unmodified after every case. `test_drivers_never_pass_an_unavailable_or_failed_step` runs `verify_phase1.main` and `verify_corpus.main` with every step returning 1, 2, or 3 and asserts exit 1.
5. **Fixed.** The dry run now runs on a scratch copy holding exactly the tracked selection plus the control.

Mutation check after the fixes: 26 of 26 single-line mutations are killed. That set adds file-dropping, duplicate-collapsing, diagnostics-dropping, deleted-input, untracked-input, dry-run-write, and revert-compare mutations.
