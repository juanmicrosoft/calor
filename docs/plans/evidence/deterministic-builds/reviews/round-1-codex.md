## Review text

1. **Major — The publication toolchain still floats.** `.github/workflows/reproducible-builds.yml:39` selects `10.0.x`, line 90 selects Node `20`, and both jobs use `ubuntu-latest`. `global.json:4` permits SDK roll-forward. Two builds within one job can agree while publication later uses a different compiler, NuGet, Node, or native SWC binary and rejects the adjudicated hashes. The recorded proof uses macOS/Node 26 and explicitly lacks the Linux publication comparison (`docs/plans/evidence/deterministic-builds/README.md:92`). **Fix:** pin the build environment, exact SDK, Node and npm versions across adjudication, proof and publication; regenerate evidence in that environment.

2. **Major — `--z3 copy` imports unchecked build inputs into “fresh” clones.** `scripts/reproducible_builds.py:92` copies entire ignored `z3/` and `runtimes/` directories. The verifier checks only six named assets (`scripts/verify-z3-assets.py:53`), so extra files survive verification. An ignored `z3/Injected.cs` would enter the compiler’s default `**/*.cs` compilation glob; both proof builds could then agree on packages containing code absent from the commit. I confirmed default compilation is enabled and those directories are not excluded. The existing hermetic guard passes because it does not inspect this copy operation. **Fix:** copy only the registered, pinned asset paths, verify them, regenerate provenance, and add a negative test containing an extra `.cs` file.

3. **Major — The build ID no longer distinguishes different deployments reliably.** `website/next.config.js:21` uses only `website/package.json`’s version. `scripts/bump-version.sh:30` updates the .NET version but never updates the website version; the publication gate does not enforce their equality. Different releases can therefore retain `calor-0.24.0`. Next’s router uses a changed build ID to fall back to full navigation when an existing browser receives another deployment’s Flight data; reusing the ID defeats that check and also reuses manifest URLs. [Next 14 router source](https://raw.githubusercontent.com/vercel/next.js/v14.2.35/packages/next/src/client/components/router-reducer/fetch-server-response.ts). **Fix:** derive the ID from the candidate commit, supplied consistently to adjudication and publication. Test deployment changes as well as repeated builds.

4. **Minor — Path normalization misses JSON escaping followed by URL encoding.** `website/reproducible-module-ids.js:32` generates raw, URI-encoded and JSON-escaped forms separately, but omits the URI-encoded JSON-escaped form. Next actually JSON-stringifies requests before encoding its loader query. [Next loader construction](https://raw.githubusercontent.com/vercel/next.js/v14.2.35/packages/next/src/build/webpack/plugins/flight-client-entry-plugin.ts). I exercised `apply()` with that query format: `/tmp/check"out/calor` and `/tmp/other/calor` assigned IDs **255** and **667**. Windows backslashes also survive normalization. **Fix:** handle composed escaping and separator variants, preferably by decoding and normalizing query fields; test actual ID assignment with these paths.

5. **Major — Empty or incomplete publication outputs can pass comparison.** `scripts/reproducible_builds.py:138` adds a website tree key even when the export contains zero files. Consequently, the empty-output check at line 148 never fires. I reproduced `hash_build()` producing an empty website digest and `compare(h, h)` returning `[]`. Two metadata-only package outputs likewise pass. `scripts/test_reproducible_builds.py:191` tests only the completely absent-output case. **Fix:** validate the requested target’s inventory before comparing: both expected packages and metadata documents, or a nonempty website with required entry files. Add missing-*both*-builds and empty-directory controls.

6. **Minor — An ambient variable overrides the supposedly fixed pack timestamp.** `Directory.Build.props:34` assigns the constant only when `DeterministicTimestamp` is empty. MSBuild imports environment variables as properties. I ran property evaluation with `DeterministicTimestamp=2025-02-03T00:00:00Z` and obtained that value. `SOURCE_DATE_EPOCH` alone is correctly ignored. **Fix:** remove the condition; explicit command-line global properties can still override an unconditional project assignment. Test ambient-variable rejection and explicit override separately.

7. **Minor — CI omits the environmental variation implemented by the proof helper.** `.github/workflows/reproducible-builds.yml:52` and line 55 run both builds with the same HOME, NuGet cache, npm cache, time zone and locale. They never invoke `run_proof()`’s isolation. Thus CI can remain green after introducing a HOME or time-zone dependency. **Fix:** use the isolated proof runner, or supply distinct environments and caches to each build; vary locale and `SOURCE_DATE_EPOCH` deliberately.

8. **Minor — The workflow’s path filter omits actual publication inputs.** `.github/workflows/reproducible-builds.yml:11` excludes `README.md` bundled into Calor.Sdk, `docs/assets/calor-icon.png` bundled into the tool, and the embedded resources referenced at `src/Calor.Compiler/Calor.Compiler.csproj:163` and line 166. It also excludes publication-workflow and bootstrap-action changes. These PRs can change publication inputs or procedures without running the proof. **Fix:** remove the filter or cover the complete input set and publication tooling.

Eight configuration tests and the Z3 workflow guard passed. Full builds were unavailable in the read-only workspace. Node availability is not a current CI failure—the Ubuntu runner includes Node. [Runner inventory](https://raw.githubusercontent.com/actions/runner-images/main/images/ubuntu/Ubuntu2404-Readme.md). I found no concrete shallow-clone failure or standalone manifest break caused by `[contenthash]`.

VERDICT: CHANGES REQUESTED
