## Findings and dispositions

| # | Finding (repro) | Severity | Disposition |
|---|---|---|---|
| 1 | `new P { A = i++ }` where `P()` writes `i`: the postfix hoist runs before the constructor, so `A` reads the old value. Assignments and nested hoists have the same exposure. | major (silent) | Fixed. The syntactic hoist predicate is gone. `ConvertObjectCreation` and `ConvertImplicitObjectCreation` record `_pendingStatements.Count` before the arguments and initializer values are converted. If any value adds a pending statement, the hoists (including the arguments') are rolled back and the whole creation is kept as C# (`RollBackAndPreserveObjectInitializer`). Test: `Counter = 0; new PI { A = Counter++ }` → `10:11`. |
| 2 | Parentheses bypass the syntactic check: `new() { L = (new List<int> { 5 }) }` became `new List<int>(5)` (capacity, no elements). | major (silent) | Fixed. The target-typed path now checks the converted node (`IsBlockLevelCollection`) instead of syntax, and preserves instead of calling `ConvertBlockLevelCollectionToNew`. The explicit path is covered by the rollback in #1. Test: `q = new() { L = (new List<int> { 5 }) }` → `k7k5`. |
| 3 | Constant elements do not make a hoisted collection effect-free: `new P { L = new List<V> { 1 } }` with a user implicit conversion `int → V` ran `v` before `k`. | major (silent) | Fixed by #1: any hoisted value now preserves the creation. `HasOnlyConstantOperands`/`IsInSimpleStatement` are deleted. Cost: `new P { L = new List<int> { 1, 2 } }` is now preserved as C# rather than converted natively. Tests: `PV { L = new List<V> { 1 } }` → `kv1`; the `List<int>{1,2}` row is now an interop row. |
| 4 | `new List<int> { Capacity = 20 }` went through `ConvertListCreation`, which treated `Capacity = 20` as an element (and assigned an outer `Capacity` field). | major (silent) | Fixed. The List/HashSet/Dictionary specializations now require `SyntaxKind.CollectionInitializerExpression`; an object initializer on `List<T>` takes the native `§NEW` path. Test with a same-named outer `Capacity` field → `0:20:0`. |
| 5 | Direct interpolation `$"{X()}{new P { A = 5 }.A}"`: the emitter hoisted the preserved `§CS` receiver before the `X()` hole. | major (silent) | Fixed. An interpolated string whose holes contain a creation with a non-empty initializer is preserved whole as C# (`ConvertExpression` switch arm). Test: `var text = $"{X()}{new P { A = 5 }.A}"` → `15xk`. |
| 6 | Static auto-property default `Prop { get; } = new P { A = Later }` declared before `Later`: emitters group fields before properties, so initialization order changes. | major (silent) | Not changed; pre-existing and not initializer-specific. The same reorder happens for `Prop { get; } = Later + 1` on main. Member ordering across fields and properties belongs to the emitters' member grouping, outside #1524. Recorded for the caller as a follow-up. |
| 7 | `default(float)` and `default(decimal)` became `0.0` (a double) after the float fix: `default(float) + 2f` boxed a `Double`; `default(decimal) + 2m` did not compile. | blocker | Fixed. `ConvertDefaultExpression` emits `SINGLE:0` for `float`/`Single` and `DEC:0` for `decimal`/`Decimal`. The float oracle now compares runtime types (`Single:2`, `Decimal:2`, `Double:2.5`, `Int32:2`) and includes `1 / 3f` → `Single:0.33333334`. |
| 8 | Attribute arguments bypass `Visit(FloatLiteralNode)`: `[Kind(2.0)]` became `[@Kind(2)]` and selected the `int` overload. | major (silent) | Fixed. `CalorAttributeArgument.FormatSingleValue` (C# form) writes `2.0`, `2f`, `2m` with invariant culture. The new `GetCalorFormattedValue` (Calor form, used by `CalorEmitter`) writes `2.0`, `SINGLE:2`, `DEC:2`. Test: `[Kind(2.0)]`, `[Kind(2f)]`, `[Kind(2)]` → `double,float,int`. |
