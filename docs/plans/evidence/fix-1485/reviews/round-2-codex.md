# Fix #1485 — Codex adversarial review, round 2

- Reviewer: `codex exec -s read-only --ephemeral -c model_reasoning_effort="high"`, diff `origin/main...HEAD` on stdin.
- Verdict: **changes-required**. Codex confirmed all five round-1 repros now pass. It reproduced each finding below against the patched DLL.

## Findings and dispositions

| # | Finding (repro) | Severity | Disposition |
|---|---|---|---|
| 1 | A body on the last line of a multi-line bracketed header was lost. One repro is `§F{f1:A:pub} (` / `bool:x` / `) -> i32 §R 1`, which reports `Calor0100`. Another is `§IF{i} (==` / `1 2` / `) §P "then"`, where "then" was emitted outside the `if`. Ownership checked the opener's line, not the header's last line. | major | Fixed. `BlockOwner.HeaderLine` records the line on which the header ends. Content on that line belongs to the body, and the flat-closer scan starts after it. Tests: `MultilineHeader_BodyOnHeaderLastLine_StaysInBody`, `MultilineFunctionHeader_BodyOnHeaderLastLine_StaysInBody`. |
| 2 | Inside braces (`() → { … }`) the lexer emits no Dedent. An outer `§EL` after an empty inner `§IF` attached to the inner `§IF`, so the program returned 0 instead of 1. The same applied to `§CA`/`§FI` chains. | major (silent) | Fixed. A chain continuation (`§EI`/`§EL`, `§CA`/`§FI`, `§PPE`) now belongs to a chain only if its line is not shallower than the chain's opener (`ContinuesChain`). Test: `BracedLambda_OuterElseAfterEmptyInnerIf_BelongsToOuterIf` (executes, returns 1). |
| 3 | An empty member-level or type-level `§PP{DEBUG}` swallowed the next `§MT` or `§CL`. | major (silent) | Fixed. `ParseMemberPreprocessorBlock` and `ParseTypePreprocessorBlock` now use ownership for their `§PP` and `§PPE` bodies. Tests: `EmptyMemberPreprocessorBlock_DoesNotSwallowSiblingMethod`, `EmptyTypePreprocessorBlock_DoesNotSwallowSiblingClass`. |
| 4 | An empty `§EEXT` adopted the next same-column `§F` as an extension method. | major (silent) | Fixed. Ownership now applies to `§EEXT`, with the legacy column-1 layout kept lenient. Test: `EmptyEnumExtension_DoesNotAdoptSiblingFunction`. |
| 5 | `§LAM{lam1}` without a closer took the next same-column `(inc n)` as its expression body, so the program returned 0 instead of 1. | major (silent) | Fixed. Lambda ownership is computed before the expression body, and that body must be owned. Test: `BlockLambda_WithoutCloser_DoesNotTakeNextLineAsExpressionBody`. |
| 6 | The flat-closer scan skipped nested openers on the header line. In `§SYNC{s1} (a) §SYNC{s2} (b) …` / `§/SYNC{s2}`, the scan treated `s2`'s closer as `s1`'s. | major (silent) | Fixed. Header-line tokens are scanned for nested openers and ids. A closer on the header line that is not a nested block's means "not flat". Test: `FlatCloserScan_TracksNestedOpenerOnHeaderLine`. |
| 7 | The closer scan was quadratic for many empty blocks without closers (8,000 blocks took 7.4 s). | minor | Fixed. The scan returns immediately when no closer of that kind occurs later in the file, using a last-index table built once per parse. `HasLambdaCloserAhead` uses the same table. Test: `ManyEmptyBlocksWithoutClosers_ParseWithoutErrors` (3,000 blocks). |
| 8 | Test gaps: `§FIXED` and `§PP` were missing from the matrix, nothing executed the nested-chain cases, and the empty `Action` lambda test only parses. | minor | `§FIXED` and statement-level `§PP` were added to both empty-clause theories. The braced-lambda case now executes. The empty-lambda test stays parse-only, because `() => default` for an empty `Action` lambda is a pre-existing emitter limit unrelated to #1485. |
