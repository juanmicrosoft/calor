# Codex adversarial review, round 1 (#1426 R0)

- **Reviewer:** OpenAI Codex CLI (`codex exec -s read-only --ephemeral -c model_reasoning_effort="high"`), cross-family adversarial review. Not an independent human review.
- **Input:** `git diff origin/main...HEAD` at `49128556` (generated Calor outputs omitted from stdin, readable in the tree).
- **Earlier attempt:** a first run at `2e13471c` stopped on a usage limit before giving a verdict. It left one interim note (missing ref/out negatives, local-function resolution, iterator disposal and reporting-mode rows). Those rows were added before this round; the attempt is not counted as a round.
- **Verdict:** REQUEST-CHANGES (2 BLOCKING, 5 MAJOR, 1 MINOR).

## Findings (verbatim)

1. **BLOCKING — The MCP “default” baseline is confounded by a nondefault option.** `docs/plans/evidence/v0.25-r0-1426/reproduce/reproduce.py:117` supplies `moduleName` only to MCP. `RoslynSyntaxVisitor.cs:4632` uses `_context.ModuleName` as the namespace identity for these namespace-free fixtures; `CSharpToCalorConverter.cs:1236` then requires that identity to match the original declaration before rescue. Thus the option can prevent rescue, including with `passthroughOnError=true`. The claim at `scope.json:815` that this is a “legitimate default difference” is unsupported. **Fix:** measure MCP with actual default arguments, retain custom-module-name behavior as a separate witness, and regenerate the affected baselines and issue recommendations.

2. **BLOCKING — READY accepts missing or meaningless required evidence.** `tests/Calor.Compiler.Tests/InteropScope/InteropScopeValidator.cs:244` treats an absent or wrongly typed `failed` field as zero through `Int()`. Empty project/reviewer/record/approver strings pass; `websiteExamples: [{}]` passes. Review records and example paths are never resolved. Moreover, extending the packet’s readiness vocabulary with another status bypasses the literal `status == "READY"` checks entirely (`:162`). **Fix:** freeze the vocabulary in code, require correctly typed fields and nonblank identities, resolve retained evidence, and add negative controls for these mutations.

3. **MAJOR — Denominator protection expires for added cases, and amendments grant permanent exemptions.** `tests/Calor.Compiler.Tests/InteropScope/InteropScopeValidator.cs:111` compares only `denominatorV1`. A later added case without a fixture can subsequently disappear without any removal amendment. `Amended()` at `:49` also lets one historical reclassification or rehash entry authorize arbitrary subsequent changes to that ID. No amendment invalidates affected READY evidence. **Fix:** validate versioned before/after denominators, bind each approved change to exact old/new values, and invalidate readiness when registered inputs or expectations change.

4. **MAJOR — S013 does not establish baseline integrity.** `tests/Calor.Compiler.Tests/InteropScope/InteropScopeValidator.cs:201` compares summary strings against unsealed results, trusting `matchesOriginal` at `:267`. Changing an original result, execution result, fixture hash in the results, or retained generated Calor can pass without detection. Deleting three surface entries from both a case’s baseline and its results also passes; only the remaining entries are checked. **Fix:** seal results, generated outputs, and producers; validate fixture/result correspondence and required surfaces; recompute behavioral equality from successful original/generated executions.

5. **MAJOR — Mandatory family rows remain outside the frozen acceptance denominator.** `docs/plans/evidence/v0.25-r0-1426/scope.json:818` onward uses broad F6 placeholders instead of the required per-surface defaults, both-enabled/disabled modes, aggregation, partial failures, and schema controls from [#1144](https://github.com/juanmicrosoft/calor/issues/1144). Other omissions include #1132’s supported/unsupported rank and initializer matrix and nested-expression rows, and #1139’s native illegal-accessor controls. The document’s “still required” prose does not make those requirements necessary for READY: the validator checks only registered cases. **Fix:** register explicit mandatory and unsupported rows now, permitting `not-measured` status, and require their complete results for family readiness.

6. **MAJOR — F5-ARRAY-04 does not discriminate generated-name collisions.** `docs/plans/evidence/v0.25-r0-1426/fixtures/F5-ARRAY-04.cs.txt:21` puts `_hoist000` in `Grid`, while the generated `_hoist000` occurs in `Run` (`generated/F5-ARRAY-04.mcp-default.calr.txt:26`). Those names cannot collide. In `Grid`, the returned array name is `arr2d006` (`:17–19`), while the parameter is `arr2d005`. Fixing expression-position emission could make this witness pass without exercising collision avoidance. **Fix:** place user storage matching the generated local name in the same lexical scope, observe both values, and verify that unsafe name allocation makes the witness fail.

7. **MAJOR — MET can be asserted without the promised amendment or completed registration.** `tests/Calor.Compiler.Tests/InteropScope/InteropScopeValidator.cs:186` accepts a FROZEN packet when each condition says `SATISFIED` with any nonempty evidence string. It requires neither the later amendment promised at `v0.25-interop-scope-and-baseline.md:43` nor actual interaction/documentation rows. It likewise does not validate retained #1413 closure evidence. **Fix:** require a decision-bearing gate amendment and validate each condition against its specific retained artifact and required registrations, rather than accepting assertions alone.

8. **MINOR — The website rejection classification is arithmetically wrong.** `docs/plans/v0.25-interop-scope-and-baseline.md:248` says three intended negatives plus “the other 7 non-parse rejections.” There are seven non-parse rejections total: `13 − 6`; subtracting the three intended negatives leaves four unclassified. **Fix:** change seven to four.

## Dispositions (fixed in the commit after this record)

1. **Fixed.** MCP calls now pass only `source` (plus the mode flag). With true defaults, MCP `passthroughOnError` rescues like the CLI. The custom-moduleName behavior is kept as a separate surface and a new row, F6-REPORT-11. F6-REPORT-03 and every MCP note were rewritten from the new results.
2. **Fixed.** Vocabularies are frozen in code and the packet must repeat them exactly. READY needs numeric `total` and `failed`, non-blank identities, website example pages and review records that exist in the repository, a GitHub approval URL, and the scope version it was assessed under. New controls cover each mutation.
3. **Fixed.** Cases not in the 1.0.0 denominator must be registered by an amendment's `addedCases`; removal is checked over every registered case. Amendment `changes` carry exact `from`/`to` values applied in order. A READY record is stale when a later amendment touches one of its family's cases.
4. **Fixed.** `scope.json` seals `baseline-results.json` and every generated output; the test pins that seal with the denominator. Behavioral equality is recomputed from the original and generated runs, not read from `matchesOriginal`. Every C# fixture must record all four surfaces, and results must name the registered fixture and hash.
5. **Fixed in part.** Explicit rows were added: F1-REFOUT-A2, F2-INTERP-08/09, F3-LOCAL-04 (measured) and F3-LOCAL-A1, F4-ITER-03 (measured native Calor0209 control) and F4-ITER-04, F5-ARRAY-05 (measured rank/initializer matrix), F6-REPORT-12/13. READY already requires a `passed` result for every registered row of the family, so `not-measured` rows block READY. Cross-feature and documentation rows remain an open gate condition.
6. **Fixed.** F5-ARRAY-04 now puts a user `_hoist000` in the scope where the converter hoists into `_hoist000`, and names Grid's parameters after the generated `§ARR2D` id and name. The native output is now rejected with Calor0260 (immutable binding rebound), so the collision is observed.
7. **Fixed.** MET requires a FROZEN packet, an amendment with `gateDecision: "R0-MET"`, every condition SATISFIED with an evidence file that exists, a #1413 closure time, and registered `interaction` and `doc-example` rows.
8. **Fixed.** The document now says four unclassified non-parse rejections.
