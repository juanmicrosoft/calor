## 1. What was established, and what was not

- B1 (v0.22.0 built from `72a0a855`) and N1 (nuget.org `calor 0.21.0`) each ran the full frozen case
  list: 678 sweep cases and 32 controls. The two sweeps are separate. Every count below is per
  baseline. The two baselines produced the same token and class on all 710 cases; that is an
  observation, not a pooled result.
- **The verifier reported a false unconditional proof on both baselines.** 7 cases in 4
  release-critical rows are `false-unconditional-proof` on B1, and the same 7 on N1. Under contract
  §4 and §8 each is release-blocking for its form until S2 fixes or visibly demotes it.
- 10 further release-critical rows per baseline carry other findings (`required-demotion-absent`,
  `spurious-refutation`).
- 74 of 88 release-critical rows per baseline are `CLEAN-WITHIN-BUDGET`. That means only: **no
  counterexample was found within this matrix and budget.** 10 of those 74 are modeled rows with
  zero `validated-proof` cases, so they support no claim that relies on `Proven` or `Discharged`
  for that form (list in §3).
- No row is `INCOMPLETE` and no row is `BLOCKED`. Two cases per baseline stayed
  `TimeoutOrUnavailable` after their retry (`timed-out`); both sit in rows that already have a
  finding, so those rows are `FINDING`, and they would be `INCOMPLETE` without it.
- Not established: whole-compiler soundness; anything on platforms other than osx-arm64 (one
  OS/architecture per baseline, as registered; contract 1.1.0 makes platform a determinism
  dimension, and this sweep does not test it); solver determinism (#1421/#1135); the 7 excluded
  rows (`NOT-INVESTIGATED`, zero cases, as registered).

A caveat on `spurious-refutation`: the registered rule replays the solver's model as an oracle
input. For obligations after an assignment or inside a branch, the model binds the parameter's
value at the obligation, which can fail the entry hypothesis even when the property really is
false. Three such cases (`STR-OPS-COUNT-INDEX-003`, `OBL-BRANCH-FACTS-006`, `OBL-MUTATION-KILL-004`)
have O1 `violated` and are still `spurious-refutation` under the frozen table. They are recorded as
registered. A refutation is never a positive claim; these are completeness defects for S2.

### Harness corrections after the run (no re-execution)

An audit of the first report, before anything was published, found three mapping defects in the
harness. Each correction implements registered text. No observation changed and no case was
re-executed. The corrected mapping was re-applied to the retained attempts by
`Calor.Soundness.Sweep reclassify`. Each attempt keeps its run-time classification
(`runtimeClassification`), and `<baseline>/case-results.runtime-8e33f080.jsonl` keeps the run-time
case results. `harness-corrections.json` lists all 38 changed case results (19 per baseline).

1. **CH-IMPLICATION direction (HC1).** The run-time harness read any `Calor0815` as `Proven`. The
   baselines also emit the *other* direction's `Calor0815` when that direction has no contracts.
   The registration adjudicates only the template's own direction. This removed 13
   `false-unconditional-proof` results per baseline (all in `IMPL-*` rows) whose own direction was an LSP-violation error
   (`Failed`).
2. **Obligation guard markers (HC2).** B1 emits refinement-return guards as
   `InvalidOperationException` and inline parameter refinements with different text. The run-time
   harness reported those present guards as absent, which produced 5 spurious
   `guard-elided-without-proof` results per baseline.
3. **String models (HC3).** Counterexample models with string parameters are now replayed under O1,
   as the registered `spurious-refutation` rule requires. This added 1 `spurious-refutation` per
   baseline (`STR-OPS-COUNT-INDEX-003`).

R1-O2 still uses the registered exception type per site. Because B1's refinement-return guard throws
`InvalidOperationException`, O2 records those firings as `o2-other-exception`. That creates no
divergence record, as registered. O2 did not run on 16 cases per baseline: in 9, the baseline's
emitted C# does not compile; in 7, the replay driver's parameter types do not match. No
`semantic-divergence` was found.
