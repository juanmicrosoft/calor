## Invalidation classifier

`tests/Calor.Compiler.Tests/EvidenceContract/CandidateInvalidation.cs`. Given a target commit, it
classifies every commit in `candidate..target` against each of its parents (renames off). One
non-exempt path makes the verdict `INVALID`. A shallow clone, unfetched `origin/main`, or a short
SHA gives `UNDECIDED`. A target that does not contain the candidate is `INVALID`. A change that a
later commit reverts still invalidates.

**Default deny.** Only these paths are exempt; every other path, including all other
documentation, invalidates:

| Exempt path | When | Why it cannot affect production or publication |
|---|---|---|
| `docs/plans/evidence/c1-1423/**`, this document, `CandidateInvalidation.cs`, `CandidateInvalidationTests.cs`, `CandidateManifestTests.cs` | Before C1 lands | Read by no build, workflow, package, or site. The tests are test-side only |
| `docs/plans/evidence/c1-1423/reviews/**` (newly added data and text files) | Always | Review records |
| `eng/test-manifest.json` | Before C1 lands | Only if the parsed JSON differs solely in `Calor.Compiler.Tests` `expectedTotal` (a rise) and an appended note, with no mode change. Any test file that could explain the rise is classified itself |
| `docs/plans/evidence/c2-1424/**`, `docs/plans/evidence/adjudication-1408/**` (newly added data and text files) | Always | Downstream records about the candidate, not inputs to it |

After the landing and in the downstream directories only **additions** are exempt. Modifying or
deleting a record there invalidates, because a committed record may itself be a frozen input (C2's
claim registry, A1's terminal record, which the R2 gate reads). Exempt files must be plain
non-executable files: a symlink, gitlink, or executable is `INVALID`, and so is any path segment
starting with `.`. "Data and text" means `.json`, `.jsonl`, `.md`, `.txt`,
`.log`, `.trx`, `.csv`, `.gz`, or `.sha256`. Paths are case-sensitive.

**After C1 lands** (the first first-parent commit of `origin/main` that holds the manifest), C1's
own files are frozen. Editing the manifest or the classifier then invalidates the candidate and
returns to #1423, so a later commit cannot weaken the classifier and exempt itself.

**Not a tripwire.** No CI check blocks a later invalidating merge to `main`. By default
`RangeFromTheCandidateIsNotInvalidated` classifies the candidate up to the newest commit that
changes a C1 file. In this PR's CI that range is this PR's merge, so the test shows this PR
invalidates nothing; it also fails if anything else merged after the candidate first. C2 and A1
classify up to their own commit, **from a checkout of the C1 landing commit**. That commit is the
trust anchor: running the classifier from the commit being judged would let that commit change
the classifier. With the variable set, the test fails unless C1 has landed and the running
checkout's C1 files equal the landing's.

```bash
git worktree add ../c1-anchor <C1 landing commit>
cd ../c1-anchor && src/Calor.Compiler/scripts/download-z3.sh
CALOR_C1_CLASSIFY_TARGET=<full SHA> dotnet test tests/Calor.Compiler.Tests \
  --filter FullyQualifiedName~CandidateManifestTests.RangeFromTheCandidateIsNotInvalidated
```

Controls (`CandidateInvalidationTests`): 28 relevant paths invalidate in both phases (compiler,
verifier, workflows, Z3 pins, lockfiles, `Directory.Packages.props`, `global.json`, website content
and the benchmark headline, `CHANGELOG.md`, the contract and registered packets, producers,
`.claude` release skill, samples, a case-changed C1 path); a submodule bump, non-regular files,
and edits to C1 files after landing invalidate; added review and downstream records, and the C1
bump of the test manifest before landing, do not; modifying or deleting those records, the bump
after landing or with a mode change, and six other test-manifest edits invalidate. On real git: C1-only
commits pass; a source, workflow, lockfile, or website commit fails with exactly that path; a
gitlink bump fails even with `submodule.*.ignore=all` configured (diffs use
`--ignore-submodules=none`); a reverted change fails; a merged branch is classified commit by commit; after landing, a review
record passes and an edit to the classifier fails; a target without the candidate fails; an
unfetched `origin/main` or a short SHA is `UNDECIDED`.
