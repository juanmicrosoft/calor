## Chosen grammar (measured parts only)

```text
module M Contoso.Tools                     // namespace field; M is only the file label
  using System.Text
  record P (int:X, int:Y)                  // C# record class; body/`extends Base(X)` indented
  class C                                  // public default; lowercase keywords, no sigil
    /// since 1.2.0
    func Add (int:a, int:b, int[]:xs) → int  // type:name, C# types, T[] / T?, bare literals
      ! cw                                 // effects; `=> e` = postcondition
      => forall int:i in 0..xs.Length : xs[i] >= 0
      var int:n = a + b                    // mutable; `let` = immutable
      set n n + Make().B()[I()].M(Arg())   // infix, C# precedence, any expression as callee
      set Store()[Key()] n                 // indexer setter (upsert), each operand once
      for i from 0 to b step 1             // snapshot range: bounds evaluated once
        set n n + i
      for i = 0; i < Len(); i = i + 1      // C# for: condition re-evaluated
        set n n - i
      each k, v in Pairs()
        set n n + v
      do
        set n Read()
      while n < 0
      return "v=${n,4:D2} lit=\${0}"       // plain string: ${…} runtime hole, \${…} literal
  raw delegate <N>                         // <N> = exact UTF-8 byte count of the payload below
public delegate void D();
```

## Consequences

- **Ambiguity.** Infix with C# precedence removes greedy `§C` absorption and the `§/C`, `§/NEW`, `§/LAM` closers; `f()`/`(f)`/`(f, x)` follow C#; the ~45 builtin heads and word operators cannot capture calls, collisions use `@name`. `M<T>(x)` needs C# type-argument lookahead then `(`. Implication `->` is gone (no clash with `→`). `!`/`=>` are header clauses only before the first body statement; lambdas keep `=>` in expressions. `var` means mutable, not inferred; `let` and `var` both infer an omitted type. Interpolation A migrates literal digit placeholders (`${0}` → `\${0}`).
- **Call target.** `CallExpressionNode.Target:string` becomes an expression callee with ordered arguments. BCL identity comes from the bound receiver `RoslynSymbol` plus the Roslyn-selected method and argument mapping, never spelling; `MetadataArrayResultType`/`ResolvedMetadataMethod` (997aa02) must flow through.
- **Hoist.** Converter `_new`/`_chain`/`_elem`/`_idx` temporaries become unnecessary; removing the sample's one `_chain` saves 28 tokens (row 25). Emitter temporaries must keep left-to-right evaluate-once order and never lift out of `&&`, `||`, `?:` operands.
- **Interop.** C# type/array/nullable spellings remove the name mapping. `raw <reason> <N>` carries exact bytes (CRLF, no final newline, delimiter text, inactive malformed branches) regardless of indentation, never base64; `<N>` is the exact UTF-8 length, computed by the converter. Only a delegate stays raw in this sample. On the member-heavy record probe, `raw record` is 34 tokens fewer than native `record` (355 vs 389), but raw cannot carry effects, contracts or binding, and 044/100 need native records; that is a capability requirement, not a spelling choice.
- **Keywords.** One `for` splits on the token after the loop name: `from` = snapshot, `=` = C# `for`. `record`, `each`, `op`, `pp` and `yield` become reserved heads; `forall`/`exists` are contextual only before `type:name`, so `forall(xs)` stays an ordinary call.
- **Namespace and retained capability (C).** `module M N` keeps M (the compilation-unit label, not a static `module` container, #1619) separate from namespace N. Omitting N must set the explicit global namespace, not legacy null; `_global` is an ordinary name; a trailing `block` marks block origin, file-scoped is the default. One namespace per file: nested, sibling, repeated or conditional scopes need faithful converter preservation, and the converter currently drops `@` escapes. `in a..b` lowers to the half-open guard (vacuous when b <= a) and keeps native `ArrayLength` proofs. `<! e>` must not parse as a type argument. `pp` conditions stay verbatim C# expressions. Lambda effects follow the parameters, before `=>`.

Native namespace headers escape keyword segments again on emission. Their `using`
directives retain compilation-unit scope, including C# `global using`. A C# namespace
with its own scoped imports is a different lexical topology: the converter preserves
that original file rather than moving its imports or silently changing name lookup.
The counted module overflow clause is spaced: `overflow checked` or `overflow unchecked`.

A record's indented `extends Base(arguments)` clause retains its base constructor
arguments, including an explicit empty list. It uses the same argument reader as
the existing record-header base clause; inherited copy and init effect checks still apply.

Native effect binders use `<! e>` and remain separate from emitted CLR type parameters.
Parameter rows end before the next `type:name` parameter. A registered compact effect
code such as `fs:r` remains row data; an actual following parameter with that spelling
uses `@fs:r`. The emitter preserves that distinction with an escaped type name.
A field's type row must stay on the field line. A separate `! cw` after
`field int:count private` retains the shared `Calor0405` placement error and
recovers at the following member; it does not become a field or method row.
An inline row on a non-callable field still fails the existing binding check.
Two native type rows on the same line retain the shared duplicate-row
`Calor0405`: only the first row attaches. Recovery keeps parameter, return,
binding, field and property boundaries intact. A code ending in `:` without a
same-line value remains malformed; its reader cannot consume the next member.

Static containers use a named `module Counter` inside the compilation-unit wrapper.
`class Counter static` is an error under #1619, not a supported class modifier.
Ordinary non-static classes can still contain static members. The wrapper label does
not become a CLR type or a static container.
Free functions in the same CLR namespace share a generated partial container across
files. Project compilation checks the generated files together, so duplicate function
signatures remain errors rather than becoming separate file-label containers.
CLI, MCP, and LSP label-only rename follow that separation: duplicate labels and a namespace or
import with the same spelling are not split declarations. It changes only the
selected file's label and preserves its sidecar identity, namespace/import text,
and CLR owners. Actual shared partial types still reject single-part rename using
their namespace, containing types, and generic arity. Workspace inheritance groups
the same actual qualified types; changing a label cannot split their diagnostics.
Base-call navigation consumes the structural bound receiver and resolves actual
namespace, containing-type, and generic-arity identity through that same lookup.
Qualified misses and ambiguous declarations do not select foreign same-named types.

Operators use `op + (...) → T` or `op implicit (...) → T`; public/static semantics
are implicit. Indexers use `this[type:name] → T` with indented get/set/init accessors,
retaining visibility and member modifiers. Conditional declarations use `pp condition`,
same-column `pp elif condition`, and `pp else`, with independently indented bodies.
Their conditions retain C# syntax and physical-line text. Existing converter policy
still preserves inactive C# branch text verbatim inside its branch; it does not
reparse that text into a potentially lossy native subset or rescue the whole class.

Enums use `enum Mode byte`, with optional visibility and underlying integral type,
and indented members. Delegates use `delegate Handler (int:value) → void`, with
an optional indented effect row. The existing delegate AST represents public,
non-generic declarations; other C# delegate shapes retain explicit raw preservation.
Events use `event System.Action:Changed`, optionally with indented `add` and `remove`
bodies. Both explicit accessors are required. Named-module events inherit static
semantics; ordinary class events can explicitly say `static`. This does not broaden
the converter's preserved static-event surface. Unsupported C# attributes and
modifiers remain preservation gates rather than being silently dropped.
Combined visibilities use ordinary `protected internal` and `private protected`.
Inline `[@Attribute]` metadata remains distinct from an escaped attribute name,
such as `[@@event]`, and retains optional targets such as `[@return:MaybeNull]`.
Parameter attributes use the same suffix, for example
`(out string?:name [@NotNullWhen(true)])`, before any effect row, refinement, or default value.
The selected `/// since`, `/// deprecated`, and `/// breaking` forms apply equally
to free functions, named-module functions, and class methods. Deprecation still
emits the CLR `ObsoleteAttribute`. Breaking descriptions are C# string literals,
including escaped newlines and literal `${...}` text.

## Remaining decisions and gaps

### Expression cutover integration

The expression parser uses ordinary grouping, unary `-`, `!`, `~`, and the existing
arithmetic, shift, comparison, equality, eager bitwise and short-circuit Boolean
operators with C# precedence. `??` and `?:` associate right; binary operators
associate left. An operator missing its same-line operand diagnoses rather than
consuming the next statement. Call separators and header boundaries end expressions;
interpolation holes use the same parser without an implicit raw-C# rescue.

Inner string literals therefore use native Calor escaping too. When migrating
an old raw-C# hole, translate the literal's value rather than copying its source
spelling: C# `"\x41"` becomes native `"\u0041"` (or `"A"`), while C# `"${x}"`
becomes native `"\${x}"` to retain the literal placeholder. Keep alignment and
format clauses unchanged. This is source-context translation within the selected
syntax, not a new escape, interpolation rule, or compatibility fallback.

Prefix operator/builtin dispatch and its greedy-minus exception are removed:
`(- x -1)` means `-x - 1`. Builtin-looking names remain ordinary callees; `@new(x)`
escapes a genuine keyword. Native calls, ordered expression-valued callees, generic
calls, scalar casts, `is`/`as`, array creation/access, and indentation-only block
lambdas use the existing AST. Lambda arrows must share the closing parameter
parenthesis's line, so a grouped postcondition cannot capture the next clause's `=>`.
A bare `return` cannot consume a next-line expression or misplaced effect clause.
Legacy expression fixers no longer normalize conversion candidates.

This is **not completion of #1598** or a whole-converter acceptance result. Unary
`+`, `++`/`--`, `>>>`, infix power `**`, assignment expressions, conditional postfix
invocation/indexing, and higher-rank nested array initializers remain unsupported.
Computed-call conversion inside lambdas no longer stages receivers outside their
execution regions; assignment/for-header and native-operation conversion routes
still need their coordinated acceptance controls. Contextual `forall`/`exists`
now parse typed bindings with half-open `in lower..upper` ranges or the general
`where guard` form. They retain the existing quantified AST, implication/conjunction
semantics, certified finite-range runtime lowering, and modeled array-length proof
path. Calls named `forall` or `exists` remain ordinary calls. Lambda rows use the
selected `(type:name) ! codes => body` placement; explicit pure `!` and absent rows
remain distinct. These additions implement rows 30–31 alongside the integrated
declaration-owned `<! e>` effect-variable binder in row 32. Public converter admission still needs the
coordinated declaration, control and metadata integration.
Native metadata calls now retain the array-to-concrete-collection diagnostic for
bindings, returns and assignments. Contract typing uses the selected metadata
method for native calls, including the Unicode `char.IsDigit` predicate.
String indexing supplies its actual character result to computed-call binding;
`text[0].ToString()` no longer needs an unknown effect. Escaped value receivers
remain values. Array and string `Length` members retain their integer type in
ordinary loop conditions; unknown members and non-boolean conditions still fail.
Qualified CLR primitive names retain the same arithmetic types as their C#
keywords; unrelated or misspelled type names do not acquire a numeric identity.
Declared `byte[]` returns retain their primitive element through
internal-call arguments, including `File.WriteAllBytes(path, Encode(...))`.
Source-generic metadata calls retain type-parameter identities
and constraints in Roslyn's overload probe; `List<T>.Add` and `ToArray` no longer
substitute an unknown type. Shadowed class/member parameter names and
source-defined constraint identities remain explicit metadata-binding gaps.
Namespace aliases still need separate integration.
Native call arguments retain `ref`, `out` and `in` modifiers in positional and
named channels. An undeclared `out _` is a discard, not an undefined variable;
escaped `@_` remains a reference, and invalid by-reference operands still fail.
Cast lookahead rejects array types with explicit rank sizes, so grouped indexed
operands followed by subtraction remain expressions. Ordinary array casts retain
their omitted rank sizes and CLR array identities.
Native record clones use `target with { Property = value }` with C# precedence.
They retain ordered initializer evaluation inside lazy regions and the existing
record copy, allocation and setter-effect checks.
Native ranges use `start..end`, including omitted endpoints, and unary `^offset`
uses the existing from-end index node. Range precedence is above `with` and
below unary operators; binary `^` remains XOR. Quantified bounds retain their
separate `..` delimiter. Array and string slices retain their container type
and array element annotations, rather than becoming scalar elements.
This increment does not change the existing slice-allocation effect policy or
complete custom range indexer / stored `System.Range` binding. The legacy lexer
still recognizes range/index section markers; that staging acceptance is not
the final grammar cutover.
Native `default(T)` for built-in primitive types lowers to existing typed
zero, Boolean or null expressions, not an ordinary call with unknown effects.
Reference defaults retain their authored static type through a cast of null,
including during source and CLR metadata overload resolution; that cast does
not acquire a non-null guarantee.
This preserves the original nested Inventory program's `default(int)` locals
and `ref`/`in`/`out` storage behavior. Generic, nullable and qualified-type
defaults remain explicit unsupported forms in this bounded increment.
Converter-generated default initializers retain the binding's declared type,
so uninitialized locals and lowered `out var` declarations emit `default(int)`
rather than an escaped variable named `@default`. The unchanged W1 ref/out and
out-var-statement fixtures retain native, lossless conversion and CLR behavior.
Metadata construction and member reads resolve ordinary imports, namespace
aliases and closed generic type aliases in their actual lexical namespace
scope. Equal namespace names do not merge separate using scopes. The existing
effect resolver receives the resolved CLR type, not the alias spelling; no
effect rows or manifest permissions are widened. Missing alias targets and
sibling-alias chaining do not fall back to a similarly named BCL type.
This bounded metadata increment does not implement aliases to source-defined
types or general source-name resolution through imports.
Native collection initializers use ordinary constructor braces:
`new List<int> {1, 2}`, `new HashSet<string> {"a"}` and
`new Dictionary<string,int> {{"a", 1}}`. Existing construction AST nodes retain
ordered implicit `Add` calls, including grouped arguments, effects and source
spans. Constructor arguments precede elements; conditional branches do not
hoist construction or element evaluation. Object assignments retain their
existing channel and cannot mix with collection entries.
The retained source-typed `List<WidgetException> {new WidgetException()}` gate
uses the actual BCL `List<T>.Add(T)` definition and exact source type identity,
not an `object` substitute or a fabricated constructed CLR method.
Generic source collection classes, broader source-containing CLR generics,
nullable/derived source arguments to that bounded bridge and context-dependent
`Add` argument conversions remain unsupported; errors are not suppressed.
Unknown collection effect contracts remain unknown. Array and matrix creation
grammars are unchanged; this increment adds no legacy-marker acceptance and
does not close the remaining final-cutover gates.
To preserve the former built-in literals' allocation-only contract, binding
marks only genuine implicit `Add` calls on fresh, parameterless, concrete BCL
`List<T>`, `HashSet<T>` and `Dictionary<TKey,TValue>` constructions. Only that
call's receiver-local `mut` contribution is discharged. Hash keys must be CLR
primitive or string types whose default equality cannot invoke user callbacks;
the exact source-element `List<T>` bridge also qualifies. Constructor,
element and external effects remain charged. Explicit constructor arguments,
comparers, source-defined or derived collections, unknown contracts and ordinary
post-construction `Add` calls do not acquire this proof. The earlier increment's
new expectation that a fresh built-in initializer requires `mut` was a regression
against the unchanged original allocation-only literal rows, not a new contract.
`nameof(n).Length` retains the actual `System.String.Length` property and
remains pure. A directly invoked cast lambda, such as
`((Func<int>)(() => 9))()`, retains its structural lambda body and the actual
metadata delegate's parameter and return types. Its body and argument effects
are charged without inventing an opaque-call assumption; a cast of an unknown
delegate value does not acquire this literal-body proof. Re-emission groups
the lambda operand so the cast survives parsing.
Named parenthesized receivers retain staged grouped-call interpretation:
`(f)(x)` and `(obj.Child.Pick)(value)` are calls, not newly inferred type casts.
The named-cast extension is limited to a generic type syntax followed by a
structurally recognized parenthesized lambda. Other ambiguous named casts,
including named casts before unary `!` and `~`, remain deferred.
No frozen fixtures, acceptance counts or census
inventories are changed by these expression increments.

### Raw-frame integration

The raw-frame prerequisite implements rows 17–18 without retiring the remaining
grammar. A line-head `raw <reason> <N>` ends with LF, CRLF, or CR; the payload starts
immediately after that header newline. `N` is a nonnegative decimal UTF-8 byte
count, limited to 2,147,483,647. The lexer consumes Unicode scalars until exactly
that count is reached. It rejects missing, invalid, overflowing, or truncated
lengths, unpaired surrogates, and a count ending inside a UTF-8 code point with
`Calor0013`. It never interprets payload strings, braces, old delimiters, or
preprocessor directives. Payload bytes are not base64, indented, or normalized.

The next Calor construct starts on a new line. If the payload already ends on
a line break, the next header may follow immediately. Otherwise a newline
outside the byte count separates the payload from the next construct. The emitter
always writes one envelope newline after the payload; that newline is not part
of the C# AST payload. Payloads with no final newline and with multiple final
newlines therefore both round-trip exactly.

`raw statement N` preserves a statement; `raw member N` preserves a member with
no feature metadata. Other reason markers inside a statement body retain that
body position and their framing reason. A compact feature such as `raw delegate N` preserves an
interop member's feature name. Non-default metadata uses
`raw member:<feature>:<MemberKind>:<reason> N`; whole-compilation-unit passthrough
uses the same fields with `unit:` instead of `member:`. Metadata strings are
URI-percent-escaped (not payload encoding); `~` means null, an empty field means
an empty string, and a literal tilde is `%7E`. Reserved feature names use the
extended form. The existing AST fields, source order, and whole-unit bypass stay
intact. No native record or async semantic changes belong to this prerequisite.

For #1621 phase A, converter-created ordinary statement, member, and unit
fallbacks carry their existing preservation feature and reason in these fields.
Statement markers use the recorded loss description, including its existing
truncation; payload bytes and preservation decisions do not change. Phase A
retained bare-marker acceptance.
Validated compiler-directive frames are not C# interop and are exempt.

Phase B1 rejects ordinary statement, member, and whole-unit passthrough without
nonempty feature and reason fields (`Calor1012`). Invalid percent escapes or
invalid UTF-8 metadata are malformed frames (`Calor0013`). Shared compilation
checks this before optional analysis and whole-unit emission, even with type and
effect checking disabled or unsafe transpilation requested. The language server
uses the same check; framing-only lexing/parsing remains available to tools.
Validated directive frames remain exempt. Structurally nonempty metadata does
not prove converter origin or a valid preservation reason: unknown-feature and
context-aware applicability authority, stale reporting, and migration of
existing raw blocks remain phase B2 work.

The first B2 foundation shares the converter's existing pure syntax, record-header,
for-header and by-reference block guards. Its internal query takes caller-resolved
original syntax and preservation boundaries; it never reparses a payload as its
original context. Results distinguish `StillRequired`, `NowNative`,
`UnknownOrMismatch`, `InsufficientContext` and `ChangedBoundary`. `StillRequired`
establishes only that the shared guard applies at that original boundary, not
marker provenance or payload identity. This foundation cannot return `NowNative`:
neither an absent guard nor a feature's support level proves native conversion.
Contextual, conditional and rescue reasons remain explicitly unresolved. No B2
compile gate, context persistence, stale reporting or migration rewrite is enabled.

#### Provisional compiler-directive preservation

The milestone coordinator authorized `raw directive:<feature> N` as a bounded
extension of the selected byte-exact envelope. This internal discriminator is
**provisional preservation metadata**, not a Run D measured winner or a new
keyword. `<feature>` is the canonical URI encoding of an existing directive
feature: `nullable-directive`, `pragma`, `warning-directive`, `error-directive`,
`line-directive`, or `symbol-directive`.

These frames reconstruct `CompilerDirectiveNode`, retaining its exact feature,
payload, enclosing scope, and item order. Roslyn must parse the entire payload
as only matching nonconditional directives and comments or whitespace. Unknown
features, noncanonical encodings, mismatches, malformed directives, executable
code, imports, and conditional/disabled text are errors. Symbol directives
remain restricted to the compilation-unit prefix, before declarations or usings.
The discriminator is not a security boundary: source is untrusted, and choosing
it never authorizes arbitrary raw C# or changes interop/effect/native accounting.
Existing `#error` and `#warning` diagnostics retain their compiler-state effects.
This extension does not select a semantics-version declaration syntax.

Source formatting protects raw token spans. Healing and regex-based conversion
fixes temporarily shield frames, then restore their exact text. Interop counts
and minimize hints read lexer payloads rather than delimiter regexes. LSP hover
documents the header; completion, signature help, and semantic highlighting do
not interpret payload text as Calor.

Line-ending normalization at Calor-input boundaries must preserve counted payloads
as well. Replacing CRLF throughout emitted Calor corrupts the declared byte length
when a raw payload contains CRLF. The shared normalization helper changes only
the Calor envelope; corpus gate parsing and self-test compilation use it. Invalid
lengths remain errors rather than being repaired to match a rewritten payload.
