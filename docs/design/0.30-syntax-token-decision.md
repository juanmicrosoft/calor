# 0.30 syntax spelling decision (#1597)

**Rule (maintainer, 2026-10-20):** every 0.30 spelling choice goes to the variant with the fewest tokens, not the most readable one.

**Ties:** when two or more variants tie exactly, pick (1) the C# spelling, then (2) the probe baseline, then (3) the fewest UTF-8 bytes. Rows decided this way are marked *tie*.

**Measurement.** Claude Opus 5.5 (`GET /v1/models` → `claude-opus-5-5`), `/v1/messages/count_tokens` only, no generation, tool `main` 2ce8a9c (`count_tokens.py` `5d34e62f…`), baseline source d82f3ae. Each count is one single-message `input_tokens` including fixed API framing, which cancels in deltas but dilutes small-probe percentages, so decisions use absolute deltas.

- **Run A** [41665665387](https://github.com/juanmicrosoft/calor/actions/runs/41665665387): payload ce134ec (`inputs_sha256 7f8af24d…`, manifest `7c99c3b2…`), 367/400 attempts, `results.json` `606a125d…` (artifact 13246990894). Rows 1–20.
- **Run B** [42545537256](https://github.com/juanmicrosoft/calor/actions/runs/42545537256): payload a48b338 (`inputs_sha256 350ee54e…`, manifest `e03c434e…`), 436/450 attempts, `results.json` `47b834f7…` (artifact 13643450784). It adds 17 probes (rows 21–28); every one of run A's 125 sample counts reproduced exactly.

**Cost.** Anthropic [token counting is free](https://platform.claude.com/docs/en/build-with-claude/token-counting#pricing-and-rate-limits): these runs incur no token-counting charges. GitHub Actions compute and Copilot usage are separate. The 400/450-attempt caps are not dollar budgets or authorization for paid generation or agent evaluation.

**Population and limits.** Primer 1; converted 20 (6 MediatR, 6 Serilog, 6 FluentValidation, 1 Synthetic, 1 Synthetic2: a hand-picked declaration-heavy convenience sample, not the 283-file census); 20 historical run-1 agent files from fewer than 20 independent tasks. Population variants bundle sigils, braces, typed-literal removal and expressions; probe savings overlap and do not add. Non-baseline payloads are speculative hand-written text, not compiler-accepted syntax or runtime-equivalence evidence.

## Chosen grammar (measured parts only)

```text
module M
  record P (int:X, int:Y)                  // C# record class; body/`extends Base(X)` indented
  class C                                  // public default; lowercase keywords, no sigil
    /// since 1.2.0
    func Add (int:a, int:b, int[]:xs) → int  // type:name, C# types, T[] / T?, bare literals
      ! cw                                 // effects; `=> e` = postcondition
      var int:n = a + b                    // mutable; `let` = immutable
      set n n + Make().B()[I()].M(Arg())   // infix, C# precedence, any expression as callee
      set Store()[Key()] n                 // indexer setter (upsert), each operand once
      for i from 0 to b step 1             // snapshot range: bounds evaluated once
        set n n + i
      for i = 0; i < Len(); i = i + 1      // C# for: condition re-evaluated
        set n n - i
      each k, v in Pairs()
        set n n + v
      do
        set n Read()
      while n < 0
      return "v=${n,4:D2} lit=\${0}"       // plain string: ${…} runtime hole, \${…} literal
  raw delegate <N>                         // <N> = exact UTF-8 byte count of the payload below
public delegate void D();
```

## Consequences

- **Ambiguity.** Infix with C# precedence removes greedy `§C` absorption and the `§/C`, `§/NEW`, `§/LAM` closers; `f()`/`(f)`/`(f, x)` follow C#; the ~45 builtin heads and word operators cannot capture calls, collisions use `@name`. `M<T>(x)` needs C# type-argument lookahead then `(`. Implication `->` is gone (no clash with `→`). `!`/`=>` are header clauses only before the first body statement; lambdas keep `=>` in expressions. `var` means mutable, not inferred; `let` and `var` both infer an omitted type. Interpolation A migrates literal digit placeholders (`${0}` → `\${0}`).
- **Call target.** `CallExpressionNode.Target:string` becomes an expression callee with ordered arguments. BCL identity comes from the bound receiver `RoslynSymbol` plus the Roslyn-selected method and argument mapping, never spelling; `MetadataArrayResultType`/`ResolvedMetadataMethod` (997aa02) must flow through.
- **Hoist.** Converter `_new`/`_chain`/`_elem`/`_idx` temporaries become unnecessary; removing the sample's one `_chain` saves 28 tokens (row 25). Emitter temporaries must keep left-to-right evaluate-once order and never lift out of `&&`, `||`, `?:` operands.
- **Interop.** C# type/array/nullable spellings remove the name mapping. `raw <reason> <N>` carries exact bytes (CRLF, no final newline, delimiter text, inactive malformed branches) regardless of indentation, never base64; `<N>` is the exact UTF-8 length, computed by the converter. Only a delegate stays raw in this sample. On the member-heavy record probe, `raw record` is 34 tokens fewer than native `record` (355 vs 389), but raw cannot carry effects, contracts or binding, and 044/100 need native records; that is a capability requirement, not a spelling choice.
- **Keywords.** One `for` splits on the token after the loop name: `from` = snapshot, `=` = C# `for`. `record` and `each` become reserved heads.

## Remaining decisions and gaps

### Operator-parser staging

The operator-parser increment accepts ordinary grouping, unary `-`, `!`, `~`,
and the existing arithmetic, shift, comparison, equality, eager bitwise and
short-circuit Boolean operators in infix form. `??` and `?:` associate right;
binary operators associate left, with C# precedence. A newline ends an infix
expression; an operator missing its same-line operand is an error, not permission
to consume the next statement. Call-argument separators and contract/header
markers also end expressions. Interpolation holes use the same expression parser.

This is **not completion of #1598**. Legacy headers, prefix operators and builtin
forms remain accepted during integration with the emitter and active fixtures.
Consequently, a legacy head followed by arguments still selects a prefix form;
`(name)` alone is ordinary grouping, including `(upper)`. One temporary ambiguity
is explicit: `(- x -1)` remains legacy subtraction of a negative literal when
the head is spaced and the second sign is attached; use `(-x - 1)` for infix
unary grouping. Removing prefix acceptance must remove this exception.
Unary `+`, `++`/`--`,
`>>>`, infix power `**`, assignment expressions, and C# cast/type-test expression
spellings are not added by this increment. Existing removed-operator errors remain;
unsupported infix forms must diagnose rather than disappear. Computed calls,
generic-call lookahead, and the final removal of prefix acceptance are separate
integration work. In legacy whitespace-separated multi-operand hosts, nonfinal
operands use primary/unary parsing; group an infix operand explicitly so a following
negative value cannot be mistaken for subtraction. No acceptance counts or census
inventories are updated here.

### Raw-frame integration

The raw-frame prerequisite implements rows 17–18 without retiring the remaining
grammar. A line-head `raw <reason> <N>` ends with LF, CRLF, or CR; the payload starts
immediately after that header newline. `N` is a nonnegative decimal UTF-8 byte
count, limited to 2,147,483,647. The lexer consumes Unicode scalars until exactly
that count is reached. It rejects missing, invalid, overflowing, or truncated
lengths, unpaired surrogates, and a count ending inside a UTF-8 code point with
`Calor0013`. It never interprets payload strings, braces, old delimiters, or
preprocessor directives. Payload bytes are not base64, indented, or normalized.

The next Calor construct starts on a new line. If the payload already ends on
a line break, the next header may follow immediately. Otherwise a newline
outside the byte count separates the payload from the next construct. The emitter
always writes one envelope newline after the payload; that newline is not part
of the C# AST payload. Payloads with no final newline and with multiple final
newlines therefore both round-trip exactly.

`raw statement N` preserves a statement; `raw member N` preserves a member with
no feature metadata. Other reason markers inside a statement body retain that
body position and their framing reason. A compact feature such as `raw delegate N` preserves an
interop member's feature name. Non-default metadata uses
`raw member:<feature>:<MemberKind>:<reason> N`; whole-compilation-unit passthrough
uses the same fields with `unit:` instead of `member:`. Metadata strings are
URI-percent-escaped (not payload encoding); `~` means null, an empty field means
an empty string, and a literal tilde is `%7E`. Reserved feature names use the
extended form. The existing AST fields, source order, and whole-unit bypass stay
intact. No native record or async semantic changes belong to this prerequisite.

Source formatting protects raw token spans. Healing and regex-based conversion
fixes temporarily shield frames, then restore their exact text. Interop counts
and minimize hints read lexer payloads rather than delimiter regexes. LSP hover
documents the header; completion, signature help, and semantic highlighting do
not interpret payload text as Calor.

Line-ending normalization at Calor-input boundaries must preserve counted payloads
as well. Replacing CRLF throughout emitted Calor corrupts the declared byte length
when a raw payload contains CRLF. The shared normalization helper changes only
the Calor envelope; corpus gate parsing and self-test compilation use it. Invalid
lengths remain errors rather than being repaired to match a rewritten payload.

This is **not completion of #1598**. Legacy `§RAW`, `§CSHARP`, inline `§CS{…}`,
other closer forms, conversion snapshots, census baselines, and protected
historical fixtures remain for their separate integration/acceptance work.

1. **Counted-loop keyword.** Shared `for` ties shared `range` and the split form at 60 tokens; the C# rule picks `for`, which satisfies #1606 (one construct). The two header semantics still need #1599's explicit representation and acceptance tests.
2. **Documentation tags.** The sigil-free body word is fewest (32/40/35/68), but it is three reserved words, not the `///` form or one doc tag that #1596 allows. Among the allowed forms, `/// since …` is fewest in all 4 probes. Adopting the body word needs a #1596 amendment.
3. **Weak decisions.** Rows decided by *tie*. `→` and `func` win by 1 token each, in one context only. `record` wins by only 1–2 tokens per probe.
4. **#1622 defaults.** Measured, per pair only, in one small probe each. Match, conditional expression and counted loop are fewer and behave the same in their probes (held-out 26/26). The loop beats LINQ (124 vs 231, 95 vs 130), but it differs in effects (`alloc,mut` vs `alloc`), null exception type and deferral. Counted vs `while` holds only for an immutable bound, and `while` leaves `i` in scope. None is a universal lint rule.
5. **Unmeasured.** The whole chosen grammar as one file set: probe deltas overlap and do not add. The foreach keyword itself (`each` vs `foreach`/`for`); only its two-name header was compared.
6. **Semantics.** Token counts do not establish meaning. Native record class semantics (044/100: equality, `with`, deconstruction, derived records, Calor0410/0411 constructor effects), loop semantics, native `do`, upsert-not-`Add` and evaluate-once stores need acceptance tests from their owners.
