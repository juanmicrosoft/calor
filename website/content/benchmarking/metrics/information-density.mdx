## Overview

The Information Density metric measures how much semantic content is packed into each token. Higher density means more meaning per token.

---

## Why It Matters

Not all tokens carry equal semantic weight:

- `public` carries visibility information
- `{` carries only structural information
- `! cw` carries effect information

Languages that pack more meaning into fewer tokens use context windows more efficiently.

---

## How It's Measured

### Semantic Elements Counted

**Archived Calor calculator elements:**

These named marker checks describe the recorded calculator and its old inputs,
not the syntax agents should write now.
| Element | What it represents |
|:--------|:-------------------|
| Module markers | Namespace/module signals in the archived representation |
| Function markers | Function definition |
| Binding markers | Variable binding |
| Input/output markers | Type information |
| Precondition/postcondition markers | Contracts |
| Effect markers | Side effect declarations |
| Branch/loop markers | Control flow |
| Call markers and operators | Computations |

**C# elements (via Roslyn):**
| Element | What it represents |
|:--------|:-------------------|
| Namespaces | Namespace declarations |
| Methods | Function definitions |
| Constructors | Constructor definitions |
| Variables | Variable declarations |
| Parameters | Function parameters |
| Type annotations | Type syntax nodes |
| Control flow | If/for/while/switch |
| Expressions | Invocations, binary ops |

### Density Calculation

```
Density = TotalSemanticElements / TokenCount
```

Higher density = more semantic content per token.

---

## Why C# Narrowly Leads

### 1. Implicit Information

C# encodes information implicitly:

```csharp
public static int Add(int a, int b) => a + b;
```

This single line conveys:
- Visibility (public)
- Static binding
- Return type (int)
- Two parameters with types
- Expression body

**Calor equivalent:**
```calor
module Density
  func Add (int:a, int:b) → int
    !
    return a + b
```

This preserves the Add signature and arithmetic. No current token count or
density comparison has been measured for this native illustration.

### 2. Current Blocks End at Dedent

Indent form was introduced in v0.12. Current `module`, `func` and control-flow
blocks end at dedent. Write neither structural closer tags nor the removed call
and lambda closers; native calls use parentheses.

C# closing braces (`}`) carry minimal semantic weight but are still counted as tokens.

### 3. Effect Information is "Extra"

Calor's effect declarations add semantic content that C# doesn't have:

```calor-fragment
! cw,fs:r,net:rw
```

But C# has no equivalent, so it doesn't get penalized for missing this information.

## Detailed Breakdown

### Example: FizzBuzz

The current illustration preserves the original 1 through 100 trace.
`for i from 1 to 100 step 1` includes both bounds; it is not the half-open
`in 1..100` form.

**Calor:**
```calor
module FizzBuzz
  func Main () → void
    ! cw
    for i from 1 to 100 step 1
      if i % 15 == 0
        Console.WriteLine("FizzBuzz")
      else if i % 3 == 0
        Console.WriteLine("Fizz")
      else if i % 5 == 0
        Console.WriteLine("Buzz")
      else
        Console.WriteLine(i)
```

The following counts and token estimates belong to the archived example, not
the native code above. They are retained as historical calculator output.

| Element Type | Archived Count |
|:-------------|:------|
| Module | 1 |
| Function | 1 |
| Output type | 1 |
| Effect | 1 |
| Loop | 1 |
| Conditionals | 4 |
| Expressions | 4 |
| **Total** | **13** |

Tokens: ~80
Density: 13/80 = **0.16**

**C#:**
```csharp
for (int i = 1; i <= 100; i++)
{
    if (i % 15 == 0) Console.WriteLine("FizzBuzz");
    else if (i % 3 == 0) Console.WriteLine("Fizz");
    else if (i % 5 == 0) Console.WriteLine("Buzz");
    else Console.WriteLine(i);
}
```

| Element Type | Count |
|:-------------|:------|
| For statement | 1 |
| Variable decl | 1 |
| If statements | 4 |
| Method calls | 4 |
| Binary exprs | 7 |
| **Total** | **17** |

Tokens: ~50
Density: 17/50 = **0.34**

**Ratio:** 0.16/0.34 = **0.47x**

## Interpretation Nuance

The published ratio is 0.97x, so the aggregate difference is small. Its meaning
still depends on what the calculator counts:

### Calor's "Extra" Semantics

Calor includes semantic elements C# doesn't have:
- Explicit effects
- First-class contracts
- Structural IDs in the archived source

The historical comparison depends on its calculator's element definitions.
Current declaration IDs live in the per-project `.calor/ids.json` sidecar,
maintained by project tools, not in authored source. The historical token
estimates do not measure that sidecar or the current native spelling.

### Quality vs Quantity

Information density measures *quantity* of semantic content per token, not *quality* or *usefulness*.

Calor's explicit effects might be more valuable for agent reasoning than multiple C# type annotations, even if effects contribute fewer semantic elements.

---

## When Density Matters Less

Low density is acceptable when:

1. **Explicitness has value** - Contracts, effects worth the tokens
2. **Comprehension matters** - Clear structure aids understanding
3. **Context is available** - Large context windows reduce pressure
4. **Precision is needed** - Sidecar identities support tool-driven targeting without source ID fields

---

## The Tradeoff

This metric captures Calor's fundamental tradeoff:

| Approach | Density | Explicitness |
|:---------|:--------|:-------------|
| C# | Slightly higher in the historical corpus | More implicit |
| Calor | Slightly lower in the historical corpus | More explicit |

Calor deliberately trades density for explicitness.

---

## Historical Suggestions and Current Syntax

Earlier suggestions proposed shorter tags and removing source IDs. Current
illustrations already use native words, dedent-based blocks and sidecar IDs.
Removing ID fields from source does not remove identity tracking. This page
does not propose another spelling or claim a new token saving; a current
density result needs a separate measurement with recorded inputs and method.

---

## Summary

The 0.97x result is the only C# win in the current eight-metric dashboard. It is
a near-parity result for this specific semantic-elements-per-token definition,
not a general measure of code quality.
