## Overview

This deterministic metric scores compilation and AST structure in supplied
source pairs. It does not ask an AI agent to generate code or measure an agent's
generation success rate.

---

## Why It Matters

When an agent generates code, it must:
- Produce syntactically valid code
- Create structurally complete programs
- Avoid compilation errors

Languages with familiar patterns and extensive training data have an advantage.

---

## How It's Measured

### Composite Score

The test runner's `GenerationAccuracyCalculator` uses:

```
Score = (CompilationSuccess × 0.5) + (StructureScore × 0.3) + (NoErrors × 0.2)
```

| Component | Weight | Description |
|:----------|:-------|:------------|
| Compilation Success | 50% | Does the code compile? (1.0 or 0.0) |
| Structure Score | 30% | Are all structural elements present? |
| No Errors | 20% | Zero compilation errors? (1.0 or 0.0) |

---

## Structure Score Calculation

### Calor Structure Score

| Element | Points | Check |
|:--------|:-------|:------|
| Module name | 0.20 | Module has a name |
| Has functions | 0.30 | At least one function |
| Function name | 0.20 | First function has a name |
| Function output | 0.20 | First function has an output type |
| Function body | 0.10 | First function has a nonempty body |

These are the current test runner's checks, capped at 1.0 and applied only after
successful compilation. The previous table assigned 0.10 to the name and output
checks; that table did not match the implementation. This correction does not
reconstruct the unrecorded historical measurement binary or change its result.

### C# Structure Score

| Element | Points | Check |
|:--------|:-------|:------|
| Has usings | 0.10 | Using statements present |
| Has namespace | 0.30 | Namespace declaration present |
| Has class | 0.30 | Class declaration present |
| Has method | 0.30 | Method declaration present |

## Why the Result Is Close

The historical snapshot reports a 1.02x Calor/C# ratio. That is a small difference
under its compilation-and-structure rubric, not a result about present-day LLM
generation.

### 1. Training Data Advantage

C# is more widely published than Calor. A model's actual training mix and the
effect on its syntax errors are not measured here. Familiarity is a hypothesis
for an agent experiment, not an explanation established by this calculator.

### 2. Familiar Patterns

```csharp
// C#: Very common pattern, well-learned
public static int Add(int a, int b)
{
    return a + b;
}
```

```calor
module FamiliarAdd
  func Add public (int:a, int:b) → int
    !
    return a + b
```

### 3. Error Recovery

C# errors often have clear fixes:
- Missing semicolon → add semicolon
- Missing brace → add brace
- Wrong type → cast or convert

Calor errors may be less familiar:
- Misindented block body → requires understanding indent-only scope
- Wrong block nesting → requires indentation-level understanding

## Example Comparison

### Agent Task: "Write a function that adds two integers"

**C# source illustration, not observed agent output:**
```csharp
public static int Add(int a, int b)
{
    return a + b;
}
```
This is a method fragment. A class, namespace and imports are not shown; do not
assign it a complete-program structure score without its compilation context.

**Complete native Calor illustration, not observed agent output:**
```calor
module GeneratedAdd
  func Add public (int:a, int:b) → int
    !
    return a + b
```

The example compiles under normal enforcement and `Add(20, 22)` returns 42.
That is a bounded compiler/runtime check, not a new generation-accuracy score.

**Intentional indentation error, not a measured error frequency:**
```calor expect=Calor0100
module InvalidGeneration
  func Add public (int:a, int:b) → int
  return a + b
```

The return is aligned with the function rather than nested in it. Parsing rejects
the program with `Calor0100`. Under the test runner's rubric, failed compilation
also gives a zero structure score; this is not evidence that agents commonly
make this particular error.

## Error Patterns

### Common Calor Errors

| Error | Cause | Example |
|:------|:------|:--------|
| Misindented body | Body not indented under its declaration | `return` aligned with `func` |
| Missing block body | Forgot statements inside a block | A counted `for` header with no body |
| Wrong nesting | Dedented or indented at the wrong level | An `if` body aligned with its parent |
| Missing module wrapper | No enclosing module declaration | Function outside `module Name` |

### Common C# Errors

| Error | Cause | Example |
|:------|:------|:--------|
| Missing semicolon | Forgot line terminator | `return x` |
| Missing brace | Unbalanced braces | `if (x) { return y;` |
| Type mismatch | Wrong return type | `string` method returning `int` |
| Missing using | Forgot namespace import | Using `Console` without `System` |

---

## Mitigation Strategies

### For Calor

1. **Template-based generation:** Start with valid templates
2. **Indentation tracking:** Maintain consistent block levels
3. **Validation pass:** Check structure before outputting

### For C#

1. **Standard patterns:** Use well-established code patterns
2. **Roslyn validation:** Parse generated code before output
3. **Error correction:** Attempt to fix common errors

## Interpretation

The historical ratio is 1.02x, a small Calor lead in the deterministic calculator.
Actual model-generated code may behave differently because:
- C# has more training data exposure
- C# patterns are more familiar to LLMs
- C# tooling provides better error feedback

Treat the result as near parity on the recorded compilation and structural
signals, not as proof that an LLM generates either language more reliably.
The rubric also rewards wrappers such as C# namespaces and imports; valid source
can omit them. These checks are scoring choices, not language requirements.

The test-runner calculator lives in
`tests/Calor.Evaluation/Metrics/GenerationAccuracyCalculator.cs`. The compiler's
embedded evaluation calculator is a different implementation. Do not mix their
scores or use a native illustration to overwrite the archived dashboard.
