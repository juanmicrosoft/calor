You describe the change you want. Your coding agent writes the Calor code,
runs checks, and tests the result. You review whether it did what you asked.
Project guidance and checks support this process, but do not guarantee that
the code is correct.

**Reader question:** How do I ask my agent for a change and review the result?

## Prepare a new or existing project

Install the [.NET 10 SDK and Calor](/docs/getting-started/installation/).
Open a terminal in your existing .NET project folder, or create a new project
in a new folder:

```bash
dotnet new console -o MyApp
cd MyApp
```

## Initialize Calor for your coding agent

Run `calor init` with your agent's option in that project folder. This adds
Calor build support and project instructions, tools, and references for the
agent. Choose one setup below:

| Client setup | Configuration and boundary |
|:-------------|:---------------------------|
| [Claude Code](/docs/getting-started/claude-integration/) | `calor init --ai claude` installs instructions, references, and configured write-validation hooks. |
| [Gemini CLI](/docs/getting-started/gemini-integration/) | `calor init --ai gemini` configures `BeforeTool` validation in supported hook-enabled clients. |
| [Codex CLI](/docs/getting-started/codex-integration/) | `calor init --ai codex` installs project hooks. Review and trust them with `/hooks`; coverage is limited to supported tool paths. |
| [GitHub Copilot](/docs/getting-started/github-integration/) | `calor init --ai github` installs guidance and MCP configuration; check that page for client-specific setup. |

Hooks can reject covered file writes, such as attempts to create C# source
where the project requires Calor. They are not a filesystem sandbox:
configuration, client support, and the tool used determine coverage.
Hook feedback does not guarantee a correct retry.

Open or restart your agent in the same folder and follow its setup prompts.
For Codex, review and trust the project hooks with `/hooks` and follow the
smoke test in its setup guide. Other clients have their own setup steps
linked above.

## Ask for one small change

Describe the behavior you want, including things it should reject. For example:

> Use Calor to add a function that calculates an order total from item prices
> and quantities. Reject negative prices and quantities. Add tests and run
> the project's build and tests. Leave unrelated code unchanged.

The agent writes the code; you do not need to create a `.calr` file yourself.
For an existing C# project, you can instead ask the agent to propose one
small conversion and wait for your approval. Follow the
[phased conversion guide](/docs/guides/adding-calor-to-existing-projects/)
rather than converting the whole application.

## Review and revise

Review the change and its rules against your request. Check the build and
test results, including any warnings or checks that could not decide.
If a command failed, read the first error's file, location, and message,
and ask the agent to address that specific failure. Rerun the affected
checks and tests after the fix. Do not treat a successful build as proof
that the requested behavior works.

Supported MCP clients can also request compiler diagnostics through
`calor_check`; that does not replace executing the application tests.

## Know what a successful check establishes

A successful compilation is not proof of every behavior, complete effect
coverage, or production safety. Contract runtime modes and optional static
verification have different boundaries; use the
[verification guarantees](/docs/guides/verification-guarantees/) as the
canonical reference. The [evidence status](/docs/benchmarking/evidence-status/)
separates implemented behavior from historical measurements and deferred
studies. The historical task runner did not test the full feedback loop;
its scores are not a model-wide reliability result. Neither a hook nor a
passing example establishes an agent-productivity advantage.

## Optional: use the command line without an agent

Developers who want to inspect a hand-written example can use the
[manual Hello World reference](/docs/getting-started/hello-world/) without an AI account.
That is an alternative reference path, not a required step before setting up
your coding agent.
