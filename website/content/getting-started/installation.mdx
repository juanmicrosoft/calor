This guide covers installing the Calor compiler and setting up your development environment.

## Before you start

Install the [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0), not just the runtime.
Check `dotnet --version` before the commands below.

- [Try your first program](/docs/getting-started/hello-world/) — a complete new-directory path, without an AI subscription.
- [Adopt Calor in an existing project](/docs/guides/adoption-playbook/) — preserve your application and its entry point.
- [Connect an optional agent](#ai-agent-integration) — choose a provider after project setup.
- [Contribute to the compiler](/docs/contributing/) — source builds and contributor tests are a separate path.

---

## Global Tool Install

Install the Calor compiler as a global .NET tool:

```bash
dotnet tool install -g calor
```

After installation, you can compile Calor files from anywhere:

```bash
calor --input program.calr --output program.g.cs
```

To update to the latest version:

```bash
dotnet tool update -g calor
```

The site header identifies the compiler release these docs describe. Historical
packaging notes remain in the [changelog](/docs/changelog/); they are not instructions
to install an older patch.

## AI Agent Integration

Calor provides first-class support for AI coding agents. The `calor init` command sets up your project for AI-assisted development.

### Supported AI Agents

| Agent | Flag | What Gets Created |
|:------|:-----|:------------------|
| Claude Code | `--ai claude` | Skills in `.claude/skills/`, `CLAUDE.md` project docs |
| OpenAI Codex | `--ai codex` | Codex-optimized configuration |
| Google Gemini | `--ai gemini` | Gemini-optimized configuration |
| GitHub Copilot | `--ai github` | Copilot-optimized configuration |

### Claude Code Integration

Initialize your project for Claude Code:

```bash
calor init --ai claude
```

This creates:

| File | Purpose |
|:-----|:--------|
| `.claude/skills/calor/SKILL.md` | Calor code writing skill with YAML frontmatter |
| `.claude/skills/calor-convert/SKILL.md` | C# to Calor conversion skill |
| `CLAUDE.md` | Project documentation (creates new or updates Calor section) |

### Claude Code Commands

After initialization, use these commands in Claude Code:

| Command | Description |
|:--------|:------------|
| `/calor` | Write new Calor code with Claude's assistance |
| `/calor-convert` | Convert existing C# code to Calor syntax |

### MSBuild Integration

The `init` command also adds MSBuild targets to your `.csproj` file for automatic Calor compilation:

```bash
# Specify project explicitly
calor init --ai claude --project MyApp.csproj

# Auto-detect single .csproj
calor init --ai claude
```

After initialization, Calor files compile automatically during `dotnet build`.

See [`calor init`](/docs/cli/init/) for complete documentation.

## Editor Support

Calor ships a **language server** (`calor lsp`) speaking standard LSP over stdio:
diagnostics, go-to-definition, references, symbol-exact rename, formatting, and
semantic tokens. Any LSP-capable editor can use it.

<Callout type="warning">
VS Code extension support was withdrawn after v0.13.1. The extension was
distributed as VSIX assets attached to each release; that channel no longer
exists, and the Marketplace listing (frozen at v0.3.8) is not maintained. The
language server is unaffected — point your editor at `calor lsp` directly.
</Callout>

## Clone and Build

If you want to contribute to Calor or build from source:

```bash
# Clone the repository
git clone https://github.com/juanmicrosoft/calor.git
cd calor

# Download the verified Z3 assets required by the compiler build
src/Calor.Compiler/scripts/download-z3.sh

# Build the entire solution
dotnet build

# Verify the build
dotnet run --project src/Calor.Compiler -- --help
```

On Windows, run `src/Calor.Compiler/scripts/download-z3.ps1` instead of the
shell script. Building from source needs these assets even if you are not
using contract verification.

Expected output:
```text illustrative
Calor Compiler - Coding Agent Language for Optimized Reasoning

Usage:
  calor --input <file.calr> --output <file.cs>

Options:
  --input, -i    Input Calor source file
  --output, -o   Output C# file
  --help, -h     Show this help message
```

## Compiling Calor Files

Basic usage:

```bash
dotnet run --project src/Calor.Compiler -- \
  --input path/to/your/program.calr \
  --output path/to/output/program.g.cs
```

The `.g.cs` extension is a convention indicating "generated C#".

---

## Running Generated Code

After compilation, you need a C# project to run the generated code:

### Option 1: Use the HelloWorld Sample

From the repository root, build and run the checked-in sample:

```bash
dotnet run --project src/Calor.Compiler -- \
  --input samples/HelloWorld/hello.calr \
  --output samples/HelloWorld/hello.g.cs

dotnet run --project samples/HelloWorld
```

Do not add another generated file containing a second `Main` to that sample.

### Option 2: Create a New Project

For an independent project, use the complete
[Hello World walkthrough](/docs/getting-started/hello-world/). It covers both
`calor run Program.calr` and generating C# for a new console project, including
removal of only the new template entry point.

When using the source-built compiler instead of an installed tool, run this
from the repository root, replacing the paths with your files:

```bash
dotnet run --project src/Calor.Compiler -- \
  --input path/to/Program.calr \
  --output path/to/Program.g.cs
```

## Troubleshooting

### Tool Not Found

If installation succeeds but `calor --version` is not found, ensure the .NET
global-tool directory is on your `PATH`: `$HOME/.dotnet/tools` on macOS and Linux,
or `%USERPROFILE%\.dotnet\tools` on Windows. Reopen the terminal after changing
`PATH`. Run `dotnet tool list -g` to check that `calor` is installed for the
current user.

### Build Errors

**"SDK not found":**
```bash
# Verify .NET is installed
dotnet --info

# If missing, install .NET 10.0 SDK
```

**"Project not found":**
```bash
# Ensure you're in the calor directory
pwd  # Should show .../calor

# List available projects
ls src/
```

### Runtime Errors

**"Main method not found":**

Use a complete program with an entry point:

```calor
module InstalledHello
  func Main public () → void
    ! cw
    System.Console.WriteLine("Hello from Calor!")
```

The generated entry point is `GlobalModule.Main`, not
`InstalledHello.Main`. A console project's template `Program.cs` takes
precedence over that entry point. Remove it only when it is the untouched
template created for this walkthrough, not an existing application's source.
