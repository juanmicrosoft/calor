The key setup step is `calor init`: it prepares your project and gives your
coding agent the instructions and tools it needs to work with Calor. You
describe the task; the agent writes the code. You do not need to type Calor
code yourself.

The same workflow works for a new project or one you already have.

---

## Quick Overview

Calor lets you record important rules alongside code. Your application runs
on the .NET runtime, using familiar .NET tools to build and test it.

## What you need to try it

- [.NET 10.0 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) or later
- A terminal or command prompt
- A supported coding agent: Claude Code, Codex, Gemini CLI, or GitHub Copilot,
  installed and signed in as required by that tool

---

## Installation

Install the Calor compiler as a global .NET tool:

```bash
dotnet tool install -g calor
```

Or update an existing installation:

```bash
dotnet tool update -g calor
```

## Add Calor to a .NET project

You can add Calor to a new or existing .NET project. The setup adds build
support for Calor files; your existing C# code can stay as it is.

### Step 1: Open a new or existing project

For an existing project, open a terminal in its folder. Keep its current
starting code and run its usual build and tests before making changes.

Starting a new project? Use a new folder name:

```bash
dotnet new console -o MyApp
cd MyApp
```

### Step 2: Check that you are in the project folder

The folder should contain your `.csproj` project file or solution. This is
where you will run `calor init` and open your coding agent. If there are
multiple projects, the [init reference](/docs/cli/init/) explains how to select
one with `--project` or initialize a solution with `--solution`.

### Step 3: Initialize Calor for your agent

Choose **one** command for the coding agent you use. Each command adds both
Calor build support and that agent's project setup; you do not need to run
plain `calor init` first.

For [Claude Code](/docs/getting-started/claude-integration/):
```bash
calor init --ai claude
```

For [Codex](/docs/getting-started/codex-integration/):
```bash
calor init --ai codex
```

For [Gemini CLI](/docs/getting-started/gemini-integration/):
```bash
calor init --ai gemini
```

For [GitHub Copilot](/docs/getting-started/github-integration/):
```bash
calor init --ai github
```

This prepares the .NET build for Calor files and adds guidance and tools for
your agent. Open or restart the agent in the same project folder so it loads
the new setup, and follow its configuration and trust prompts. Keep your
existing files; initialization does not mean converting the whole project.

**Note:** Claude Code, Gemini CLI, and Codex can configure Calor-first hooks.
For Codex, review and trust the generated hooks with `/hooks`, then run the
generated smoke test because specialized file-change paths may bypass lifecycle
hooks. GitHub Copilot is guidance-based with MCP tool support.

### Step 4: Ask your agent to build something

Give the agent a small, concrete task in everyday language. For example:

> Use Calor to add a function that calculates an order total from item prices
> and quantities. Reject negative prices and quantities. Add tests and run
> the project's build and tests. Leave unrelated code unchanged.

The agent writes the Calor code and tests. You review whether the result
matches your request, whether its rules make sense, and whether the build
and tests passed. Read any warnings or checks that could not decide.

If something fails, give the agent the actual error and ask it to fix that
specific problem. Setup and passing checks do not guarantee correct code.

See [How it works](/docs/getting-started/how-it-works/) for the review cycle.

### Step 5: (Optional) Convert some existing C# code

Ask the agent to assess existing C# code and propose one small, well-tested
file to convert first. It can use:

```bash
calor assess ./src --top 10
```

Review the choice before conversion. The agent can then convert the file:

```bash
calor convert HighScoreFile.cs
```

An assessment score is not a reason to convert everything. Review the
conversion report, keep the rest of the project in place, and run your tests
before moving to another file. The
[phased conversion guide](/docs/guides/adding-calor-to-existing-projects/)
explains the journey and its limits.

## What You Get

### Basic Init (`calor init`)

| Component | Description |
|:----------|:------------|
| MSBuild integration | `.calr` files compile automatically during `dotnet build` |
| Build files | Temporary build files stay in `obj/`, separate from the code you edit |

### With Claude (`calor init --ai claude`)

| Component | Description |
|:----------|:------------|
| Claude Code skills | `/calor` to write Calor code, `/calor-convert` to convert C# |
| Hook configuration | Validates covered file writes, including attempts to create `.cs` files |
| CLAUDE.md | Project guidelines instructing Claude to prefer Calor for new code |

### With Codex (`calor init --ai codex`)

| Component | Description |
|:----------|:------------|
| Hook configuration | Validates covered file edits and lints changed `.calr` files |
| MCP configuration | Direct compiler, verification, analysis, and conversion tools |
| AGENTS.md | Automatically loaded Calor project guidelines |

**Note:** Codex hooks require repository and hook trust. They are guardrails;
builds, tests, and repository-wide checks remain necessary.

### With Gemini (`calor init --ai gemini`)

| Component | Description |
|:----------|:------------|
| Gemini CLI skills | `@calor` to write Calor code, `@calor-convert` to convert C# |
| Hook configuration | Validates covered file writes through a supported `BeforeTool` hook |
| GEMINI.md | Project guidelines instructing Gemini to prefer Calor for new code |

### With GitHub Copilot (`calor init --ai github`)

| Component | Description |
|:----------|:------------|
| Copilot skills | `calor` and `calor-convert` skills (referenced by name) |
| copilot-instructions.md | Project guidelines with Calor-first rules |
| MCP tools | `calor_compile`, `calor_verify`, `calor_analyze`, etc. via `.vscode/mcp.json` |

**Note:** GitHub Copilot does not support hooks, but MCP tools provide programmatic compiler access for validation.

## AI Integration Comparison

| Feature | Claude Code | Gemini CLI | Codex CLI | GitHub Copilot |
|:--------|:------------|:-----------|:----------|:---------------|
| Project-local skills | `.claude/skills/` | `.gemini/skills/` | Not generated; managed `AGENTS.md` guidance | `.github/copilot/skills/` |
| Project instructions | `CLAUDE.md` | `GEMINI.md` | `AGENTS.md` | `copilot-instructions.md` |
| Skill invocation | `/calor` | `@calor` | Not applicable | Reference skill name |
| MCP tools | `~/.claude.json` | `.gemini/settings.json` | `.codex/config.toml` | `.vscode/mcp.json` |
| Guardrails | Hooks for covered writes | Hooks for covered writes | Hooks for covered writes | Guidance + MCP tools |
| Hook mechanism | `PreToolUse` | `BeforeTool` | Codex project hooks | None |

Hooks are not a filesystem sandbox. Their coverage depends on the client,
configuration, and tools used. Guidance and hooks do not guarantee a correct
change; keep reviewing results and running tests.
