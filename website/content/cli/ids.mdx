---
title: ids
description: Synchronize, validate, and index tooling-maintained declaration identities
---

Calor declarations have **no IDs in source**. Tools maintain their persistent
identities in the project's `.calor/ids.json` sidecar. Commit that file alongside
the source; do not copy its IDs into declaration headers.

```calor
§M{Calculator}
  §F{Double:pub} (i32:value) -> i32
    §R (* value 2)
```

Build, check, watch, migration, and project indexing synchronize their actual
active inputs automatically. They do not recursively enroll every `.calr` file
in a repository. Frozen historical inputs stay outside that active input set.

| Command | Purpose |
|:--------|:--------|
| `sync` | Reconcile registered inputs, register explicit inputs, or recover an interrupted transaction |
| `check` | Synchronize selected active inputs and validate their persisted identities |
| `index` | Export a declaration index using sidecar identities |

## `ids sync`

```bash
# Explicit registration when using identity tooling without a build.
calor ids sync . --register src/Calculator.calr

# Reconcile existing registrations and recover interrupted transactions.
calor ids sync .
```

The project directory owns the sidecar. Without `--register`, `sync` reconciles
the already registered files. It never writes IDs into source.

Unambiguous changes preserve identity. If several old and new declarations
could match, synchronization fails without changing the sidecar. Use a
transactional rename or move tool to supply an exact mapping instead of choosing
an ID manually.

## `ids check`

```bash
calor ids check src/Calculator.calr
calor ids check src/Calculator.calr --format json
calor ids check .
```

An explicit file argument selects an active input. A directory selects its
registered inputs, including validated pending registrations needed for recovery;
it does not scan every source file below that directory.

The check rejects duplicate IDs, invalid kind prefixes, malformed sidecars,
ambiguous reconciliation, and unavailable identity state. Invalid source retains
its lexer or parser diagnostics. Identity failures use `Calor0806`.
`--format json` returns the shared diagnostic envelope.

## `ids index`

```bash
calor ids index src/Calculator.calr --output declaration-index.json
```

An exported index describes declarations and their identities. It is a report,
not another authoritative store. Output cannot overwrite `.calr` source or a file
directly inside `.calor`.

## Refactoring and recovery

MCP and LSP refactoring preserve exact identity across supported renames and
moves. Source and sidecar changes travel together. LSP rename requires a client
with transactional text-edit support and refuses unsaved buffers that differ
from disk.

An interrupted journaled update recovers during synchronization. Recovery
refuses to overwrite a conflicting external edit. Independent branch additions
can reconcile from ordinary or diff3 Git conflict markers; conflicting changes
to one identity require an explicit resolution.

The old source-rewriting `ids assign` command is removed. Use `ids sync`, not
source-ID insertion or duplicate reassignment. See
[Stable Identifiers](/docs/philosophy/stable-identifiers/) for the identity model.
