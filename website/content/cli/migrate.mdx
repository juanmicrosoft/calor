Migrate an entire project between C# and Calor.

See [Converting C#: What Stays C# and Why](/docs/guides/csharp-interoperability/)
for native conversion, preserved C#, and how to interpret the report.

```bash
calor migrate <path> [options]
```

---

## Overview

The `migrate` command converts all applicable files in a project or directory. It:

- Scans for convertible files
- Creates a migration plan
- Converts files in parallel (optional)
- Generates detailed reports
- Handles errors gracefully without stopping

---

## Quick Start

```bash
# Preview migration (dry run)
calor migrate ./src --dry-run

# Migrate C# to Calor
calor migrate ./src

# Migrate with report
calor migrate ./src --report migration-report.md

# Migrate Calor back to C#
calor migrate ./src --direction calor-to-cs
```

---

## Options

| Option | Short | Default | Description |
|:-------|:------|:--------|:------------|
| `--dry-run` | `-n` | `false` | Preview changes without writing files |
| `--benchmark` | `-b` | `false` | Include before/after metrics comparison |
| `--direction` | `-d` | `cs-to-calor` | Migration direction |
| `--parallel` | `-p` | `true` | Run conversions in parallel |
| `--report` | `-r` | None | Save migration report to file (`.md` or `.json`) |
| `--verbose` | `-v` | `false` | Enable verbose output |
| `--skip-analyze` | — | `false` | Skip the migration analysis phase |
| `--skip-verify` | — | `false` | Skip the Z3 contract verification phase |
| `--verification-timeout` | — | `5000` | Z3 verification timeout per contract, in milliseconds |
| `--explicit-call-closers` | — | `false` | Emit explicit `§/C` for every `§C` call (v0.6.0-compatible output). |

## Migration Plan

Before converting, the command analyzes your codebase and creates a plan:

```bash
calor migrate ./src --dry-run
```

Output:
```text illustrative
=== Migration Plan ===

Direction: C# → Calor
Source: ./src

Files to Convert:
  ✓ 24 files fully convertible
  ⚠ 8 files partially convertible (will have warnings)
  ✗ 3 files skipped (unsupported constructs)
```

## Migration Reports

Generate detailed reports for documentation:

```bash
# Markdown report
calor migrate ./src --report migration-report.md

# JSON report
calor migrate ./src --report migration-report.json
```

Each file result in the JSON report carries `losses[]`, where every entry
names its `path` (`interop`, `rescue`, `passthrough`, `lossy`, or `dropped`)
and, for rescues, the `trigger` and `enabledBy` that applied. It also carries
`conversionPaths`, the same per-file summary `calor convert --format json`
writes (see [Which Path Preserved Each Member](/docs/cli/convert/#which-path-preserved-each-member)).
The console summary adds one line when any member was preserved:

```text
  Preservation paths: 1 by automatic rescue (parse-failure: 1; no passthrough request needed)
```

Default migration tries native conversion, then preserves C# at a member, type,
or whole-file boundary. Generated-Calor and combined project C# checks still run;
failures escalate preservation and trigger another check. Whole-file output
reproduces the original C# without a generated preamble.

Every buildable discovered input is written without a lossy or passthrough flag.
Malformed, missing, unreadable inputs and write failures remain errors; they do
not discard unrelated valid files. Loose source copies may lack project references.
Their exact preserved outputs are written with `outcome: "unverified"` and failed
compilation diagnostics, not a passed build. Native fraction excludes passthrough
and is reported separately from writing, compilation, and test execution.
The destructive lossy and branch-selection options have been removed.

## Exit Codes

| Code | Meaning |
|:-----|:--------|
| `0` | No files failed; warnings alone do not fail the command |
| `1` | The path was missing, one or more files failed, or migration raised a handled error |
