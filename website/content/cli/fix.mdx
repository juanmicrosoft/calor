```bash
calor fix [file-or-root] --apply [options]
```

`--apply` applies deterministic safe diagnostic patches, then rechecks the
result. The path defaults to the current directory. It does not apply fuzzy
name suggestions, choose effect contracts or guess ambiguous indentation.
Those suggestions remain available in structured diagnostics.

```bash
calor fix src/Broken.calr --apply --dry-run --format json
calor fix src/ --apply
```

The command makes at most three patch passes. Remaining errors produce a
nonzero exit, even if some patches were applied. A dry run preserves the
original diagnostics and source. Writes preserve encoding, BOM and permissions,
reject stale source, and replace each file atomically. Invalid, overlapping or
cross-file edits fail explicitly.

Alternatively, select one reversible migration operation:

| Operation | Rewrite |
|:----------|:--------|
| `--heal-closers` | Delete removed structural closers such as `§/F` and `§/M` while leaving strings and comments untouched |
| `--elide-call-closers` | Elide `§/C` for safe zero- and one-argument same-line calls |

The obsolete `--compact-ids` and `--drop-structural-ids` options are errors.

```bash
calor fix src/ --heal-closers --dry-run
calor fix src/ --heal-closers --log .calor/closers.json
calor fix src/ --heal-closers --revert --log .calor/closers.json
```

`--dry-run` (`-n`) reports changes without writing. `--log` records removed
UTF-8 byte ranges, and `--revert` restores the original bytes. `--format json`
(`-f`) emits a schema 2.0 envelope. Migration flags, `--log` and `--revert`
cannot be combined with `--apply`.

Use this command—not format or lint—to heal structural closer syntax, because
those tools must parse the file and `Calor0830` rejects the closer first.
