Compile and execute a Calor program without creating a project file.

```bash
calor run <path> [options]
```

`path` can be a `.calr` file or a directory of Calor sources. The command
materializes a temporary .NET project, builds it, and runs it. `bin/`, `obj/`,
and `reference/` directories are excluded from discovery.

| Option | Description |
|:-------|:------------|
| `--permissive` | Assume unknown calls are pure and demote forbidden-effect findings to warnings |
| `--keep-temp` | Preserve and print the temporary project path |
| `--verbose`, `-v` | Show compilation details and stream build output |
| `--enforce-effects <bool>` | Enable effect enforcement; defaults to `true` |
| `--verify` | Run Z3 contract verification |
| `--contract-mode <mode>` | Runtime checks: `off`, `debug`, or `release`; defaults to `debug` |
| `--timeout <seconds>` | Per-child-process timeout; defaults to 600 seconds |

Use [`calor test`](/docs/cli/test/) when the directory also contains xUnit
tests.

## Optional: inspect a .NET project

This technical example shows manual compilation for developers who need to
inspect the compiler output. It is not required for running Calor or reviewing
a typical change. Start with the [Hello World program](/docs/getting-started/hello-world/)
in a new `HelloCalor` directory, leaving its greeting unchanged.

In that same directory, create a console project:

```bash
dotnet new console --name HelloApp --output .
```

The template creates a top-level `Program.cs` that prints `Hello, World!`.
Remove **only that freshly generated template file** before adding Calor's
entry point. Otherwise .NET runs the template instead of your Calor `Main`.
Do not delete an existing application's entry point: follow the
[phased conversion guide](/docs/guides/adding-calor-to-existing-projects/) instead.

On macOS or Linux:

```bash
rm Program.cs
```

In PowerShell, use `Remove-Item Program.cs` instead.

Generate C# and run the console project:

```bash
calor --input Program.calr --output Program.g.cs
dotnet run --no-launch-profile
```

The program prints `Hello from Calor!`. This manual example does not use
`calor init`: after changing `Program.calr`, rerun the compiler command before
`dotnet run`.

For automatic project builds, use `calor init` instead of maintaining a manual
generated file. Remove only the `Program.g.cs` generated by this example before
switching, to avoid compiling the same entry point twice.
