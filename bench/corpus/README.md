# Round-trip benchmark corpus (D-W4.2)

The three OSS C# projects the round-trip harness (`tools/Calor.RoundTrip.Harness`)
converts and round-trips are **vendored here as git submodules pinned at exact
commits**. This ends the former un-pinned external dependency
(`~/sources/repos/experimental/github-top10`) — an un-pinned corpus is an
unreproducible epoch (wedge plan v0.11 §2 D-W4.2, `docs/plans/wedge-w4-prereqs.md`
§4). The fourth corpus member, **Synthetic**, stays in-repo at
`tests/Calor.RoundTrip.Synthetic` (not a submodule).

## SHA-selection rule

For each project the pinned commit is a **released tag** whose test suite is
GREEN on the pinned .NET 10 SDK (`global.json` → 10.0.100, rollForward
latestMinor) and whose LICENSE permits benchmark use:

- **MediatR — pinned to the last Apache-2.0 release.** MediatR relicensed to a
  commercial license in **v13.0.0**; every `v12.x` tag (and earlier) is Apache-2.0.
  `v12.4.1` is the last `v12` release, so it is the newest commit we can vendor
  while staying Apache-2.0. License recorded from the `LICENSE` file at the pinned
  commit (Apache License 2.0).
- **Serilog `v4.3.1`** — Apache-2.0 (`LICENSE` at the pinned commit). Chosen
  because its library **and** test projects already target `net10.0` natively at
  this tag, so it round-trips on the pinned SDK with zero retargeting.
- **FluentValidation `12.1.1`** — Apache-2.0 (`PackageLicenseExpression` =
  `Apache-2.0` in `src/Directory.Build.props`). Latest `12.x` release; its library
  targets `net8.0` and its test project `net8.0;net9.0`.

Baseline suite-green is **measured**, not assumed — it is the harness's Baseline
stage. As of this vendoring, all three pass (see "First fidelity measurement").

## Build/measurement caveats (recorded honestly)

The vendored sources are kept **verbatim at their pinned commit** — we never edit
the subjects. To build them on Calor's pinned SDK the harness applies these
**working-copy-only** transforms (the submodule tree is untouched):

1. **No source retargeting.** Each subject is built/tested at a TFM it declares at
   its pinned tag and that the installed runtimes (net8.0 + net10.0) can execute —
   Serilog at `net10.0`, MediatR and FluentValidation at `net8.0`. Building a
   `net8.0` target with the .NET 10 SDK satisfies "builds on the pinned .NET 10
   SDK"; the caveat is that MediatR/FluentValidation are exercised on the net8.0
   runtime, not net10.0. (No net9.0 runtime is installed, so FluentValidation's
   `net9.0` test leg is not run.)
2. **`global.json` neutralized in the working copy.** A subject may pin its own SDK
   (FluentValidation pins `9.0.0`, which is not installed); the harness drops
   `global.json` from the throwaway working copy so every subject builds on Calor's
   pinned SDK.
3. **`NuGetAudit=false` and `TreatWarningsAsErrors=false`** are passed to the
   subject builds. The subjects are measurement targets, **not** held to Calor's
   own zero-warning policy: `NuGetAudit=false` stops a NuGet advisory (`NU1903`,
   e.g. Serilog's transitive `System.Security.Cryptography.Xml`) failing restore
   under the subject's own `TreatWarningsAsErrors`, and disabling warnings-as-errors
   keeps a converted file from being reverted over a mere analyzer warning
   (coverage counts ledger losses, not warnings).

## Dependency effect manifests (D-W3.1 / B2)

`manifests/` holds effect manifests generated by **`calor import`** for the corpus
libraries' own runtime dependencies, so the converted arm can resolve their
effects. Each was produced with `calor import <package> --no-contracts` and every
entry carries provenance (Tier A IL-derived / Tier B curated / Tier C unresolved —
unresolved members are *surfaced*, never silently emitted as pure). Build-only
packages (MinVer, SourceLink, PolySharp, source generators, reference-assembly
packs) are excluded — they are not part of any converted call chain.

Regenerate with:

```bash
dotnet run --project src/Calor.Compiler -- import <package> --no-contracts \
  --output bench/corpus/manifests/<package>.calor-effects.json
```

## Using the corpus

```bash
# One-time: fetch the pinned submodule commits
git submodule update --init --recursive

# Run the round-trip harness against the vendored corpus (default --projects-dir)
dotnet run --project tools/Calor.RoundTrip.Harness -- run --all \
  --dotnet dotnet --output ./conversion-reports/
```

The harness defaults `--projects-dir` to this directory
(`ProjectConfigs.DefaultCorpusDir`); `--projects-dir <path>` still overrides it.
The **main** Calor build and test suite do **not** depend on the corpus — the
submodules are benchmark infra, and `dotnet build` / `dotnet test` are green
without initializing them. Only the CI `roundtrip-verification` job checks out with
`submodules: recursive`.

## Historical first fidelity measurement

The table below predates the failure-safe #776 gate and is retained as historical
context only. The current harness uses lossless conversion, counts excluded and
reverted files in the denominator, and enforces the per-project thresholds in
`ProjectConfigs.cs`; current CI reports are authoritative.

| Project | Baseline | Round-trip | Convertible files | Native | NativeFraction | With-losses | Reverted | Failed-conv |
|---------|----------|-----------|-------------------|--------|----------------|-------------|----------|-------------|
| MediatR | 155/157 green | 155/157 (0 regressions) | 32 | 15 | **0.469** | 4 | 6 | 7 |
| Serilog | 811/811 green | 811/811 | 110 | 44 | **0.400** | 2 | 43 | 21 |
| FluentValidation | 865/866 green | 865/866 | 139 | 74 | **0.532** | 1 | 38 | 26 |

These legacy fractions must not be compared directly with current reports because
their conversion mode and denominator differ.

The blocking thresholds are explicit and overridable with `--min-coverage` and
`--min-native`:

| Project | Minimum total | Minimum native |
|---------|---------------|----------------|
| Synthetic | 62.5% | 62.5% |
| Synthetic2 | 25.0% | 25.0% |
| MediatR | 55.0% | 40.0% |
| Serilog | 30.0% | 25.0% |
| FluentValidation | 50.0% | 48.0% |

Serilog's `Core/Logger.cs` is an explicit conversion exclusion because its
conversion exceeds the per-file timeout. `Rendering/ReusableStringWriter.cs` is
also excluded because regression bisect attributes 43 test failures to its
round-tripped output. Both remain in the denominator as coverage failures; they
are not silently removed from the measurement.

Notes for the tranche-2 bar-setters:

- **"Native" counts loss-ledger entries, not compiler warnings.** `ConvertedNative`
  requires `LossCount == 0` from the conversion loss ledger — it has nothing to do
  with C# warnings. `TreatWarningsAsErrors=false` for the subjects (caveat 3 above)
  therefore does **not** inflate NativeFraction; it only prevents a converted file
  from being *reverted* over an analyzer warning, which would otherwise understate
  coverage. Reverted files stay in the denominator as failures (#776 anti-masking).
- MediatR's round-trip occasionally shows 154/157 — a single timing-sensitive
  timeout test (`GenericRequestHandlerTests.ShouldThrowExceptionWhenTimeoutOccurs`)
  that flakes; it is **not** a conversion regression (0 attributable regressions).
- These fractions are only meaningful when the run is **conclusive**. If the
  post-conversion recovery build fails without any attributable error file (e.g. a
  recovery-build timeout on a cold NuGet cache), the harness marks the run
  **inconclusive** and emits **no** coverage fraction — do not read a number out of
  an inconclusive run.
